# 控制模型

## A0-A6 动作等级

| 等级 | 语义 | 默认授权 |
| --- | --- | --- |
| A0 | 只读调查 | 仅盘点、查询和分析，不产生写入 |
| A1 | 文档和候选产出 | 规格、计划、设计候选与控制记录，需当前对象和路径审批 |
| A2 | 隔离原型 | 沙盒代码、验证页和非生产资源；不得触达正式入口 |
| A3 | 生产实现 | 业务代码、正式 Scene/资源、数据库结构和生产配置；仅 `IMPLEMENTING`，需严格 Implementation Package |
| A4 | 集成与迁移 | 正式入口、数据迁移、生产路径替换、删除旧实现和跨模块整合；仅 `INTEGRATING` 且需 F4 精确审批 |
| A5 | 外部状态操作 | PR、push、消息、第三方、上传构建和云配置；必须精确外部目标审批 |
| A6 | 高风险和发布 | 数据删除、生产迁移、真机安装、商店提审、正式发布和线上回滚；必须独立发布/高风险对象审批 |

低等级批准不能授权更高等级。真机、破坏性和发布动作一律为 A6。动作等级描述影响，不表示审批存在。

## F0-F4 唯一语义

| 门 | 唯一语义 | 核心问题 |
| --- | --- | --- |
| F0 | 授权与流程合规 | 工作项、审批、状态、A 等级、路径、目标、基线、停止门是否允许动作？ |
| F1 | 规格一致性 | 实际候选是否匹配已批准需求、范围、模块契约与冻结包？ |
| F2 | 领域质量 | 产品、架构、玩法、视觉、资源、音频、数值、QA 等专业质量是否达标？ |
| F3 | 工程验证 | 构建、测试、性能、迁移演练与可复现证据是否绑定当前候选？ |
| F4 | 集成/发布决策 | 是否允许集成，或对独立发布工作项执行精确发布动作？ |

任何领域不得重新定义 F0-F4。测试通过不能覆盖 F0 路径越界，领域通过不能覆盖 F1 规格漂移，F4 不能补签早先未授权动作。

## 审批账本规则

审批记录必须保存用户原文、时间、明确对象、阶段、模块、基线版本与哈希、动作类型、文件范围、服务、外部写入、破坏、真机和发布字段及失效条件。`handoff` 展示当前唯一 pending 后，用户可仅回复“批准”“同意”“可以”“继续”或“批准然后按流程推进”；机器记录仍须逐字段等于该 pending。短回复只确认当前门，沉默、未绑定 blanket approval、历史批准和相邻模块批准均无效。

新审批不得让未授权的既往动作合法化。基线、对象、阶段、模块、文件范围或动作等级改变时，创建新审批。旧记录只读保留。
