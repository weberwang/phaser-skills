# Phaser 4 玩法开发

## 输入与决策

快速通道只处理已批准正式资源的尺寸、锚点、采样或九宫格小修，单个动态文本、间距、颜色或低风险显示缺陷，以及不改变视觉方向、不新增正式资源、不改变资源拆分的局部修复；仅读取任务直接相关的代码、配置、测试和验收条件。重做、重新设计、高保真、复刻、还原参考图、对齐截图、提升细节、替换整套 UI 或正式美术任务必须进入标准通道并完整执行 A1 至 A6。标准、发布通道读取 docs/project-profile.yaml、docs/GDD.md、docs/TDD.md、docs/control-plane.md，数值已进入实施时再读取 docs/balance.md。只实现已批准且具备验收条件的需求。

模块首次实现或边界变化时，先按总控 references/module-decomposition.md 形成候选模块图并提交总控；必须等待总控执行拷问并取得人工批准。已批准模块内部的低风险实现仅在出现范围、状态边界、依赖或验收冲突时提交决策包。

## 实现与交接

1. 定义可观察的玩家行为和测试点，核对 TDD 中对应模块为“已批准待实现”，读取总控 [多级漏斗审核](../phaser4-game-orchestrator/references/review-funnel.md) 和 [游戏实现规则](../phaser4-game-orchestrator/references/game-implementation.md) 后开始实现。视觉任务同时读取总控 [视觉质量硬门](../phaser4-game-orchestrator/references/visual-quality-gate.md)；涉及 UI 时完整读取 [UI 精准布局契约](../phaser4-game-orchestrator/references/ui-layout-precision.md)；参考还原任务还要读取[视觉与功能还原规则](../phaser4-game-asset-integration/references/visual-reconstruction.md)。截图无法证明的行为标为“待人工定义”，不得自行推断。
2. 使用代码和 Phaser 基础图形建立可运行低保真，隔离低保真路径与纹理键；记录稳定 ID、层级、交互区、前置状态、输入、规则、状态迁移、时序、反馈、成功/失败、异常恢复、结构说明和资源依赖清单。UI 逐组件记录父级坐标系、参照物、双方停靠点、水平/垂直距离、尺寸策略、横纵布局组、安全区、方向/断点和误差阈值，并提交带参照线、边界和间距标注的运行证据；禁止以无参照语义的孤立屏幕 `x/y` 常量代替布局契约。参考还原任务逐项重放功能契约，提交 A1 的 F1 证据和 F2 专业审核输入；只有未知行为、信息结构取舍或范围变化才由总控升级 F4。只还原布局或静态状态不得通过。
3. 为每个可见场景声明无交互满幅背景槽；通过架构的统一适配器创建背景，竖屏按高度、横屏按宽度适配，保持最低层级且不启用输入、碰撞或玩法语义，不得复制缩放逻辑或用黑色填充掩盖问题。
4. A1 通过后，按批准模块契约实现与表现解耦的规则、状态、输入、场景表现和平台服务；数值只读取可审阅配置。纯规则可与 A2 至 A5 并行，不得自行裁切效果图或把低保真、效果图当正式资源。
5. 只有每个主要视觉对象都有 A4 的 F2/F3 处置结论，A5 已交付实际文件、资源登记与来源、深浅底检查、Phaser 加载与缩放截图、目标视口证据、未完成/未验收清单及适用审核层结论后，玩法角色才可独占修改正式场景和预制体代码，使用独立 GameObject、命名容器和图层装配正式结构；UI 通过统一布局入口从契约值计算，区分资源锚点、布局锚点与动画偏移，并在 resize、恢复、方向、安全区、状态和内容变化后重新排布。美术角色只提供资源与审阅证据。
6. 需要本地服务验证时，先按总控 references/local-service-validation.md 查找同一项目、模式和服务类型的健康实例；可复用时直接使用现有 URL，页面暂未就绪时诊断或等待原服务，不得再次启动。
7. 验证触控、重开、暂停恢复、前后台切换、方向/尺寸变化、场景过渡、资源失败、离线和存档异常；UI 在基准、最窄、最宽视口、支持方向和代表性安全区逐组件输出期望/实测边界、中心与间距，检查动态文本、成员显隐、累计漂移和重排结果。参考还原任务按相同视口宽高、设备像素比、游戏状态、操作轨迹、文本语言和动画时间点核对功能与画面，同时保存参考图、运行图及并排/叠加/像素差异图。发现黑边、透明缝、背景截获输入、尺寸、锚点、焦点、帧序、九宫格或采样问题时，将运行证据交回架构或美术；对比条件不一致时只能标记“未验证”。
8. 实现偏离已批准职责、契约、状态所有权或依赖方向时，停止受影响模块并退回划分与拷问；实现完成后向技术架构提交契约测试或集成证据，由技术架构将 TDD 中的模块标为“已实现”。
9. 玩法角色独占执行低保真实现清理；正式结构验收通过且确认运行时、测试、构建和配置零引用后，删除对应低保真代码、占位资源和纹理键，重新运行测试和生产构建，并保留结构说明与确认记录。
10. 标准、发布通道向制作策划提交功能状态，由制作策划更新 GDD；同时向总控提交审核 ID、候选版本、实现提交、模块契约、A1 至 A6 的 F1/F2/F3 证据、按需 F4 记录、服务复用、正式装配、低保真清理、构建、测试、限制或阻断项，由总控更新控制面。快速通道直接提供 F0/F1、代码、测试和任务证据。

数值偏差、资源问题和可复现缺陷分别交给对应角色；不要自行扩张已批准范围。正式装配只使用 A5 通过的资源，低保真实现不得进入完成状态或候选构建。源码标记测试只能称为“结构回归”，不能作为视觉通过证据；方法名、固定坐标、类型检查、单元测试、构建、无控制台错误、元素存在和主观截图均不能单独证明最终画面。新增或修改的类、函数、实体定义均添加说明规则、边界或性能取舍的简体中文注释。
