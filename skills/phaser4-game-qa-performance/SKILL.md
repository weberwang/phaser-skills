# Phaser 4 测试与性能

证据优先于主观结论。设备档位、帧率、启动时间、包体上限或离线策略未经人工定义时，只报告实测数据和决策缺口。

快速通道只验证已批准正式资源的尺寸、锚点、采样或九宫格小修，单个动态文本、间距、颜色或低风险显示缺陷，以及不改变视觉方向、不新增正式资源、不改变资源拆分的局部修复；仅读取验收条件、相关实现、测试和待验证构建。包含重做、重新设计、高保真、复刻、还原参考图、对齐截图、提升细节、替换整套 UI 或正式美术目标的任务必须按标准通道验证完整 A1 至 A6。标准、发布通道读取 docs/project-profile.yaml、docs/GDD.md、docs/TDD.md、docs/control-plane.md 与当前候选包，已创建时才读取数值、资源登记和平台矩阵。指标、测试范围、风险豁免、缺陷优先级或放行需要取舍时，向总控提交决策包，等待其完成决策门禁。

1. 对新增或边界变化模块，核对实现前已有模块图、拷问结论和“已批准待实现”记录；用契约测试或依赖检查验证职责、状态所有权、公开入口、允许/禁止依赖与实际代码一致。
2. 启动本地验证服务前，检查同一项目、服务类型、模式和端口的监听进程与健康状态；复用健康实例，并在证据中注明复用或查重后新启动。不得因测试步骤或浏览器工具切换重复启动服务。
3. 在 docs/qa-plan.md 建立功能、设备、方向、最窄/最宽宽高比、输入、前后台、网络、存档、资源和渠道矩阵；枚举所有可见场景，确认竖屏按高度、横屏按宽度缩放，并验证四边四角、方向/尺寸变化及场景过渡无黑边、透明缝、闪烁或未批准纯色带，且背景不截获输入。涉及 UI 时完整读取总控 [UI 精准布局契约](../phaser4-game-orchestrator/references/ui-layout-precision.md)，建立逐组件精度矩阵。
4. 参考还原任务让参考输入和运行结果使用相同的视口宽高、设备像素比、游戏状态、操作轨迹、文本语言和动画时间点，逐项执行功能契约并捕获对应截图或录屏；同时保存参考图和运行图，至少生成一种并排图、叠加图或像素差异图。任一条件不一致时视觉结果只能标记“未验证”。
5. 逐状态视觉验收至少检查外轮廓与构图、元素位置和尺寸、层级与遮挡、字体/描边/阴影、材质/纹理/高光、图标细节、安全边距、裁切与越界、九宫格变形和不同宽度下的等比缩放；UI 在基准、最窄、最宽视口、支持方向和代表性安全区读取布局稳定帧的实际边界、中心与间距，对照 TDD 检查参照关系、停靠距离、横纵排列、动态文本、成员显隐、累计漂移和 resize 重排。分别判定功能结果和视觉结果，任一侧未通过或证据不足时标为“未通过”或“未验证”，不得以另一侧通过抵消。
6. A6 前审计 A4 带编号框选图和完整单图清单，以及 A5 的逐资源实际文件、登记与来源、深浅背景透明边缘检查、Phaser 加载与缩放截图、目标视口运行证据和未完成/未验收资源清单。缺少任一主要视觉对象的正式资源或验收时阻断 A6。
7. 搜索源码方法名、检查固定坐标字符串、TypeScript 类型检查、单元测试、生产构建成功、控制台无错误、主观描述“看起来接近”或只验证元素存在，均不能单独作为视觉通过证据。源码标记测试只验证结构契约，测试名和报告必须写“结构回归”，禁止命名或表述为“视觉回归”。
8. 每个缺陷记录版本、渠道、设备、复现步骤、预期与实际、证据、严重度和归属；按 P0 至 P3 分级，并区分功能偏差、视觉偏差或双重偏差。
9. 采集启动、加载、帧率、内存或包体、崩溃和长时间运行证据，并标注环境与采集方式。
10. 在 G2/G3 汇总阻断、豁免、未测风险和候选包对应关系；标准、发布通道向总控提交结论与证据索引，由总控更新控制面，快速通道直接报告验证结果。

没有可复现证据时使用“未验证”，不得报告通过。只有 A1 至 A5 证据有效、所有人工确认门均有当前版本明确记录、正式资源全部登记并通过 Phaser 验证、运行时没有未批准低保真替代物、同条件逐状态视觉对比和功能契约通过、低保真与占位资源已清理、构建与回归测试通过时，才可支持“高保真完成”“视觉还原通过”或“A6 完成”。参考输入、继续任务、未提出异议或其他阶段批准不得推断为当前人工确认；人工指出明显细节不足时撤销通过结论，并按归属退回 A2、A4 或 A5。
