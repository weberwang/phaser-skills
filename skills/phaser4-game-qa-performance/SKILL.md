# Phaser 4 测试与性能

## 全局控制接入

控制面边界：可提议、可审查、可在批准 Work Item 范围内修改，且必须回到 `$phaser4-game-workflow-control` 审批。

本领域可提议验证计划并审查候选，只能在批准的 Work Item、A 等级和路径内写测试或证据；结果回到 [`phaser4-game-workflow-control`](../phaser4-game-workflow-control/SKILL.md)。测试通过不能覆盖授权、范围、路径、基线或审批失败。

证据优先于主观结论。项目未定义量化指标时只报告实测与决策缺口，不自造通用阈值。

1. 读取 Work Item、质量门、TDD、qa-plan 和当前候选。F0 校验授权与流程，F1 校验规格一致，F2 形成独立 QA 领域结论，F3 绑定实际命令、环境、数据源、文件、判定与未覆盖项；缺少独立审查时标记未验证。
2. 启动服务前检查同一项目、服务类型、模式、端口和健康状态；存在健康实例时复用，不终止归属不明的进程。
3. 视觉任务核对 V0 分流：原子资源只有在结构、布局、交互和视口行为不变，且已有适用、有效、绑定版本并覆盖当前范围的玩法视觉契约、低保真/高保真确认记录、视觉可交付结论与预算基线可引用时走 V3-V5；影响满幅背景、安全区、文本尺寸或视口行为时升级组件/资源集或场景路径，后两类按规定执行 V1-V5。场景、整套 UI、视觉系统、参考还原和重做类任务必须执行 V1 低保真与 V2 高保真两道出口确认；组件/资源集按结构变化与高保真变化分别执行。快速通道只有在结构、布局、交互和视口行为不变且既有低保真确认仍适用时才能使用。
4. 适用 V1 时检查逐状态第一视觉目标、玩家/目标/危险/交互/装饰优先级、区分信号、可供性（affordance）、反馈时序、遮挡和小屏/高速/灰阶/色觉阈值，以及场景级纹理、图集、帧数、采样、内存、包体、过绘、Draw Call、最大纹理预算；复核低保真确认包的契约版本、草图/灰盒、关键场景/页面/状态、信息层级、稳定 ID/层级/资源槽、交互区/输入轨迹、布局/安全区/断点、失败恢复、排除项、待 V2 变量、已关闭问题与返工影响。只有当前版本用户明确“通过”才允许进入 V2；原子资源检查所引用契约、低保真确认与预算对当前范围仍适用且有效。
5. 适用 V2 以及所有 V5 必须执行动态可玩片段或可复现交互轨迹，验证识别、预警、反馈、遮挡和移动端缩小可读性；响应式路径按 [响应式视觉验证](references/responsive-visual-validation.md) 覆盖完整 viewport、同页面 resize、背景覆盖、安全区、动态文本、显隐、滚动和触控。QA 核对 V2a/V2b 与独立美术 F2 均先于用户确认，确认包绑定当前候选版本、全局基线和动态证据，且只有用户明确“通过”才形成视觉可交付并进入 V3；仅有基准静态图、像素接近和资源齐全不能证明游戏性。
6. V4 核对机器清单、唯一 ID/纹理键/输出路径、可编辑来源或生成记录、授权、运行时输出、Phaser 与玩法视觉证据，并只验证 V1 已定义或原子资源已引用且在 V3 写入的预算。
7. 同条件截图记录视口、设备像素比、状态、轨迹、语言、ROI、容差、动态时间采样/稳定帧与遮罩理由；可用并排、叠加或像素差，但生成式、动画和 VFX 不得只靠像素差。
8. UI 读取 [`phaser4-game-ui-layout`](../phaser4-game-ui-layout/SKILL.md) 合同，并按 [响应式视觉验证](references/responsive-visual-validation.md) 在基准、最窄、最宽视口、断点邻值、同宽窄高度、竖/横屏、默认/大字号、默认/最长文案和零/非零安全区采集稳定帧。每个视口记录 viewportRect、canvasRect、逻辑尺寸、四边空隙、背景覆盖、安全区、关键 UI 边界、CSS/物理缩放和 resize 前后变化，验证动态文本、成员显隐、关键动作状态、滚动所有权和 resize/方向重排。完整 viewport 缺失只能标记“未验证”；普通测试断言关系不变量，Golden 只在冻结视口、DPR、语言、状态和稳定帧验证精确视觉。
9. V5 检查结构化集成、玩法所有权、低保真零引用、性能峰值和功能契约，并提交动态证据供 F3。修订候选重跑受影响 F0-F4；结构根因退 V1，模块边界变化强制模块门与 grilling。
10. 共享基础完成后验证代表性 Vite/Phaser 启动、Boot/首场景、资源加载和适用插件；关键玩法流完成后在主目标平台烟测核心循环与失败恢复；只有最终集成/G3/release 执行完整渠道/平台矩阵。局部任务证据不得宣称全平台通过，不得自动发起真机验收。

没有可复现证据时标记“未验证”。低保真确认与高保真确认必须独立绑定当前候选；沉默、继续工作、旧版本批准、功能范围批准、参考输入或方向级批准不能替代任一明确确认，低保真确认也不能跳过 V2a/V2b、独立美术 F2 或高保真确认。FIT 只证明等比不溢出，不证明满屏或响应式重排；禁止以 `backgroundCoversCanvas`、不溢出、Canvas ROI、参考缩放到 ROI、控制台构建元素逻辑坐标、源码、单元测试、构建成功、元素存在或无控制台错误假通过。根因按“目标行为未定义=方案缺失；契约明确但实现不符=执行问题；缺陷存在门禁通过=验收问题”分类，多因给主次。

可复用自动化脚本位于 `scripts/responsive-visual-validation.mjs`，纯计算测试位于 `scripts/responsive-visual-validation.test.mjs`。脚本通过 Node ESM 动态导入 Playwright，在同一页面调整视口、不刷新页面，输出完整页面截图和结构化 JSON。
