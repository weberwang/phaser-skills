# Phaser 4 测试与性能

证据优先于主观结论。项目未定义量化指标时只报告实测与决策缺口，不自造通用阈值。

1. 读取审核漏斗、质量门、TDD、qa-plan 和当前候选。实现者或作者在 F0 实际执行当前任务适用的项目原生命令；总控 F1 按风险分诊，独立 QA F2 只读候选并返回结构化结论，最后由总控 F3 收敛。
2. 启动服务前检查同一项目、服务类型、模式、端口和健康状态；存在健康实例时复用，不终止归属不明的进程。
3. 视觉任务核对 V0 分流：原子资源只有在结构、布局、交互不变，且已有适用、有效、绑定版本并覆盖当前范围的玩法视觉契约、低保真/高保真确认记录、视觉可交付结论与预算基线可引用时走 V3-V5，否则升级组件/资源集或场景路径；后两类按规定执行 V1-V5。场景、整套 UI、视觉系统、参考还原和重做类任务必须执行 V1 低保真与 V2 高保真两道出口确认；组件/资源集按结构变化与高保真变化分别执行。快速通道只有在结构、布局、交互不变且既有低保真确认仍适用时才能使用。
4. 适用 V1 时检查逐状态第一视觉目标、玩家/目标/危险/交互/装饰优先级、区分信号、可供性（affordance）、反馈时序、遮挡和小屏/高速/灰阶/色觉阈值，以及场景级纹理、图集、帧数、采样、内存、包体、过绘、Draw Call、最大纹理预算；复核低保真确认包的契约版本、草图/灰盒、关键场景/页面/状态、信息层级、稳定 ID/层级/资源槽、交互区/输入轨迹、布局/安全区/断点、失败恢复、排除项、待 V2 变量、已关闭问题与返工影响。只有当前版本用户明确“通过”才允许进入 V2；原子资源检查所引用契约、低保真确认与预算对当前范围仍适用且有效。
5. 适用 V2 以及所有 V5 必须执行动态可玩片段或可复现交互轨迹，验证识别、预警、反馈、遮挡和移动端缩小可读性。QA 核对 V2a/V2b 与独立美术 F2 均先于用户确认，确认包绑定当前候选版本、全局基线和动态证据，且只有用户明确“通过”才形成视觉可交付并进入 V3；静态效果图、像素接近和资源齐全不能证明游戏性。
6. V4 核对机器清单、唯一 ID/纹理键/输出路径、可编辑来源或生成记录、授权、运行时输出、Phaser 与玩法视觉证据，并只验证 V1 已定义或原子资源已引用且在 V3 写入的预算。
7. 同条件截图记录视口、设备像素比、状态、轨迹、语言、ROI、容差、动态时间采样/稳定帧与遮罩理由；可用并排、叠加或像素差，但生成式、动画和 VFX 不得只靠像素差。
8. UI 在基准、最窄、最宽视口及安全区读取稳定帧的边界、中心、间距与累计漂移，验证动态文本、成员显隐和 resize 重排。
9. V5 检查结构化集成、玩法所有权、低保真零引用、性能峰值和功能契约，并提交动态证据供 F3。修订候选重跑受影响 F0/F1，重开覆盖事实变化的 F2，并由总控重新 F3 后再重提适用 F4。结构根因退 V1 并重做模块审计；引用失效时升级路径。
10. 共享基础完成后验证代表性 Vite/Phaser 启动、Boot/首场景、资源加载和适用插件；关键玩法流完成后在主目标平台烟测核心循环与失败恢复；只有最终集成/G3/release 执行完整渠道/平台矩阵。局部任务证据不得宣称全平台通过，不得自动发起真机验收。

没有可复现证据时标记“未验证”。低保真确认与高保真确认必须独立绑定当前候选；沉默、继续工作、旧版本批准、功能范围批准、参考输入或方向级批准不能替代任一明确确认，低保真确认也不能跳过 V2a/V2b、独立美术 F2 或高保真确认。源码、单元测试、构建成功、控制台无错误、元素存在或主观截图不能单独证明最终画面。
