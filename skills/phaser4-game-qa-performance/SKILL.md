# Phaser 4 测试与性能

证据优先于主观结论。项目未定义量化指标时只报告实测与决策缺口，不自造通用阈值。

1. 读取审核漏斗、质量门、TDD、qa-plan 和当前候选；F2/F3 必须由非作者独立执行。缺少第二角色时，总控只能核对流程与证据完整性，并标记“独立验收未验证”，不得给出通过结论。启动服务前检查同项目、服务类型、模式、端口和健康状态，健康实例必须复用。
2. 核对 V0 分流：原子资源只有在已有有效玩法视觉契约、视觉可交付结论和预算基线时走 V3-V5；影响布局、满幅背景、安全区、文本尺寸或视口行为时升级。场景、整套 UI、视觉系统和参考还原按 V1-V5；快速通道不得改变布局或视口行为。
3. V1/V2/V4/V5 的响应式检查统一遵循[响应式视觉验证](references/responsive-visual-validation.md)，该文是测量字段、完整 viewport 证据、Hook 和脚本用法的唯一详细来源。总控的[UI 精准布局与响应式视觉契约](../phaser4-game-orchestrator/references/ui-layout-precision.md)是契约和门禁唯一详细来源；契约缺失标记“响应式契约缺失”并阻断 V2。
4. 按阶段输出：V1 核对四层坐标、策略、背景覆盖、留白/裁切/拉伸许可、基准/最窄/最宽/横屏/安全区和动态行为；V2 做覆盖矩阵的动态样片（仅基准静态图阻断 V3）；V4 做非作者 F2 的资源与满幅能力审计；V5 做完整 viewport、同页面动态 resize、运行态集成、性能峰值及适用的非作者 F3。
5. 每个视口都记录 viewportRect、canvasRect、逻辑尺寸、四边空隙、背景覆盖、安全区、关键 UI 边界、CSS/物理缩放和 resize 前后变化。完整 viewport 缺失只能“未验证”；FIT 只证明等比不溢出，不证明满屏或响应式重排。禁止以 `backgroundCoversCanvas`、不溢出、Canvas ROI、参考缩放到 ROI、控制台构建元素逻辑坐标或构建成功假通过。
6. 无可复现证据时标记“未验证”。根因按“目标行为未定义=方案缺失；契约明确但实现不符=执行问题；缺陷存在门禁通过=验收问题”分类，多因给主次。正式资源、动画、VFX 和性能还需动态时序、可读性与遮挡证据；源码、单元测试、控制台无错误不能单独证明最终画面。

可复用自动化脚本位于 `scripts/responsive-visual-validation.mjs`，纯计算测试位于
`scripts/responsive-visual-validation.test.mjs`。脚本通过 Node ESM 动态导入 Playwright，
在同一页面调整视口、不刷新页面，输出完整页面截图和结构化 JSON。
