# Phaser 4 测试与性能

证据优先于主观结论。设备档位、帧率、启动时间、包体上限或离线策略未经人工定义时，只报告实测数据和决策缺口。

快速通道仅读取验收条件、相关实现、测试和待验证构建；标准、发布通道读取 docs/project-profile.yaml、docs/GDD.md、docs/TDD.md、docs/control-plane.md 与当前候选包，已创建时才读取数值、资源登记和平台矩阵。指标、测试范围、风险豁免、缺陷优先级或放行需要取舍时，向总控提交决策包，等待其完成决策门禁。

1. 对新增或边界变化模块，核对实现前已有模块图、拷问结论和“已批准待实现”记录；用契约测试或依赖检查验证职责、状态所有权、公开入口、允许/禁止依赖与实际代码一致。
2. 启动本地验证服务前，检查同一项目、服务类型、模式和端口的监听进程与健康状态；复用健康实例，并在证据中注明复用或查重后新启动。不得因测试步骤或浏览器工具切换重复启动服务。
3. 在 qa-plan.md 建立功能、设备、方向、最窄/最宽宽高比、输入、前后台、网络、存档、资源和渠道矩阵；枚举所有可见场景，确认竖屏按高度、横屏按宽度缩放，并验证四边四角、方向/尺寸变化及场景过渡无黑边、透明缝、闪烁或未批准纯色带，且背景不截获输入。
4. 每个缺陷记录版本、渠道、设备、复现步骤、预期与实际、证据、严重度和归属；按 P0 至 P3 分级。
5. 采集启动、加载、帧率、内存或包体、崩溃和长时间运行证据，并标注环境与采集方式。
6. 在 G2/G3 汇总阻断、豁免、未测风险和候选包对应关系；标准、发布通道在控制面只追加结论与证据索引，快速通道直接报告验证结果。

没有可复现证据时使用“未验证”，不得报告通过。
