# Phaser 4 测试与性能

证据优先于主观结论。项目未定义量化指标时只报告实测与决策缺口，不自造通用阈值。

1. 读取审核漏斗、质量门、TDD、qa-plan 和当前候选。F2 必须由非作者执行；缺少第二角色时由总控代审并标识。测试在 F1 复核证据，并在适用路径的 V5/G 门 F3 给出跨域综合结论；原子资源只有出现跨域风险才进入 F3。
2. 启动服务前检查同一项目、服务类型、模式、端口和健康状态；存在健康实例时复用，不终止归属不明的进程。
3. 视觉任务核对 V0 分流：原子资源只有在已有适用、有效、绑定版本且覆盖当前范围的玩法视觉契约、高保真效果图确认记录、视觉可交付结论与预算基线可引用时走 V3-V5，否则升级组件/资源集或场景路径；后两类按规定执行 V1-V5。场景、整套 UI、视觉系统、参考还原和重做类任务必须执行 V2 出口确认；组件/资源集只要适用 V2 且候选定义或改变用户可见高保真形态也必须执行。快速通道只能验证不新增正式资源、不改变方向、拆分、结构、交互或布局的局部修复。
4. 适用 V1 时检查逐状态第一视觉目标、玩家/目标/危险/交互/装饰优先级、区分信号、可供性（affordance）、反馈时序、遮挡和小屏/高速/灰阶/色觉阈值，以及场景级纹理、图集、帧数、采样、内存、包体、过绘、Draw Call、最大纹理预算；原子资源检查所引用契约与预算对当前资源仍适用且有效。
5. 适用 V2 以及所有 V5 必须执行动态可玩片段或可复现交互轨迹，验证识别、预警、反馈、遮挡和移动端缩小可读性。QA 核对 V2a/V2b 与独立美术 F2 均先于用户确认，确认包绑定当前候选版本、全局基线和动态证据，且只有用户明确“通过”才形成视觉可交付并进入 V3；静态效果图、像素接近和资源齐全不能证明游戏性。
6. V4 核对机器清单、唯一 ID/纹理键/输出路径、可编辑来源或生成记录、授权、运行时输出、Phaser 与玩法视觉证据，并只验证 V1 已定义或原子资源已引用且在 V3 写入的预算。
7. 同条件截图记录视口、设备像素比、状态、轨迹、语言、ROI、容差、动态时间采样/稳定帧与遮罩理由；可用并排、叠加或像素差，但生成式、动画和 VFX 不得只靠像素差。
8. UI 在基准、最窄、最宽视口及安全区读取稳定帧的边界、中心、间距与累计漂移，验证动态文本、成员显隐和 resize 重排。
9. V5 检查结构化集成、玩法规则未被表现层改变、低保真零引用、性能峰值和功能契约。原子资源做集成 F1 与动态证据，只有跨域风险才执行 F3；其他路径按 V0 规定在 V5 做 F3。资源问题退 V4，生产设计退 V3，样片/方向退 V2，契约退 V1；用户“修改后重提”时核对旧记录保留、新版本及受影响 V2b/F2 重验，“拒绝”时核对按根因退 V2a 或 V1。原子资源引用基线或绑定确认记录失效时升级路径。

没有可复现证据时标记“未验证”。沉默、继续工作、旧版本批准或方向级批准不能替代当前高保真候选的明确确认。源码、单元测试、构建成功、控制台无错误、元素存在或主观截图不能单独证明最终画面。
