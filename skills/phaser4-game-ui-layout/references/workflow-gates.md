# UI 布局工作流门禁

本参考只细化布局领域，F0–F4 的职责、候选身份、F2 返回结构和 `review.md` 生命周期以总控 [审核漏斗](../../phaser4-game-orchestrator/references/review-funnel.md) 为唯一事实源；不建立第二套流程状态机。

## V0–V5

- V0：改变 UI 结构、布局关系、坐标空间、断点、安全区、滚动或交互区时不得按原子资源快速处理，升级组件/场景路径。
- V1：冻结合同、稳定 UI ID、信息层级、坐标空间、低保真结构、关键交互区和响应式意图；参照物、坐标系、布局组或安全区策略变化使旧确认失效或缩小范围。
- V2：在高保真动态可玩样片验证文本增长、状态、成员显隐、遮挡和小屏；独立专业审核仍由总控漏斗定义。
- V3：选择资源路线并绑定 origin、布局属性、字体/九宫格和预算；不得从整屏效果图裁 UI。
- V4：验证资源边界、缩放、授权和预算，不重新发明布局规则。
- V5：统一入口集成，在目标视口、安全区、方向、动态文本和成员变化下采集边界、中心、间距和累计漂移证据。

## F0–F4

- F0：作者实际执行合同验证器及当前任务适用的原生命令，冻结候选 SHA/ID；不能缩窄为只跑格式检查。
- F1：缺合同、坐标空间、双方锚点、参照物、断点条件、滚动所有权、遮挡回退或证据映射必须退回。发现固定值、绝对定位、悬浮 HUD、手写断点或单行省略只触发布局专项 F2。
- F2 QA：验证可达、无截断、无遮挡、触控尺寸、滚动、键盘/安全区和 resize/方向重排。
- F2 技术：验证坐标空间边界、唯一入口、幂等重排、Scale/Camera/Container/DOM 转换和可测试布局计算。
- F2 视觉：验证相对居中、边缘/安全区距离、层级、遮挡和断点结构变化；只在冻结视口验证精确 Golden。
- F3：所有布局不变量、F2 结论和证据矩阵必须绑定同一合同版本与候选后才批准；修订按总控漏斗产生新候选并重开受影响审核。

## G0–G3

- G0：冻结逻辑尺寸、平台范围、视觉方向、合同框架和项目待定义阈值。
- G1：可玩切片具备合同、适用 V1/V2 确认、布局 F0–F3 和关键动态证据。
- G2：冻结布局系统与断点，完成全 UI 集成、响应式矩阵和性能回归。
- G3：只聚合现有发布门的布局证据，不把本技能扩大为发布审查。
