# 功能语义分组约束

适用于 V2 的效果图拆解与后置布局。先确认哪些元素属于同一功能组件，再决定组件如何停靠；不是根据元素类型、所在大区域或最小包含矩形自动确定父级。

## 判断原则

- 一个功能组件由共同表达一个功能、需要保持相对关系并共同移动或缩放的元素组成。按钮的底板、图标、标题可以是独立元素，但归属同一功能组件。
- 区域容器组织多个功能组件。例如侧栏先包含多个入口组件，各入口再包含自己的图标与文字；不能把所有入口的图标、文字直接平铺在侧栏下，也不能建立仅按“所有文字”归类的容器。
- 原子资源身份与布局归属分离。不同入口可以复用同一图标资源，但每个可见实例仍属于自己的入口；不能仅凭相同资源 ID 合并容器。
- 几何包含、距离、视觉接近只用于辅助观察与验证。语义归属明确后才验证 bounds、计算偏移；没有声明父级时禁止自动选择最小包含容器。
- 独立标题、背景、装饰或完整品牌美术可以直接属于区域或根，不强制创建只有一个元素的容器。无需强制每个组件同时拥有图标、底板和文字。
- 空容器必须有已确认的用途与理由，不得把留白当作空容器。分组不得改变原图构图、元素位置、尺寸或已有元素顺序。

## 拆解记录

每个最终确认的 `decomposition_elements` 元素必须显式声明：

```json
{
  "parent_element_id": "entry-container",
  "semantic_grouping": {
    "kind": "part",
    "rationale": "该文字属于此入口，与入口图标共同移动并保持相对位置"
  }
}
```

`parent_element_id` 只能引用同一 scene/state 的已声明容器，或稳定根 `viewport` / `safe-area`。它表达确认后的功能归属，不包含停靠方向；最终确认不接受缺省父级。`semantic_grouping.rationale` 必须是说明该归属的非空理由，不以“都是文字”“距离最近”作为功能归属理由。

| kind | 元素类型 | 归属约束 |
| --- | --- | --- |
| `region` | 容器 | 组织区域、功能组件和独立元素；父级为区域或根 |
| `component` | 容器 | 表示一个功能组件，允许组合子组件或明确的空容器；父级为区域、功能组件或根 |
| `part` | 非容器 | 功能组件中的图标、底板、文字等部件；直接父级必须为 `component` 容器 |
| `standalone` | 非容器 | 有理由独立布局的标题、背景、装饰或整体美术；父级为区域或根 |

这里的 `kind=component` 表示功能组件容器，与拆解元素字段 `element_type=component` 表示非容器元素不是同一概念。复合功能可以嵌套组件，但区域不能塞入功能组件内部。所有显式父关系必须无环、不自指、几何可包含，且空容器标记与实际子项一致。

## 阶段与校验边界

1. 阶段 A 先登记原子元素、候选容器、功能归属和理由，生成拆解图与技术 JSON。存在歧义就保留为待补充草案，展示争议点，不自动猜测或伪造人工决定。
2. 拆解人工确认覆盖分组种类、理由与父级。缺少这些声明或结构不合法，不得通过最终确认或进入布局。
3. 阶段 B 按已确认元素原序把 `parent_element_id` 映射为 `parent_layout_node_id`，再做视觉双轴对齐判断。输出节点、布局 PNG 与审阅资料需要可追溯到同一功能归属；理由不能只存在于未绑定的旁注。
4. 机器检查字段完整、父级类别、引用、环、几何包含、跨组件归属与确认身份一致性。机器不能证明业务语义正确；把多个功能谎称为一个组件、滥用 `standalone` 或填写无意义理由，仍由拆解人工审阅识别，不以 PASS 或 AI 自评代替确认。
5. 新增容器、改变功能归属或分组理由，返回阶段 A 更新提案并重新确认，使旧拆解与布局身份失效。仅调整既有归属下的停靠与偏移，重新走布局确认，不自动重做参考图。

新增节点需要明确纳入新的拆解确认，已有元素相对顺序与原始 bounds 仍保持不变。该约束不授权自动改写已有项目的冻结工件或确认回执。
