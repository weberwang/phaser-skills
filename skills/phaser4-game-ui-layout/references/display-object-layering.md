# 显示对象锚点与显示层分层

本规则适用于正式 Scene、世界对象、屏幕 UI、常驻 HUD 和独立 `DISPLAY_LAYER`。V1 确定分层与对象原点策略，V2 将它们写入布局和显示层合同，V3 按合同装配，V4 用运行证据确认遮挡与输入。

## 显示对象默认中心锚点

- 可设置原点的显示对象默认使用水平、垂直中心，即 `origin=(0.5, 0.5)`；创建对象或封装组件时显式设置，不能依赖 Phaser 或具体对象类型的隐式默认值。旋转、缩放、碰撞反馈和帧切换应围绕同一稳定中心工作。
- 必须使用其他原点时，逐对象在资源/布局合同记录稳定 ID、`origin` 数值、业务原因和对应的坐标换算，并在运行接入时显式设置。例如满幅背景的边缘对齐、Tilemap 的网格原点或确需左上角作局部坐标基准的对象。不能因为参考图边缘停靠或布局锚点在左上角，就把显示对象的资源原点改成左上角。
- `layout_anchor`、`self_anchor`、`reference_anchor` 决定布局停靠关系；`logicalViewportSpace.coordinateOrigin` 与 `cameraOriginPolicy` 决定坐标系；`animation_offset` 决定反馈位移。这些字段不得代替显示对象 `origin`。Container 或其他不提供资源原点的节点，以子对象局部坐标实现中心枢轴，不伪造 `setOrigin`。
- 序列帧和状态图片要保持统一画布、对象中心与动作物理参照；若动作需要脚底等稳定接触点，用独立的定位参照/局部偏移表达，避免逐帧改动对象原点造成跳动。

## 显示层分层合同

每个场景在 V1 列出实际需要的层及稳定层 ID，按下表从后到前声明可见顺序；无职责的层可以省略。层的根节点、Camera 或 Container、坐标空间、滚动行为、裁切、输入归属、生命周期和负责人必须明确，不能仅靠创建顺序或散落的 `setDepth` 调用决定最终画面。

| 层级职责 | 典型内容 | 关键边界 |
| --- | --- | --- |
| 背景 | 装饰性满幅背景、远景 | 背景适配器负责 cover；不接管世界输入。 |
| 世界后景 | 地图、地面、场景后部遮挡 | 与世界 Camera 和滚动一致。 |
| 世界主体 | 玩家、敌人、道具、交互对象 | 玩法对象与命中归属清晰。 |
| 世界前景与特效 | 前景遮挡、粒子、伤害反馈 | 声明与世界主体的前后关系；特效不抢交互。 |
| 场景 UI 与常驻 HUD | 页面内容、导航、常驻信息与操作 | 使用屏幕坐标和安全区；不随世界 Camera 意外滚动。 |
| 瞬态层 | 遮罩、弹窗、抽屉、Toast 等 | 独立 `DISPLAY_LAYER` Work Item；记录遮罩、输入阻断、焦点恢复和宿主关系。 |

同一层内使用命名子容器和稳定的局部 `z_index`/`z_order`；跨层比较使用场景声明的层顺序，不能把不同父容器下的局部数值直接比较。弹窗遮罩位于宿主内容之上、弹窗内容之下；多个瞬态层可共存时声明相对顺序、互斥关系及最上层输入权。若使用多 Camera、DOM Overlay 或独立 Scene 承载显示层，合同仍要给出最终合成顺序和输入映射。

V2 的 `regions.z_index`、`layout_nodes.z_order` 和 `display_layer_planning.inventory[].z_order` 必须映射到该层顺序，并在同一父级内保持确定性。V3 检查背景、世界、HUD、遮罩、弹窗及特效的同屏组合，禁止用一张整屏图代替结构化装配。V4 至少验证代表性状态下的前后遮挡、最上层命中、关闭后宿主输入与焦点恢复，以及 resize 后层顺序和锚点不漂移；记录当前候选与相关合同身份。
