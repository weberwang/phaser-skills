# V4 布局校准与参考还原

V4 保留正式资源组合的人工确认职责。它核对 V3 素材、真实字体与 V2 布局在同屏中的实际表现，不要求用户重新设计或逐节点从头排列。V2 冻结布局作为初始值，V4 只保存可追踪的位置增量，V5 继续消费同一确认草图与共享 Phaser 渲染器。

## 最短操作

生成、打开、确认前和 V5 准入共用来源内容校验：V2 节点、父子关系、viewport 与草图快照一致，V3 当前候选、效果图、coverage canvas 和组件资源绑定一致。HTTP 成功或文件存在不能代替此检查；来源漂移时先重新生成受影响草图，不对旧布局继续手调。来源摘要不作为几何真值。

1. 按草图原始尺寸打开已落盘草图，在相同 scene/state、语言和参考视口下对照。画面无需调整时，用户可直接确认，不必先重复保存。
2. 有位置偏差时查看当前与目标读数。Shift 点击节点树或编辑框添加/移除选择；先用恢复所选参考位置处理无依据的自身偏移，再按实际构图显式对齐或调整间距。
3. 修改后可选择“保存并确认”，由一次明确的用户操作依次完成写盘、读回、来源复核与人工确认；保存失败、外部修改或渲染失效时不能继续确认。普通“保存草图”仍仅保存草稿。
4. 基准画面确认后，按项目支持的代表视口检查响应式关系。设备预览不是另一份布局，V5 不另存坐标补丁，也不重复重做已确认的 V4 编辑。

任何截图、叠图或差异显示都用于用户检查。代理不得在未明确授权时自动分析截图、据此调整冻结构图或宣布视觉通过；几何函数和实测参数可以自动核对。

UI 皮肤应在 V2 按[九宫格适用规则](../../phaser4-game-asset-integration/references/nine-slice-ui.md)冻结决策。V4 直接消费小图与切片参数，不能把图片透明留白、切片边宽或文字过长当作位置偏移来补偿。

## 批量操作与历史

- 对齐以选择顺序中的第一个节点为固定参照，提供左/水平中心/右及上/垂直中心/下对齐。
- 等间距固定两端，按节点边界之间的空隙分配，不把中心距等分当作间距相等。跨度不足以容纳节点时拒绝操作，不制造负间隙或重叠。
- 批量对齐和分布只用于同一父级的独立同级节点；跨父级或父子混选给出提示，不能重复累计祖先位移。
- 参考原图可能故意使用不等间距或光学偏移；批量整齐化必须由用户显式执行，不能自动改变原图节奏。
- 恢复所选参考位置清除所选节点的自身 offset，仍继承祖先位移；需要恢复整组时选择对应父容器，或用既有“重置初始布局”清除全部偏移。
- 撤销/重做只恢复草图 offsets，不改 V2 节点、父子、尺寸和资源配方。一次拖动记为一次操作，取消拖动不留历史；重新加载文件清空编辑历史。历史不写入草图 JSON。
- 拖动未结束时暂停选择切换、坐标输入、键盘微调、批量操作和撤销重做，避免其他修改被旧手势覆盖；重置会先取消手势，成功重新加载后迟到的指针事件不能改写新快照。
- 所有修改复用同步 reflow、确认失效通知和版本化保存通路；保存/确认期间及正式效果预览模式禁用编辑工具，失败操作不能被记录成可确认的成功布局。

## 对齐、间距与留白的检查口径

分别记录节点相对目标的 dx/dy、当前与目标的父容器四边距，以及选中同级节点的当前/目标相邻间隙。读数统一使用冻结草图的逻辑坐标，不能把浏览器 CSS 缩放或截图物理像素当作位置偏移。

这些读数描述布局矩形。纹理内部透明留白、图片 contain/cover、字体实际字形与基线可能使可见内容和矩形不同；框对齐不能直接证明图像轮廓或文字视觉对齐。由用户分别检查主要对象的可见边界、字形、行基线、光效外缘与整体构图。

V2 图片目标框按完整未裁切源纹理定义，主体安全边距与合法光影空间属于其内部构图。若冻结图的测量只取可见主体，必须在 V3 生产前统一画布与主体比例，不能把含透明内边距的小主体直接填入该框再靠 V4 位置修补。默认文字实测宽高超框会使共享渲染器不健康；明确 `overflow="visible"` 的文字仍需用户检查重叠与留白。对象测量也不是字形墨迹或不透明像素轮廓，字体 fallback、baseline 和不同字形指标仍需要对应资源与排版证据。

| 偏差来源 | 处理位置 |
| --- | --- |
| V4 自身位置增量不合适 | 恢复参考或校准所选节点，不重开无关 V2 确认 |
| V2 目标 bounds、父级、对齐语义或空白用途本身错误 | 修正受影响 V2 事实并重新确认，不用 V4 拖动掩盖错误 |
| 位图内部多余透明边距、主体比例或纹理适配不符合槽位 | 回 V3 修复素材或已声明呈现规则；保留合法辉光、阴影与主体边界，不无依据裁掉 |
| 字体、字号、换行、真实字形或基线与目标不符 | 修正对应文字呈现与字体资源，不靠移动整组长期补偿 |
| 基准画面一致，但设备预览出现间距变化 | 检查共享设计变换、父级参照、安全区和响应式规则，V4/V5 使用同一入口 |

不得把“可用、没有越界”当作已经忠实还原，也不得把所有空白都填满。焦点留白、反馈空间、场景纵深和安全区各有职责，按原图与玩法意图保留。

## 关键几何验收

V2 在已有 `critical_alignments` 与布局不变量中声明需保持的关键对齐线、主区域边距、节点矩形和组间关系，并明确适用的参考视口、scene/state 与语言。V4 对照这些事实，V5 采集同条件真实 bounds；不同视口采用声明的响应式关系，不能把基准绝对坐标直接套到所有设备。

`usability` 继续是普通验收默认值，不自动要求整屏像素差或全矩阵。项目在 `critical_alignments[].tolerance` 中声明了关键矩形几何容差时，机器必须校验该项实际 x/y/width/height 与目标的差值，即使仍使用 usability；不能靠 `test_status=passed` 或手写 delta=0 放行超差。单位使用同一测量空间的 `px`、`logical-px`、`css-px` 或 `css-logical-px`，由项目决定值，不把编辑器 8px 网格当作验收阈值。

只有用户或合同明确要求整屏精确还原时才启用 exact 的严格材料与矩阵。机器几何通过与用户确认显示效果分别记录；确认不能豁免已声明却未满足的关键几何要求。
