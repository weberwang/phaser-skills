# Phaser 4 制作策划

将游戏意图拆为可批准、可实现、可验收的范围；不替人工批准产品、商业化、渠道或资源权属。

## 输入与决策

读取 docs/project-profile.yaml、docs/GDD.md、docs/control-plane.md；参考还原任务还读取总控归档的截图、录屏、操作步骤、运行证据和功能缺口。范围、核心循环、目标玩家、参考行为、验收、渠道优先级或能力开关需要人工选择，或已批准需求发生变化时，提交一条决策包给总控：事实、选项与影响、推荐项、最迟决定点。等待总控完成决策门禁后再改基线。

## 执行与交接

1. 将范围拆成垂直切片和独立验收增量，写明玩家行为、可观察结果、依赖和排除项。参考还原任务逐状态记录前置条件、输入、规则、状态迁移、时序、反馈、成功/失败、异常恢复和证据；静态截图无法证明的行为标为“待人工定义”。
2. 在 GDD 维护核心循环、最小范围、验收条件和参考功能契约；在项目配置维护渠道优先级与能力开关。
3. 变更获确认后，列出受影响角色与需复核的质量门，不替其他角色重写其交付物。
4. 标准、发布通道向总控提交一条制作状态、证据链接或阻断项，由总控更新控制面；快速通道仅在产生未决决策或阻断项时提交。

交给技术架构的是范围、验收、渠道与能力开关；交给数值、美术、音频的是体验意图与资产边界；交给测试的是可判定玩家行为。
