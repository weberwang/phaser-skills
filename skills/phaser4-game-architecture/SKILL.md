# Phaser 4 技术架构

建立可维护、可测试、可构建的边界，并显式处理小游戏、iOS、Google Play 的差异。

## 输入与边界

快速通道仅读取任务直接相关的代码、配置和测试；标准、发布通道读取总控 [多级漏斗审核](../phaser4-game-orchestrator/references/review-funnel.md)、docs/project-profile.yaml、docs/GDD.md、docs/TDD.md、docs/control-plane.md，渠道进入候选后才读取平台矩阵。涉及 UI 时完整读取总控 [UI 精准布局契约](../phaser4-game-orchestrator/references/ui-layout-precision.md)。新建或改变模块边界时，读取总控 references/module-decomposition.md，先提交候选模块图及 F1/F2 证据，再等待总控在 F3 后完成强制拷问；其他技术路线、平台适配、依赖或质量指标只有在专业审核无法裁决且属于受保护决策时，才提交 F4 决策包。

- 用 Phaser 4、TypeScript、Vite 实现 Web 核心；新项目优先采用官方当前的 create-phaser-game 流程。
- 用 Capacitor 承载 iOS 与 Android，将原生插件封装在平台适配层。
- 小游戏必须单独验证；可选商业能力须有显式接口和已批准开关。

## 执行与交接

1. 在实现前划分模块，记录职责与非目标、公开输入/输出、状态所有权、生命周期、允许/禁止依赖、失败边界、测试和实现顺序；总控拷问并获人工批准后，才在 TDD 将模块标为“已批准待实现”。
2. 仅实现已批准模块；发现需要新增模块，或改变职责、契约、状态所有权、依赖方向、持久化/平台边界时立即停下受影响实现，重新划分并拷问。
3. 为装饰性屏幕空间满幅背景建立唯一适配器，覆盖创建、唤醒、恢复、方向与画布尺寸变化；具体缩放、焦点和裁切规则由项目契约定义。世界空间关卡、Tilemap、碰撞或玩法环境必须使用独立对象、地图和层级数据，不得套用装饰背景适配器或扁平化。
4. 涉及 UI 时定义唯一的逻辑坐标与布局入口，把视口、安全区、方向和内容尺寸作为输入；在 TDD 记录组件父级坐标系、参照物、停靠点、距离、尺寸策略、横纵布局组、断点与精度阈值。布局重算从契约值开始，资源锚点、布局锚点和动画偏移相互分离，禁止在多个生命周期回调散布无参照语义的屏幕坐标。
5. 分离核心规则、表现、平台和第三方服务。玩法独占规则、状态和交互代码；美术可维护纯表现资源配置、布局/表现预制数据与视觉集成调整，但不得改变玩法规则。为 V5 协作集成、触控、安全区、暂停恢复、后台切换和断网定义验证策略。
6. 对组件/资源集和场景路径，在 V1 定义每场景纹理、图集、帧数、动画采样、纹理内存、包体、过绘、Draw Call 和最大纹理预算；在 V3 将预算写入机器清单，V4 只验证。原子资源必须引用已有适用且有效的玩法视觉契约与预算基线，否则升级路径；不得在验收时临时放宽。
7. 在 TDD 定义本地服务身份、默认模式、主机/端口和健康检查。启动开发或预览服务前检查监听进程、命令行、项目根目录与健康状态；身份一致且健康时直接复用，不得重复启动。
8. 完成最小骨架和生产构建后，标准、发布通道向总控提交一条证据或阻断项，由总控更新控制面；快速通道以构建和测试结果作为交付证据。

交给玩法开发模块入口、数据流和测试入口；交给测试提供构建命令、版本和日志定位方式。新增或修改的类、函数、实体定义均添加解释设计边界的简体中文注释。
