# Phaser 4 技术架构

建立可维护、可测试、可构建的边界，并显式处理小游戏、iOS、Google Play 的差异。

## 输入与边界

快速通道仅读取任务直接相关的代码、配置和测试；标准、发布通道读取总控 [审核漏斗](../phaser4-game-orchestrator/references/review-funnel.md)、[模块审计](../phaser4-game-orchestrator/references/module-decomposition.md)、[依赖能力档与服务边界](../phaser4-game-orchestrator/references/dependency-capability-profiles.md) 及项目权威工件。新建或改变模块边界时先审计；若实质架构决定阻断候选模块图形成，可在候选前 grilling 并绑定决策 ID/权威工件版本。已有候选时则完成 F0、F1、独立技术/QA F2 和 F3，只有剩余受保护取舍才进入 F4。

- 用 Phaser 4、TypeScript、Vite 实现 Web 核心；新项目优先采用官方当前的 create-phaser-game 流程。
- 仅在移动平台档被实际需求触发时用 Capacitor 承载 iOS 与 Android，并将每个已采用插件封装在平台适配层；初始化不得默认安装非必需插件。
- 小游戏必须单独验证；可选商业能力须有显式接口和已批准开关。

## 执行与交接

1. 在实现前划分并审计模块，记录职责与非目标、公开输入/输出、状态所有权、生命周期、允许/禁止依赖、失败边界、测试和实现顺序；候选前阻断决定先 grilling，已有候选按 F0-F3 审核后写入 TDD。
2. 实现发现需要新增模块或改变职责、契约、状态所有权、依赖方向、持久化/平台边界时，停止受影响实现，更新候选并重跑受影响 F0/F1/F2/F3；仅受保护取舍进入 F4。
3. 为装饰性屏幕空间满幅背景建立唯一适配器，覆盖创建、唤醒、恢复、方向与画布尺寸变化；具体缩放、焦点和裁切规则由项目契约定义。世界空间关卡、Tilemap、碰撞或玩法环境必须使用独立对象、地图和层级数据，不得套用装饰背景适配器或扁平化。
4. 涉及 UI 时使用 [`phaser4-game-ui-layout`](../phaser4-game-ui-layout/SKILL.md) 定义唯一的逻辑坐标与布局入口，把视口、安全区、方向、内容尺寸、状态和必要 DPR 输入作为显式参数；在 TDD 记录父级坐标空间、参照物、双方停靠点、距离、尺寸策略、横纵布局组、断点、滚动轴所有权、遮挡回退和精度阈值。布局重算从合同值开始并保持幂等，资源 origin、布局锚点和动画偏移相互分离，禁止在多个生命周期回调散布无参照语义的屏幕坐标。合同验证器属于 F0 实际命令之一，固定值或绝对定位完整有据时触发布局专项 F2。
5. 分离核心规则、表现、平台和第三方服务。玩法独占规则、状态和交互代码；美术可维护纯表现资源配置、布局/表现预制数据与视觉集成调整，但不得改变玩法规则。为 V5 协作集成、触控、安全区、暂停恢复、后台切换和断网定义验证策略。
6. 对组件/资源集和场景路径，在 V1 定义每场景纹理、图集、帧数、动画采样、纹理内存、包体、过绘、Draw Call 和最大纹理预算；在 V3 将预算写入机器清单，V4 只验证。原子资源必须引用已有适用且有效的玩法视觉契约与预算基线，否则升级路径；不得在验收时临时放宽。
7. 在 TDD 按需记录核心、移动平台、数据/API、复杂玩法、高级视觉和商业能力档；每项包含启用原因、拒绝的轻量方案、包体/性能/平台风险、验证命令和所有者。涉及服务时记录契约版本、认证授权、幂等/重试/超时、兼容、迁移/回滚、测试、监控与备份恢复；服务端不在范围时只记录外部依赖、所有者和客户端边界。
8. 在 TDD 定义本地服务身份、默认模式、主机/端口和健康检查。启动开发或预览服务前检查监听进程、命令行、项目根目录与健康状态；身份一致且健康时直接复用，不得重复启动。
9. 共享基础完成后提供代表性 Vite/Phaser 启动、Boot/首场景、资源和适用插件烟测；关键玩法流完成后提供主目标平台运行烟测；仅最终集成/G3/release 执行完整平台矩阵。不得由局部证据宣称全平台通过，不得自动发起真机验收。
10. 完成 F0 后向总控提交候选 SHA、命令证据和阻断项；独立审阅者只读候选并返回结构化 F2，不修改共享 `review.md`。

交给玩法开发模块入口、数据流和测试入口；交给测试提供构建命令、版本和日志定位方式。新增或修改的类、函数、实体定义均添加解释设计边界的简体中文注释。
