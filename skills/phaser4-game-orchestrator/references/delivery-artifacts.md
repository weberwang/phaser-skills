# 项目交付物规范

本文件是条件工件和“一条事实一个权威位置”的唯一权威定义。默认初始化只生成核心交付物；其余文档在对应角色真正开工前用 `--include` 创建。未触发的工件不创建，也不写 `N/A` 占位。

## 全局工件

| 类型 | 文件 | 负责人 | 创建时机与权威内容 |
| --- | --- | --- | --- |
| 核心 | `docs/project-profile.yaml` | 制作策划 | 初始化；项目身份、目标渠道和约束 |
| 核心 | `docs/GDD.md` | 制作策划 | 初始化；范围、玩法与验收 |
| 核心 | `docs/visual-design.md` | 美术接入 | 初始化；V1 建立、V2a 冻结唯一全局视觉基线 |
| 核心 | `docs/TDD.md` | 技术架构 | 初始化；架构、能力档、API/服务边界与验证平台 |
| 核心 | `docs/control-plane.md` | 总控 | 初始化；当前决策、证据和结论的短索引 |
| 可选 | `docs/balance.md` | 数值设计 | 数值进入实施 |
| 可选 | `docs/asset-license-register.md` | 美术接入 | 正式资源或音频进入生产；权属与生产包 |
| 可选 | `docs/visual-assets.json` | 美术接入 | 正式视觉生产；领域机器清单，不是流程状态 |
| 可选 | `docs/qa-plan.md` | 测试性能 | G1 前；测试策略和可复现证据 |
| 可选 | `docs/platform-matrix.md` | 发布合规 | 渠道进入候选；分层验证和完整矩阵 |
| 可选 | `docs/release-checklist.md` | 发布合规 | G3 前；当前发布范围内的证据与阻塞 |

`docs/visual-design.md` 是全局视觉控制的人类可读事实源；`docs/visual-assets.json` 的基线身份、风格指纹和证据必须与其对应。冻结基线变化后标记受影响证据失效并重验，不复制基线正文。

## 条件任务工件

| 条件 | 工件 | 必须包含 |
| --- | --- | --- |
| 任务需要跨角色交接 | `docs/tasks/<task-id>/brief.md` | 目标、非目标、风险等级、基线 SHA、唯一写范围、禁止修改范围、候选分支、F0 命令和验收条件 |
| 风险或交接需要持久独立验收 | `docs/tasks/<task-id>/review.md` | 候选 SHA 或候选 ID/工件哈希、F0 证据引用、F1 分诊、F2 结构化结论、失效历史和 F3 结果；仅总控写入 |

任务工件只引用 GDD、TDD、视觉确认、资源清单、截图、录屏、命令输出和源工件，不复制其字段或内容。未触发时不创建占位文件。

## 留痕与交接

- Markdown 只记录决策、证据和结论，不是运行期状态机、自动化输入或合并信号。
- 不创建 YAML/JSON 任务状态、自动 finalizer 或自动合并/清理机制。`visual-assets.json` 等领域机器清单继续使用原生格式，但不得驱动协作流程状态。
- 实现者或作者实际完成 F0 后提交候选身份、变更文件、验证摘要和阻塞项；总控需要时将证据引用写入 `review.md`。
- F2 审阅者只读候选并返回统一结构，不修改候选、控制面或 `review.md`；总控独占写入并记录结论和失效历史。
- 默认单写者、普通分支、顺序执行。用户明确要求并行写入时，仍只依赖互斥写范围、普通分支、Markdown 简报和 Git/PR/CI 事实。
- 控制面只保留当前质量门、待决策、阻断项、有效结论和交接索引；详细事实留在各自权威交付物中。
- 不得记录密钥、账号、个人数据、未脱敏日志或受限合同全文。
