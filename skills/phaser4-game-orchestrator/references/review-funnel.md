# 多级漏斗审核

审核层表达候选物的证据深度，不与生产阶段一一绑定。F0-F4 是所有候选物共用的审核语义；V0 只为视觉候选补充生产路径与审核落点，非视觉候选不得被要求填写 V0 类型。

## 通用候选物审核

| 层 | 责任 | 退出条件 |
| --- | --- | --- |
| F0 入口 | 总控确认候选类别、范围、通道、版本、所有权、验收和证据计划；仅视觉候选另记 V0 类型 | 审核路径与作者明确，缺失输入已列出 |
| F1 证据 | 作者或执行者完成确定性检查、文件、命令、复现轨迹和清单 | 证据可复现，未完成项不冒充风险接受 |
| F2 专业 | 非作者检查专业质量、契约、路线、预算和适用证据 | 非作者明确通过/退回；一般候选缺第二角色时总控代审并标识，视觉 V2a/V2b 例外 |
| F3 综合 | 聚合集成、跨域、构建、设备、性能和回归风险 | 跨域问题关闭或形成受保护决策包 |
| F4 人工 | 只决定范围、方向、风险接受、授权/成本、指标、发布放行，以及适用 V2 的当前高保真效果图确认等受保护事项 | 明确记录候选版本、选择和影响；V2 出口确认按专用记录执行 |

标准通道和发布通道的候选物先走 F0→F1→F2，再按下表判断 F3/F4。F3 不是固定终审：只有候选物需要汇合其他模块、专业或候选构建时才执行；F4 不能接收仍可由证据、实现或专业审阅关闭的问题。适用 V2 的出口高保真效果图确认是视觉路径的强制 F4 受保护决策例外，但送审前仍必须关闭专业缺陷并取得 V2b 独立美术 F2 通过。

| 候选类别 | F0→F1→F2 的专业闭环 | F3 触发 | F4 触发 |
| --- | --- | --- | --- |
| 模块/架构 | 冻结职责、公开契约、状态所有权、依赖与测试证据，并由非作者做架构审阅 | 存在跨模块依赖、所有权或集成冲突 | 新模块首次实现或模块边界变化强制执行；其他情况仅受保护架构取舍 |
| 玩法 | 复现规则、状态迁移、交互、失败路径与验收轨迹，并由非作者做玩法专业审阅 | 与模块、资源、数值、音频、平台或存档汇合 | 范围、玩家体验目标或无法用证据关闭的规则取舍 |
| 数值 | 提交参数来源、公式、模拟/实测与回归范围，并由非作者做数值审阅 | 数值变化影响玩法、经济、性能或发布指标 | 目标节奏、商业目标、风险接受或指标取舍 |
| 音频 | 提交来源/授权、格式预算、触发与混音运行证据，并由非作者做音频审阅 | 音频与玩法时序、资源预算、平台或合规汇合 | 方向、授权/成本或风险接受 |
| 测试 | 提交可复现用例、环境、结果、缺陷分级与回归证据，并由非作者做测试审阅 | 汇总多专业、设备、性能或候选构建结论 | 指标、P0/P1 豁免或剩余风险接受 |
| 发布候选 | 绑定版本、提交、逐渠道包、测试、合规、权属与回滚证据，并由非作者做发布/测试审阅 | 必须执行，形成逐渠道综合结论 | 必须执行，由人工决定发布放行 |

快速通道只执行 F0/F1，并且不得新增正式资源或改变方向、拆分、结构、交互、布局；一旦出现标准/发布通道影响即升级，不得借快速通道跳过 F2-F4。

## 视觉 V0 附加映射

视觉候选先按通用规则登记候选类别，再记录 V0 类型。下表只指定视觉生产中的 F1/F2/F3 落点：同一份专业或综合结论满足通用层级后不重复审核，不得给每个 V 阶段机械叠加 F1/F2/F3。

| V0 类型 | F0/F1 | F2 | F3 |
| --- | --- | --- | --- |
| 原子资源 | F0 一次并核对既有玩法视觉契约、高保真效果图确认记录、视觉可交付结论、冻结全局视觉基线与预算基线仍适用、有效且绑定版本；F1 逐交付包，V5 做集成 F1 与动态证据 | V4 资源与跨资源一致性验收 | 仅出现跨域风险时执行；缺少可引用基线或确认记录则升级路径 |
| 组件/资源集 | 按交付包执行 F1 | 候选定义或改变用户可见高保真形态时执行 V2a/V2b；V4 | V5 |
| 场景/整套 UI/视觉系统/参考还原及重做类任务 | 按交付包执行 F1 | V2a 方向基准、V2b 整体视觉审阅、V3、V4 | V5 |

F4 不因一般 V 阶段机械触发；只有通用规则中的受保护决策、强制模块边界例外，以及下述 V2 出口高保真效果图确认例外才进入 F4。场景、整套 UI、视觉系统、参考还原、所有重做/重新设计/提升游戏感/替换整套 UI 任务必须执行该确认；组件/资源集只要适用 V2 且候选定义或改变用户可见高保真形态也必须执行。

V2a/V2b 必须由非作者独立美术引用当前候选截图、具体区域和可观察事实给出 F2 结论。总控代审只能检查流程和证据完整性，不可单独给出艺术方向或视觉可交付通过；缺少独立美术时标记“专业视觉未验证”并阻断 V3。“用户批准方向”不能替代 V2b。明显审美缺陷、游戏感缺失、开发口径残留和缺证必须退回 V2；根因属于构图、信息层级、资源槽、页面模板或布局几何时提交结构修订包退回 V1，不得送 F4 豁免。

## V2 出口：高保真效果图用户确认

门禁顺序固定为 `V2a 方向基准 → V2b 整体视觉审阅与动态可玩样片 → 独立美术 F2 → 总控提交高保真确认包 → 用户结论`，不得新增 V 阶段编号。总控只能提交当前候选版本，确认包至少包含：审核/确认 ID、候选版本、适用范围、全局视觉基线 ID/版本/风格指纹、代表性高保真效果图及关键状态、动态可玩样片或可复现轨迹、与参考或上一版的差异、独立美术 F2 结论、已关闭问题、进入 V3 后的生产范围，以及不可逆成本或返工影响。

用户结论只允许“通过”“修改后重提”或“拒绝”，并记录结论日期、修改意见和适用范围。只有当前版本明确“通过”后，才能形成绑定该确认 ID 的视觉可交付结论并进入 V3；沉默、继续工作、旧版本批准、V2a 方向批准、参考输入或其他阶段结论都不构成当前高保真确认。

“修改后重提”必须保留旧确认记录、产生新的候选版本，并重新执行受影响的 V2b 与独立美术 F2 后再提交新确认包；不得覆盖旧记录或沿用旧版通过。“拒绝”按根因退回 V2a 重选/重做方向，或在构图、信息层级、资源槽、页面模板、布局几何等结构根因时退回 V1。确认不能替代 V2a/V2b、独立美术 F2、动态样片或缺陷修复，也不能作为明显审美问题与缺证的兜底。

V1/V2a 必须形成单一冻结全局视觉基线，V3 每个资源绑定根基线 ID、版本、风格指纹和锚点，V4 提交跨资源联系表与同屏截图，V5 提交运行态一致性证据。总控只核对绑定、版本、风格指纹、锚点和证据是否齐全；非作者独立美术判断形状、比例、镜头、材质、光源、描边、色彩、密度、字体、图标、面板、动画和 VFX 是否一致。不得以相同关键词、模型、调色板或作者声明代替 F2。

## P0-P3 缺陷优先级唯一标准

本节是 P0-P3 的唯一权威定义；其他文档只引用，不得复制或改写定义。优先级按当前候选版本的可观察影响判定，不按修复难度或期望完成时间判定。

| 级别 | 判定标准 | 关闭条件 |
| --- | --- | --- |
| P0 | 无法启动、不可恢复的数据丢失/损坏、合规或安全硬阻断，或核心流程不可完成 | 缺陷已修复并在受影响环境复验通过；进入 G2 前未关闭项必须取得绑定候选版本的 F4 豁免 |
| P1 | 关键体验、关键功能或目标渠道不可接受，但不满足 P0 | 缺陷已修复并完成针对性回归；进入 G2 前必须关闭或取得绑定候选版本的 F4 豁免 |
| P2 | 存在可行绕过方式的功能或体验问题，不阻断核心流程和目标渠道 | 修复并回归，或记录负责人、计划质量门和影响范围 |
| P3 | 不影响正确性、核心体验或发布可用性的优化与打磨项 | 完成优化，或明确纳入/拒绝并记录理由 |

P0/P1 豁免记录必须包含缺陷 ID、候选版本、影响范围、验证证据、补偿措施、负责人、失效条件和人工结论；“已知问题”、沉默或排期不能视为豁免。

## 独立性与回退

作者自检属于 F1，不能冒充 F2。一般候选由总控代审时必须在记录中写“总控代审（缺少第二角色）”；V2a/V2b 和视觉一致性 F2 不允许总控代审替代独立美术结论。资源执行偏差退 V4，生产路线、预算、基线绑定或生成包设计退 V3，方向/动态样片/全局规则漂移或纯视觉表达退 V2，构图、信息层级、资源槽、页面模板、布局几何或玩法视觉契约问题退 V1，集成/跨域问题留 V5；原子资源的引用基线或绑定的高保真确认记录失效时升级路径。冻结基线变更必须列出影响面、标记失效证据，并从最早受影响阶段重验。完成结论统一检查适用 V 阶段、适用 F2、适用时 F3、通常按需 F4 和强制 V2 出口确认例外，只重跑最早失效点之后实际受影响的层。

参考输入、继续工作、沉默、旧版本批准或其他阶段结论均不是当前候选的通过证据。F1/F2 的客观通过不能扩张为 F4 风险接受。
