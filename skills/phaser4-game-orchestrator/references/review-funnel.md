# F0-F4 统一门

本文件只提供领域编排视图。唯一权威是全局控制面的 [控制模型](../../phaser4-game-workflow-control/references/control-model.md)、[状态门](../../phaser4-game-workflow-control/references/state-gates.md) 和结构化 Schema。

| 门 | 语义 | 编排交付 |
| --- | --- | --- |
| F0 | 授权与流程合规 | preflight 结果、任务授权或必要显式批准、A 等级、路径/目标、基线与停止门 |
| F1 | 规格一致性 | 实际 diff 到 approvedRequirements、模块、领域与阶段的追踪 |
| F2 | 领域质量 | 独立产品/架构/玩法/视觉/资源/音频/数值/QA 结论 |
| F3 | 工程验证 | 当前代码/diff 指纹、实际命令、环境、数据源、文件、判定与未覆盖项 |
| F4 | 高影响集成/发布决策 | A4 精确集成批准；独立发布 Work Item 的 A6 精确发布批准；普通 A3 不适用 |

顺序不可调换或补签。低风险、测试通过、领域通过和模糊用户措辞不能跳门。编排默认沿工作流向前推进；审批只覆盖当前明确下一门。门禁问题按三级处置：`repair` 原地修复记录/字段/路径/可补证据并重跑当前门；`revalidate` 在候选与上游冻结 target/candidate/diff/baseline 身份未变时只重验当前门；`return` 仅在需求/范围、上游方案/视觉方向/基线、授权范围或候选身份实质变化，或继续推进会绕过硬门并使下游无效时按真实受影响门回退。不因任意修改重跑全部门；已满足需求的候选不会因另一种可行方案而重开，非阻塞发现记录为未覆盖项/后续事项，不扩大当前 Work Item。

## 审查与返工收敛

审查只检查需求覆盖、明确缺陷、范围越界、硬门和当前证据真实性；不重复实施代理已经完成的同类探索，也不把“还可以有另一种实现”当作缺陷。进入执行/实施前满足入口、关键调用链或契约、授权范围、主要风险和验收目标明确且无直接冲突的最小条件后，A1/A2 冻结当前候选的范围、假设与验收边界，A3 冻结 `Implementation Package`；只有 A3 的实施代理按包执行，遇到需求/范围变化、实质冲突或无法实施才返回。

每轮返工必须列出触发原因及真实受影响门：新增失败证据（测试/类型/构建失败、运行异常、需求不满足、安全或越界问题、可复现缺陷或硬门明确失败），或用户明确改变需求/范围、候选身份实际变化。失败后先判断能否 `repair`，再判断是否仅需 `revalidate`；没有真实触发时不得继续优化式修改。只有 `return` 才允许阶段回退，且必须记录必要回退分类、理由和唯一 `stage:`/`scene:`/`artifact:` `affectedScope`；控制面根据它推导 `returnState`，清空审批、pending 视觉快照/展示和 Diff Audit，失效实施包/Execution State、轮换 validationBatchId 并写 `resolvedAt`，不得默认整 Work Item/全部门失效。默认闭环是“冻结候选边界（A3 冻结 Implementation Package）→ 执行/实施 → diff 审计 → 获授权定向验证 → 仅按失败证据修正 → 完成”，且不绕过用户决定、测试授权或任何视觉/证据硬门。

## 领域返回结构

- Work Item、阶段、模块、领域、候选和基线身份。
- 覆盖事实、证据、阻断项、未覆盖项和领域结论。
- 实际 diff、路径所有者、A 等级与任务授权/显式批准 ID。
- 证据失效条件、处置级别（`repair`/`revalidate`/`return`）和建议返回的最早状态。
- `affectedScope`、实际失效的下游阶段/单元以及是否需要显式 `RETURN`；不得用“退回阶段”文本代替处置分类。

领域审查者只能提议和审查。全局控制面独占状态迁移、Approval Ledger 和最终门结论。
