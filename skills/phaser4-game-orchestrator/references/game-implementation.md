# 游戏实现与美术生产集成

进入 G1 或 G2 的游戏实现时读取本文件，并用 `review-funnel.md` 审核每个候选产物。实现按验收增量完成模块契约、代码、美术、验证和可运行构建闭环。视觉任务同时读取 `visual-quality-gate.md`；包含重做、重新设计、高保真、复刻、还原参考图、对齐截图、提升细节、替换整套 UI 或正式美术目标时，必须走标准通道并完整执行 A1 至 A6，不得因模块边界、交互或状态所有权未改变而降级。

## 必须任务链

1. **F0 冻结实现增量并判定通道**：从 GDD 选择已批准且有可观察验收条件的功能，记录审核 ID、候选版本、玩家行为、依赖、排除项和测试点；未批准需求不得实现。参考截图、录屏、运行项目或源代码还原任务先建立逐状态参考功能契约和视觉基线，证据不足的行为进入 F4 定义，不得从静态截图推断。参考输入和“按这个实现”只定义目标，不构成任何审核结论。
2. **筛选模块并执行拷问**：读取 module-decomposition.md，形成候选模块图；先完成 F1 技术证据与 F2 架构审阅，再由总控在 F3 合并冲突并调用 `$grilling` 完成 F4 受保护决策。获批后由技术架构写入 TDD 并标为“已批准待实现”；此前不得编写生产实现。
3. **建立技术骨架**：只为已批准模块按 TDD 完成场景、状态、输入、资源、配置、存档与平台边界，保证干净环境可以安装、启动和生产构建。
4. **A1 低保真功能与结构审核**：玩法用代码和 Phaser 基础图形实现可运行灰盒，提供稳定 ID、层级、位置、锚点、交互区、规则、状态、时序、反馈、异常恢复、响应式约束、结构说明和资源依赖清单；低保真使用独立路径与纹理键。F1 重放功能契约，F2 审核玩法与结构，F3 关闭跨域问题；只有行为未知、信息结构取舍或范围变化时才进入 F4，漏斗通过后冻结 A1。
5. **A2 高保真效果图审核**：美术按视觉基线和 A1 生成高保真效果图。无交互满幅背景优先生成；截图或代码重构先归档输入、运行并捕获固定视口截图。F1 检查产物与版本，F2 审核视觉质量，F3 核对结构和功能；新的视觉方向或代表性基准画面必须取得指向当前版本的 F4 结论，已冻结方向内的派生状态无需重复请求人工。
6. **A3 效果图专业审阅**：在 F2 检查结构一致性、状态覆盖、玩法可读性、视觉层级、宽高比、安全区、遮挡、边缘信息、风格一致性和单图可生成性；修改后返回 A2 的最早受影响审核层。
7. **A4 全量单图框选审核**：提交带唯一编号的框选图和覆盖全部可见对象、状态变体的完整单图清单。F1 检查清单完整性，F2 审核拆分与规格，F3 核对运行用途；只有新增预算、授权风险、主要识别对象处置或不可逆批量生产成本时才进入 F4。漏斗未通过不得生成正式单图。具有材质、体积、纹理、复杂高光、内外阴影、装饰花纹或角色化造型的主要视觉对象不得标为 `Phaser.Graphics` 代码绘制。
8. **实现核心规则**：玩法可在 A2 至 A5 期间按批准模块契约并行实现与表现解耦的规则、状态、输入、UI 行为、数值、生命周期及数据能力；边界变化时停止受影响模块并重新拷问。
9. **A5 正式单图生成与审核**：美术按 A4 查重并生成、拆分或补绘单图。F1 验证实际文件、登记与来源、深浅底透明边缘、Phaser 加载/缩放、目标视口、纹理键、锚点、九宫格、采样、帧序和性能；F2 审核资源质量与权属；偏离视觉方向或出现授权/成本取舍时才进入 F4。任一主要视觉对象缺少正式资源或上述证据时不得进入 A6。
10. **A6 功能与结构化装配及清理**：玩法使用通过 A5 的独立 GameObject、命名容器和图层装配正式预制体或场景，不得用整张效果图扁平替代。F1 运行测试与对比，F2 分别审核功能和视觉，F3 完成跨域回归、风险聚合与低保真零引用检查；参考图与运行图必须满足同条件要求。只有验收标准外的主观取舍或任务明确要求人工终验时才进入 F4。
11. **查重并复用本地服务**：需要浏览器、截图或端到端验证时，先读取 local-service-validation.md，按项目根目录、服务类型、模式、端口、监听进程和健康状态查找实例；匹配且健康时直接复用，只有确认没有可复用服务时才启动一个实例。
12. **完成测试与构建**：复用已登记服务运行模块契约测试、核心规则测试、功能验收和生产构建；逐场景验证方向/尺寸变化、过渡、四边四角无黑边、背景不截获输入，以及缩放、动画、安全区、采样和资源释放。参考还原的视觉检查至少覆盖外轮廓与构图、位置与尺寸、层级与遮挡、字体/描边/阴影、材质/纹理/高光、图标细节、安全边距、裁切与越界、九宫格变形和不同宽度下的等比缩放。任一对比条件不一致时标记“未验证”。
13. **区分结构与视觉证据**：源码方法名、固定坐标字符串、类型检查、单元测试、生产构建、无控制台错误、元素存在或“看起来接近”都不能单独作为视觉通过证据。源码标记测试只能命名为“结构回归”并验证结构契约，不得命名或表述为“视觉回归”。
14. **提交审核包**：记录审核 ID、候选版本、实现文件、模块边界、A1 至 A6 的 F1/F2/F3 结论、按需 F4 记录、本地服务结论、运行/测试/构建命令、同条件逐状态对比、正式资源、代码绘制理由、未完成资源清单、低保真清理、限制和阻断项；玩法向制作策划提交功能状态、向技术架构提交模块状态、向总控提交证据索引，分别更新 GDD、TDD 与控制面。

## 回退与复核

- 新增模块或边界变化返回模块划分与强制拷问；已批准功能范围不能替代模块边界批准。
- 功能、结构或交互变化返回参考功能契约与 A1；视觉方向变化返回 A2；框选、来源版本、规格、纹理键或锚点变化返回 A4；单图质量问题返回 A5。
- 人工指出运行结果存在明显细节不足时，立即撤销完成状态并按根因先退回 F1、F2 或 F3；结构表达问题同时退回 A2，漏项或拆分问题退回 A4，资源质量问题退回 A5。只有取舍本身需要人工时才进入 F4。
- 高保真、审阅、框选和单图生成可与纯规则实现并行，但同一视觉候选必须遵守 A1 → A2 → A3 → A4 → A5，且各阶段按漏斗审核；正式装配等待对应资源全部通过 A5。
- 源代码只能帮助识别实现入口，截图只能证明可见状态；参考还原必须运行目标场景、记录操作轨迹并捕获固定视口截图，不能只凭代码推断画面或只凭截图推断功能。
- 页面暂未就绪、工具切换或单次请求失败时先诊断已登记服务，不得直接再次启动；不得擅自终止归属不明的进程。
- 每个正式预制体或场景验收后立即清理对应低保真实现；G2 前不得残留低保真、占位、效果图替代物、未验收单图、重复文件或已取代版本。

## 完成定义

只有 A1 至 A6 的 F1/F2/F3 证据有效、按规则触发的 F4 均有当前候选版本明确结论、正式资源全部登记并通过 Phaser 验证、运行时没有未批准低保真替代物、同条件逐状态视觉对比与功能契约通过、低保真实现和占位资源已清理、构建与回归测试通过时，才可使用“高保真完成”“视觉还原通过”或“A6 完成”。文档、效果图、资源清单、静态截图、源码标记、作者自检或角色声明不能单独作为完成证据。
