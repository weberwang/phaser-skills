# 游戏实现与切图集成

进入 G1 或 G2 的游戏实现时读取本文件。实现不是单一编码动作，而是按验收增量完成代码、资源、验证和可运行构建的闭环。

## 必须任务链

1. **冻结实现增量**：从 GDD 选择已批准且有可观察验收条件的功能，记录玩家行为、依赖、排除项和测试点；未批准需求不得实现。
2. **建立技术骨架**：按 TDD 完成场景、状态、输入、资源、配置、存档与平台边界，保证干净环境可以安装、启动和生产构建。
3. **确认低保真结构**：玩法用代码和 Phaser 基础图形实现可运行灰盒，提供稳定 ID、层级、位置、锚点、交互区、状态、响应式约束、结构说明和资源依赖清单；人工确认后冻结 A1。
4. **推进视觉确认门**：美术严格执行“高保真效果图生成与确认 A2 → 效果图审阅 A3 → 全量单图框选与清单确认 A4”；任一门失败只返工当前或被影响的上游阶段。
5. **实现核心规则**：玩法可以在 A2 至 A5 期间并行实现与表现解耦的规则、状态、输入、UI 行为、数值、生命周期及已批准的数据能力，但不得把低保真或效果图当作正式资源。
6. **生成正式单图**：美术在 A4 确认后执行查重、单图生成/拆分/补绘、逐图检查、Phaser 验证和登记；已有有效资源直接复用。
7. **装配正式结构**：全部依赖资源通过后，玩法使用独立 GameObject、命名容器和图层拼装正式预制体或场景，保留可编辑层级、交互、动画和响应式约束；不得用整张效果图扁平替代。
8. **验证并清理低保真**：对照 A1/A2 验证功能和视觉。正式结构验收后确认无运行时、测试、构建或配置引用，删除低保真代码与占位资源，再运行测试和生产构建；保留结构说明和确认记录。
9. **提交实现证据**：记录实现提交或变更文件、运行/测试/构建命令、A1 至 A6 记录、正式资源与装配证据、低保真清理证据、剩余限制和阻断项；更新 GDD 状态与控制面索引。

## 资源与实现回路

- 高保真效果图、审阅、框选确认和单图生成可与纯规则实现并行，但必须严格遵守 A1 → A2 → A3 → A4 → A5 的内部顺序；正式装配等待对应资源全部通过 A5。
- 玩法发现边缘、尺寸、锚点、帧序或九宫格问题时，将运行证据交回美术；美术修复并更新登记后，玩法重新接入，测试只复核受影响路径。
- 来源版本、框选范围、规格、纹理键或锚点变化时，资源返回 A4 重新确认并查重；同时把依赖该资源的实现增量标为待复核。
- 每个正式预制体或场景验收后立即清理对应低保真实现；G2 前不得残留低保真代码、占位资源、效果图替代物、未验收单图、重复文件和已取代版本。

## 完成定义

实现增量只有在代码可运行、A1 至 A6 证据齐全、正式结构化预制体或场景验收通过、正式资源可追溯、低保真实现已删除、生产构建可复现且阻断缺陷已处置时才算完成。文档、效果图、资源清单或角色声明不能单独作为实现完成证据。
