# 游戏实现与美术生产集成

进入 G1 或 G2 的游戏实现时读取本文件。实现按验收增量完成模块契约、代码、美术、验证和可运行构建闭环。

## 必须任务链

1. **冻结实现增量**：从 GDD 选择已批准且有可观察验收条件的功能，记录玩家行为、依赖、排除项和测试点；未批准需求不得实现。
2. **划分模块并执行拷问**：读取 module-decomposition.md，形成候选模块图；总控调用 `$grilling` 确认职责、非目标、公开契约、状态所有权、依赖方向、失败边界和验收。获批后写入 TDD 并标为“已批准待实现”；此前不得编写生产实现。
3. **建立技术骨架**：只为已批准模块按 TDD 完成场景、状态、输入、资源、配置、存档与平台边界，保证干净环境可以安装、启动和生产构建。
4. **A1 低保真结构确认**：玩法用代码和 Phaser 基础图形实现可运行灰盒，提供稳定 ID、层级、位置、锚点、交互区、状态、响应式约束、结构说明和资源依赖清单；低保真使用独立路径与纹理键，人工确认后冻结 A1。
5. **A2 高保真效果图确认**：美术按视觉基线和 A1 生成高保真效果图。无交互满幅背景优先生成，竖屏满足高度适配、横屏满足宽度适配；截图或代码重构先归档输入、运行并捕获固定视口截图，再生成代表性效果图。人工确认后进入 A3。
6. **A3 效果图审阅**：检查结构一致性、状态覆盖、玩法可读性、视觉层级、宽高比、安全区、遮挡、边缘信息、风格一致性和单图可生成性；修改后返回 A2 重新确认。
7. **A4 全量单图框选确认**：在效果图副本上框出所有正式单图，建立编号、用途、复用、规格、锚点、九宫格、动画、纹理键和补全方式清单；人工确认前不得生成正式单图。
8. **实现核心规则**：玩法可在 A2 至 A5 期间按批准模块契约并行实现与表现解耦的规则、状态、输入、UI 行为、数值、生命周期及数据能力；边界变化时停止受影响模块并重新拷问。
9. **A5 正式单图生成与验收**：美术按 A4 查重并生成、拆分或补绘单图，完成逐图检查、Phaser 加载、满幅背景覆盖、纹理键、锚点、性能和权属验证；已有有效资源直接复用。
10. **A6 结构化装配与清理**：玩法使用通过 A5 的独立 GameObject、命名容器和图层装配正式预制体或场景，不得用整张效果图扁平替代。对照 A1/A2 验收后确认零引用，删除低保真代码、占位资源和纹理键，并保留确认记录。
11. **查重并复用本地服务**：需要浏览器、截图或端到端验证时，先读取 local-service-validation.md，按项目根目录、服务类型、模式、端口、监听进程和健康状态查找实例；匹配且健康时直接复用，只有确认没有可复用服务时才启动一个实例。
12. **完成测试与构建**：复用已登记服务运行模块契约测试、核心规则测试、功能验收和生产构建；逐场景验证方向/尺寸变化、过渡、四边四角无黑边、背景不截获输入，以及缩放、动画、安全区、采样和资源释放。
13. **提交实现证据**：记录实现文件、模块边界一致性、A1 至 A6、本地服务复用/新启动结论、运行/测试/构建命令、固定视口对比、正式资源、低保真清理、限制和阻断项；将完成模块标为“已实现”，更新 GDD 与控制面。

## 回退与复核

- 新增模块或边界变化返回模块划分与强制拷问；已批准功能范围不能替代模块边界批准。
- 结构或交互变化返回 A1；视觉方向变化返回 A2；框选、来源版本、规格、纹理键或锚点变化返回 A4；单图质量问题返回 A5。
- 高保真、审阅、框选和单图生成可与纯规则实现并行，但美术内部必须严格遵守 A1 → A2 → A3 → A4 → A5；正式装配等待对应资源全部通过 A5。
- 源代码只能帮助识别结构；截图或代码驱动的重构必须运行目标场景并固定视口截图，不能只凭代码推断画面。
- 页面暂未就绪、工具切换或单次请求失败时先诊断已登记服务，不得直接再次启动；不得擅自终止归属不明的进程。
- 每个正式预制体或场景验收后立即清理对应低保真实现；G2 前不得残留低保真、占位、效果图替代物、未验收单图、重复文件或已取代版本。

## 完成定义

实现增量只有在模块契约与实现一致、A1 至 A6 证据齐全、正式结构可编辑且验收通过、正式资源可追溯、低保真实现已删除、生产构建可复现且阻断缺陷已处置时才算完成。文档、效果图、资源清单或角色声明不能单独作为完成证据。
