# 游戏实现规则

实现按可验收增量闭环。玩法独占规则、状态和交互代码；美术可维护纯表现层资源配置、布局/表现预制数据和视觉集成调整，但不得改变玩法规则。

## 增量流程

1. 冻结玩家行为、模块契约、所有权、验收、服务复用和 V0 类型。原子资源必须记录有效且绑定当前版本的视觉契约、确认、基线与预算；模块边界变化强制模块门和 grilling。F4 只做精确集成/发布决定。
2. 适用 V1 时由玩法定义状态、输入、规则、反馈和必要低保真草图或可运行灰盒，美术与测试建立玩法视觉契约并冻结每场景视觉预算。相关玩法、架构与 UI 布局证据关闭可判定问题后，总控提交当前低保真候选确认包；只有用户明确“通过”才进入 V2。原子资源引用既有有效记录，不为形式重跑 V1；已冻结结构不重复灰盒。
3. 纯玩法规则可与 V2-V4 并行，但不得消费未验收资源或从效果图裁切正式资源。
4. V2 把关键画面装入最小可玩切片，提供动态轨迹；非作者独立美术 F2 检查识别、预警、反馈、遮挡和小屏表现。场景、整套 UI、视觉系统、参考还原、所有重做类任务，以及定义或改变用户可见高保真形态的适用组件/资源集，在 F2 通过后由总控提交当前候选的高保真效果图确认包；只有用户明确“通过”才形成视觉可交付并进入 V3。
5. V3 按资产类型设计源文件、输出、图集/帧/锚点/压缩及机器清单。场景/系统/参考还原做非作者 F2；AI 合成栅格拆分只是可选路线。
6. V4 生产并验证资源。只有机器清单状态为 `accepted` 且来源或生成记录、授权、运行时输出、Phaser 和玩法视觉证据完整时可集成。
7. V5 由玩法和美术协作结构化装配：玩法维护规则、状态、交互；美术调整纯表现和布局/表现数据。动态可玩轨迹与低保真清理进入 F3 工程证据；F0 只校验动作授权与流程合规。
8. F0 校验授权合规，F1 校验当前候选与批准规格一致，F2 由独立 QA、玩法、技术或视觉角色检查领域质量，F3 只验证当前候选的工程证据，F4 只做精确集成/发布决定。V1/V2 对象确认不能替代专业缺陷修复。

## UI 与背景

UI 必须使用 [`phaser4-game-ui-layout`](../../phaser4-game-ui-layout/SKILL.md) 的版本化合同和唯一布局入口，从显式坐标空间、参照物、双方停靠点、距离、尺寸、安全区与断点计算；资源 origin、布局停靠点和动画偏移分离。视口、安全区、方向、内容尺寸、DPR（若相关）和状态是入口输入，重排必须幂等，不能在多个生命周期回调散布无参照坐标。固定尺寸、绝对定位、悬浮 HUD、Camera/Container 和单行省略触发布局专项审核，不凭模式本身判错；合同缺依据或证据时才退回。普通测试验证关系不变量，Golden 只在冻结目标视口验证精确视觉。装饰屏幕空间背景使用统一适配器；世界空间 Tilemap、碰撞和玩法环境使用独立结构，不能扁平化为背景。

## 视觉证据

参考与运行图在相同视口、设备像素比、状态、轨迹、语言和时间点采集，并记录 ROI、容差、稳定帧和遮罩。生成式、动画与 VFX 不能只用像素差判断。静态高保真、资源齐全、源码检查和构建成功不能单独证明游戏性。

## 回退

玩法契约或结构问题退 V1，并让旧确认失效；模块边界变化强制模块门与 grilling。任何修订候选重跑受影响的 F0 授权合规、F1 规格一致、F2 独立领域质量、F3 当前候选工程验证和 F4 精确集成/发布决定。
