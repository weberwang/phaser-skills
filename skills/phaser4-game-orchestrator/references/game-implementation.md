# 游戏实现与美术生产集成

进入 G1 或 G2 的游戏实现时读取本文件。实现按验收增量完成模块契约、代码、美术、验证和可运行构建闭环。视觉任务同时读取 `visual-quality-gate.md`；包含重做、重新设计、高保真、复刻、还原参考图、对齐截图、提升细节、替换整套 UI 或正式美术目标时，必须走标准通道并完整执行 A1 至 A6，不得因模块边界、交互或状态所有权未改变而降级。

## 必须任务链

1. **冻结实现增量并判定通道**：从 GDD 选择已批准且有可观察验收条件的功能，记录玩家行为、依赖、排除项和测试点；未批准需求不得实现。参考截图、录屏、运行项目或源代码还原任务先建立逐状态参考功能契约和视觉基线，证据不足的行为必须人工定义，不得从静态截图推断。参考输入和“按这个实现”只定义目标，不构成任何阶段确认。
2. **划分模块并执行拷问**：读取 module-decomposition.md，形成候选模块图；总控调用 `$grilling` 确认职责、非目标、公开契约、状态所有权、依赖方向、失败边界和验收。获批后由技术架构写入 TDD 并标为“已批准待实现”；此前不得编写生产实现。
3. **建立技术骨架**：只为已批准模块按 TDD 完成场景、状态、输入、资源、配置、存档与平台边界，保证干净环境可以安装、启动和生产构建。
4. **A1 低保真功能与结构确认**：玩法用代码和 Phaser 基础图形实现可运行灰盒，提供稳定 ID、层级、位置、锚点、交互区、前置状态、输入、规则、状态迁移、时序、反馈、成功/失败、异常恢复、响应式约束、结构说明和资源依赖清单；低保真使用独立路径与纹理键。参考还原任务逐项重放功能契约。只有人工明确答复并留下指向当前 A1 产物的记录后才能冻结 A1，不得从参考输入、继续任务或未提出异议推断通过。
5. **A2 高保真效果图确认**：美术按视觉基线和 A1 生成高保真效果图。无交互满幅背景优先生成，竖屏满足高度适配、横屏满足宽度适配；截图或代码重构先归档输入、运行并捕获固定视口截图，再生成代表性效果图。只有指向当前版本效果图的明确人工确认记录存在时才能进入 A3。
6. **A3 效果图审阅**：检查结构一致性、状态覆盖、玩法可读性、视觉层级、宽高比、安全区、遮挡、边缘信息、风格一致性和单图可生成性；修改后返回 A2 重新确认。
7. **A4 全量单图框选确认**：提交带唯一编号的框选图和覆盖全部可见对象、状态变体的完整单图清单。每项记录用途、目标尺寸、透明要求、锚点、九宫格、动画、纹理键、复用与遮挡补全方式，并明确归入“代码绘制、复用、新生成、重绘、删除”之一；人工对当前版本明确确认前不得生成正式单图。具有材质、体积、纹理、复杂高光、内外阴影、装饰花纹或角色化造型的主要视觉对象不得标为 `Phaser.Graphics` 代码绘制。
8. **实现核心规则**：玩法可在 A2 至 A5 期间按批准模块契约并行实现与表现解耦的规则、状态、输入、UI 行为、数值、生命周期及数据能力；边界变化时停止受影响模块并重新拷问。
9. **A5 正式单图生成与验收**：美术按 A4 查重并生成、拆分或补绘单图。A5 证据必须包含每个正式资源的实际文件、资源登记与来源、深浅背景透明边缘检查、Phaser 加载与缩放截图、目标视口运行证据，以及未完成和未验收资源清单；同时验证纹理键、锚点、九宫格、采样、帧序、性能、权属和当前文件版本的人工确认。任一主要视觉对象缺少正式资源或上述验收时不得进入 A6。
10. **A6 功能与结构化装配及清理**：玩法使用通过 A5 的独立 GameObject、命名容器和图层装配正式预制体或场景，不得用整张效果图扁平替代。逐状态对照参考功能契约、A1 和 A2 验收功能与视觉；参考图与运行图必须使用一致的视口宽高、设备像素比、游戏状态、操作轨迹、文本语言和动画时间点，同时保存两图并生成并排图、叠加图或像素差异图。确认零引用后删除低保真代码、占位资源和纹理键，并保留当前 A6 的明确人工验收记录。
11. **查重并复用本地服务**：需要浏览器、截图或端到端验证时，先读取 local-service-validation.md，按项目根目录、服务类型、模式、端口、监听进程和健康状态查找实例；匹配且健康时直接复用，只有确认没有可复用服务时才启动一个实例。
12. **完成测试与构建**：复用已登记服务运行模块契约测试、核心规则测试、功能验收和生产构建；逐场景验证方向/尺寸变化、过渡、四边四角无黑边、背景不截获输入，以及缩放、动画、安全区、采样和资源释放。参考还原的视觉检查至少覆盖外轮廓与构图、位置与尺寸、层级与遮挡、字体/描边/阴影、材质/纹理/高光、图标细节、安全边距、裁切与越界、九宫格变形和不同宽度下的等比缩放。任一对比条件不一致时标记“未验证”。
13. **区分结构与视觉证据**：源码方法名、固定坐标字符串、类型检查、单元测试、生产构建、无控制台错误、元素存在或“看起来接近”都不能单独作为视觉通过证据。源码标记测试只能命名为“结构回归”并验证结构契约，不得命名或表述为“视觉回归”。
14. **提交实现证据**：记录实现文件、模块边界一致性、A1 至 A6、各人工确认、本地服务复用/新启动结论、运行/测试/构建命令、同条件逐状态对比、正式资源、代码绘制理由、未完成资源清单、低保真清理、限制和阻断项；玩法向制作策划提交功能状态、向技术架构提交模块状态、向总控提交证据索引，分别更新 GDD、TDD 与控制面。

## 回退与复核

- 新增模块或边界变化返回模块划分与强制拷问；已批准功能范围不能替代模块边界批准。
- 功能、结构或交互变化返回参考功能契约与 A1；视觉方向变化返回 A2；框选、来源版本、规格、纹理键或锚点变化返回 A4；单图质量问题返回 A5。
- 人工指出运行结果存在明显细节不足时，立即撤销“高保真完成”“视觉还原通过”或“A6 完成”状态。结构表达问题退回 A2，漏项或拆分问题退回 A4，材质、纹理、透明边缘、细节、缩放或资源接入质量问题退回 A5；不得以局部坐标调整掩盖资源质量问题。
- 高保真、审阅、框选和单图生成可与纯规则实现并行，但美术内部必须严格遵守 A1 → A2 → A3 → A4 → A5；正式装配等待对应资源全部通过 A5。
- 源代码只能帮助识别实现入口，截图只能证明可见状态；参考还原必须运行目标场景、记录操作轨迹并捕获固定视口截图，不能只凭代码推断画面或只凭截图推断功能。
- 页面暂未就绪、工具切换或单次请求失败时先诊断已登记服务，不得直接再次启动；不得擅自终止归属不明的进程。
- 每个正式预制体或场景验收后立即清理对应低保真实现；G2 前不得残留低保真、占位、效果图替代物、未验收单图、重复文件或已取代版本。

## 完成定义

只有 A1 至 A5 证据有效、所有人工确认门都有指向当前产物的明确记录、正式资源全部登记并通过 Phaser 验证、运行时没有未批准低保真替代物、同条件逐状态视觉对比通过、功能契约通过、低保真实现和占位资源已清理、构建与回归测试通过时，才可使用“高保真完成”“视觉还原通过”或“A6 完成”。文档、效果图、资源清单、静态截图、源码标记或角色声明不能单独作为完成证据。
