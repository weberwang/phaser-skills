# 游戏实现规则

实现按可验收增量闭环。玩法独占规则、状态和交互代码；美术可维护纯表现层资源配置、布局/表现预制数据和视觉集成调整，但不得改变玩法规则。

## 增量流程

1. 冻结玩家行为、模块契约、所有权、验收、服务复用和 V0 类型。原子资源必须记录已有适用、有效且绑定版本的玩法视觉契约、高保真效果图确认记录、视觉可交付结论与预算基线；缺少任一基线或确认记录时升级组件/资源集或场景路径。模块边界变化先完成模块审批。
2. 适用 V1 时由玩法定义状态、输入、规则、反馈和必要灰盒，美术与测试建立玩法视觉契约并冻结每场景视觉预算。原子资源引用既有基线，不为形式重跑 V1；已冻结结构不重复灰盒。
3. 纯玩法规则可与 V2-V4 并行，但不得消费未验收资源或从效果图裁切正式资源。
4. V2 把关键画面装入最小可玩切片，提供动态轨迹；非作者独立美术 F2 检查识别、预警、反馈、遮挡和小屏表现。场景、整套 UI、视觉系统、参考还原、所有重做类任务，以及定义或改变用户可见高保真形态的适用组件/资源集，在 F2 通过后由总控提交当前候选的高保真效果图确认包；只有用户明确“通过”才形成视觉可交付并进入 V3。
5. V3 按资产类型设计源文件、输出、图集/帧/锚点/压缩及机器清单。场景/系统/参考还原做非作者 F2；AI 合成栅格拆分只是可选路线。
6. V4 生产并验证资源。只有机器清单状态为 `accepted` 且来源或生成记录、授权、运行时输出、Phaser 和玩法视觉证据完整时可集成。
7. V5 由玩法和美术协作结构化装配：玩法维护规则、状态、交互；美术调整纯表现和布局/表现数据。用动态可玩轨迹验证功能与玩法视觉，并由玩法清除低保真引用。原子资源以集成 F1 和动态证据关闭本阶段。
8. 组件/资源集和场景/系统路径在 V5 的 F3 聚合跨域、设备、性能、构建和回归风险；原子资源只有出现跨域风险才执行 F3。受保护决策才进入 F4；V2 出口高保真效果图确认是强制受保护决策例外，不能替代专业缺陷修复。

## UI 与背景

UI 通过统一布局入口从参照物、停靠点、距离、尺寸、安全区与断点契约计算，资源锚点、布局停靠点和动画偏移分离。装饰屏幕空间背景使用统一适配器；世界空间 Tilemap、碰撞和玩法环境使用独立结构，不能扁平化为背景。

## 视觉证据

参考与运行图在相同视口、设备像素比、状态、轨迹、语言和时间点采集，并记录 ROI、容差、稳定帧和遮罩。生成式、动画与 VFX 不能只用像素差判断。静态高保真、资源齐全、源码检查和构建成功不能单独证明游戏性。

## 回退

玩法契约或结构问题退 V1；原子资源引用基线或绑定的确认记录失效时升级路径；方向问题或用户拒绝按根因退 V2a/V1，识别、动态样片问题或“修改后重提”退到受影响 V2b/F2 并产生新候选版本；源文件/路线/预算设计退 V3；资源质量或证据退 V4；集成、跨域或低保真残留留 V5。完成时检查适用 V 阶段、适用 F2、适用时 F3、通常按需 F4 和强制 V2 出口确认例外，只重跑受影响路径规定的审核层。
