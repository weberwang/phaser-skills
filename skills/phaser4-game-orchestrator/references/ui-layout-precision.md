# UI 精准布局契约

新增、重做、还原或修复 UI 布局时读取本文件。目标不是在单一截图中“看起来接近”，而是把每个 UI 组件的位置、尺寸和排列关系写成可计算、可复现、可测试的约束。资源锚点只描述纹理如何挂到 GameObject；布局锚点描述组件如何挂到屏幕、父容器或兄弟组件，两者不得混用。

## 坐标与参照规则

1. 在 `docs/visual-design.md` 冻结基准视口、逻辑单位、缩放策略、方向、安全区来源和位置误差阈值。默认把安全区矩形作为屏幕级 UI 的参照；只有允许延伸到刘海、圆角或系统手势区的纯装饰层才能参照完整视口。
2. 为 UI 根、容器、组件和布局组分配稳定 ID，并声明父级与本地坐标系。子对象只记录父级本地坐标，不把世界坐标反写为局部偏移。
3. 每个组件必须选择一个明确参照物：`viewport`、`safe-area`、父容器、具名兄弟组件或布局组中的前一项。禁止用没有参照物语义的孤立屏幕 `x/y` 常量实现 UI。
4. 同时声明参照物停靠点和组件自身停靠点，可选左、右、上、下、水平中心、垂直中心或文本基线；再记录有符号的水平、垂直停靠距离。距离使用设计逻辑像素或明确比例，不得在同一轴上隐式混用世界像素、纹理像素、CSS 像素和比例。
5. 声明宽高策略：固定、内容驱动、拉伸、保持宽高比或最小/最大约束。动态文本以布局框或预留框参与计算，不以字形透明边缘作为停靠边界。
6. 绝对位置只允许用于已批准的固定基准画布、调试覆盖层或不属于 UI 的世界对象；在 TDD 记录原因、适用视口和验收证据。不得以“当前屏幕能对上”为理由豁免相对布局。

## 横向与纵向排列

1. 对水平行、垂直列、工具栏、按钮组和列表建立具名布局组，声明方向、成员顺序、主轴分布、交叉轴对齐、首尾内边距、成员间距、换行策略和隐藏成员处理。
2. 默认关闭自动换行；需要换行时明确列数或触发宽度、行列间距和阅读顺序。成员隐藏后是保留占位还是收拢空间必须写入契约。
3. 不从前一个成员已经取整后的屏幕位置累计下一个成员的位置。先在逻辑坐标中计算整个布局组，再在最终渲染边界统一执行像素取整，避免重复项产生累计漂移。
4. 把布局基准位置与动画位移分离。动画、按压、震动和入场效果只修改表现偏移，结束或中断后返回布局计算出的基准位置。

## 契约字段

在 `docs/TDD.md` 为每个 UI 组件至少记录以下字段：

| 字段 | 要求 |
| --- | --- |
| 组件 | 稳定 ID、状态和父级/坐标系 |
| 参照关系 | 参照物 ID、参照物停靠点、组件自身停靠点 |
| 停靠距离 | 水平与垂直距离、单位、取值来源 |
| 尺寸 | 宽高策略、固定值或比例、最小/最大值、宽高比 |
| 排列 | 布局组 ID、方向、顺序、间距、主轴分布、交叉轴对齐 |
| 适配 | 安全区、方向、断点、最窄/最宽视口和状态变体 |
| 精度 | 期望边界或中心、允许误差、验证视口和证据位置 |

参考还原任务从同条件参考图测量停靠关系、边界和间距，并把数值来源关联到参考版本。无法从证据确定的尺寸或距离标为“待人工定义”，不得靠反复微调代码固化猜测值。

## 实现顺序

1. 先计算视口和安全区矩形，再计算 UI 根与一级停靠组件，然后计算嵌套容器和横纵布局组，最后应用局部装饰与表现偏移。
2. 每个场景或 UI 子系统使用单一布局入口，根据视口、安全区、方向、状态和内容重新计算。创建、恢复、方向变化、画布尺寸变化、安全区变化和影响尺寸的文本变化都必须触发布局；不得把坐标更新散落在多个生命周期回调中。
3. 重算必须从契约值开始，不能在上一次结果上继续加减，避免重复 resize 或场景恢复产生漂移。
4. 保持资产原点、裁切透明边界、九宫格边界和布局边界可区分。视觉资源更换后如果内容边界改变，先核对资源锚点；不得通过修改屏幕停靠距离掩盖资源本身的透明留白或裁切问题。

## A1 至 A6 约束

- A1：在低保真中建立完整 UI 布局契约，提交带稳定 ID、参照线、安全区、组件边界、中心线和间距标注的运行截图。F1 检查字段与证据完整性，F2 审核布局关系，F3 关闭跨域冲突；只有信息结构或响应式取舍属于受保护决策时才进入 F4。缺少参照物、停靠点、距离、尺寸策略或布局组规则时不得通过 A1 漏斗。
- A2：高保真效果图必须沿用 A1 的布局几何。效果图若改变组件参照关系、尺寸策略、排列顺序或响应式行为，返回 A1 更新契约并从最早失效审核层复核。
- A3：在 F2 按契约叠加参照线和边界审阅效果图，检查停靠距离、对齐、组间距、文本安全区和最窄/最宽视口；只凭肉眼判断不得通过精准布局审阅。
- A4/A5：分别记录资源锚点、九宫格和透明边界；这些资源属性不得替代 TDD 中的 UI 布局参照关系。
- A6：使用命名容器、独立 GameObject 和统一布局入口实现契约。F1 执行逐组件测量，F2 审核布局精度，F3 验证响应式与跨状态结果。只修改已有契约中的单个距离或间距且影响明确时可走快速通道；改变参照物、停靠边、坐标系、布局组、换行、安全区或响应式策略时进入标准通道并返回 A1。

## 验证与通过条件

1. 至少覆盖基准视口、目标最窄和最宽视口、每个支持方向及代表性安全区；对动态文本、成员显隐和关键状态分别验证。
2. 在布局稳定帧读取每个组件或布局框的实际边界、中心和间距，与 TDD 期望值生成逐项表格；同时保存带边界与参照线的运行截图。源码中存在某个常量或组件不能证明位置正确。
3. TDD 未指定阈值时，基准视口采用以下默认值：主要边界、中心和尺寸偏差不超过 `1` 个设计逻辑像素；相邻间距偏差不超过 `1` 个设计逻辑像素；重复布局末项不得出现超过 `1` 个设计逻辑像素的累计漂移。设备像素取整后的额外误差不得超过 `1` 个物理像素。
4. 响应式视口不比较未经定义的绝对坐标，而是验证停靠边、停靠距离、对齐、顺序、间距、尺寸策略、安全区和断点结果全部符合契约。
5. 任一组件缺少布局契约、使用未批准孤立屏幕坐标、越过安全区、出现累计漂移，或在 resize、恢复、文本变化后没有重新排布时，UI 精准布局判定为未通过。
