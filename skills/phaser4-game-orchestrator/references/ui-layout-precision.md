# UI 精准布局与响应式视觉契约

本文件是响应式视觉契约、适用范围和 V1-V5 门禁的唯一详细事实来源。其他
skill 只负责路由和验收职责；测量字段、自动化脚本及 Hook 形状见 QA 的
[响应式视觉验证](../../phaser4-game-qa-performance/references/responsive-visual-validation.md)。

## 适用范围与升级

场景、整套 UI、视觉系统和参考还原必须建立本契约。组件/资源集在影响布局、
满幅背景、安全区、文本尺寸或视口行为时同样适用；否则可引用当前有效的契约。
原子资源默认不触发响应式门禁，但出现上述任一影响时必须升级到组件/资源集或
场景路径。快速通道只允许不改变布局几何、视口行为、背景覆盖、安全区或断点的
局部尺寸、锚点、采样、九宫格、文本、间距和颜色修复。

## V1 冻结内容

V1 必须为每个关键场景、状态和 UI 组写出以下内容；任一项未定义都标记
“响应式契约缺失”，阻断 V2，不得以截图或实现猜测补齐。

### 四层坐标关系

| 层 | 必须记录 | 禁止的替代 |
| --- | --- | --- |
| 浏览器 viewport | CSS `x/y/width/height`、方向、DPR、浏览器安全区输入 | 只写逻辑画布尺寸 |
| Canvas | DOM `getBoundingClientRect()`、CSS 缩放、是否溢出 viewport | 只证明 Canvas 内部 ROI |
| 逻辑坐标 | 游戏逻辑宽高、缩放原点、世界/屏幕空间关系 | 将 CSS 像素直接当逻辑坐标 |
| safe area | 四边 inset、UI 可用矩形、横屏刘海/手势区策略 | 只记录设备型号或口头“留出边距” |

契约还要说明 Canvas 与 viewport、逻辑画布与 Canvas、safe area 与关键 UI 的
映射方向及单位。浏览器 viewport 是最终满幅判定面；逻辑画布或 Canvas ROI
不能替代完整页面证据。

### 适配策略

逐场景选择并冻结策略及其边界，不得把 `FIT` 当作响应式完成：

| 策略 | 必须说明 | 允许的结论 |
| --- | --- | --- |
| `FIT` | 等比缩放原点、最大/最小比例、溢出处理、允许留白 | 只能证明等比且不溢出；不证明满屏、重排或安全区 |
| `RESIZE` | 逻辑尺寸变化范围、重排触发点、世界/屏幕空间分界 | 证明 resize 前后关系和可读性 |
| `COVER` | 覆盖目标、裁切焦点、裁切上下限、关键对象安全区 | 证明背景/容器覆盖 viewport，不等于 UI 自动重排 |
| 响应式锚点 | 每个关键 UI 的父坐标系、参照物、停靠点、距离和尺寸策略 | 证明多比例重锚定及间距不漂移 |
| 断点重排 | 断点值、增删成员、文本换行、滚动/触控方式、动画过渡 | 证明各断点结构和动态行为 |

背景必须写明覆盖目标（viewport、safe area 或仅 Canvas）、四边留白政策、
裁切焦点和是否允许拉伸。未允许的留白、纯色带、透明缝或复制拉伸均为失败；
允许的留白必须给出四边数值/比例和使用理由。横屏必须单独写出策略，不能由
竖屏规则推断。

### 视口与动态矩阵

至少登记基准、最窄、最宽、横屏和安全区五类条件（可由项目补充设备/DPR）：

| 条件 | 必填证据 |
| --- | --- |
| 基准 | viewport、Canvas、逻辑尺寸、关键 UI 边界、背景覆盖 |
| 最窄 | 同上，并记录文字缩放/换行、显隐、滚动和触控变化 |
| 最宽 | 同上，并记录重锚定、最大间距和背景裁切 |
| 横屏 | 方向切换前后策略、断点、焦点和安全区 |
| 安全区 | 四边 inset、可用矩形、关键 UI 与手势区距离 |

每个矩阵项必须定义动态文本（增长、换行、语言）、成员显隐、滚动、触控、
resize 前后行为和稳定帧；动态 resize 在同一页面完成，不得刷新页面伪造响应式。

## V1-V5 门禁

- **V1 契约冻结**：完成四层坐标、适配策略、背景目标、留白/裁切/拉伸许可、
  五类视口矩阵、横屏策略及动态行为。缺任一项即“响应式契约缺失”，阻断 V2。
- **V2 动态样片**：沿矩阵逐视口运行最小可玩样片，覆盖动态文本、显隐、
  滚动、触控、resize、重锚定、间距、背景覆盖、安全区和最小可读性。仅有
  基准静态图即阻断 V3；必须保留同一页面的动态轨迹与完整 viewport 截图。
- **V3 生产设计**：把响应式策略、断点、锚点、背景裁切/延展规则绑定到资源
  和预制数据；不得在生产阶段发明未冻结的布局规则。
- **V4 资源级验收**：由非作者 F2 在完整 viewport 检查纹理边界、背景资源满幅
  能力、锚点、字体/九宫格、缩放和预算。算法验证或 Canvas ROI 只能作补充，
  不能证明生产场景已覆盖 viewport。
- **V5 运行态验收**：在所有矩阵条件和关键动态状态提供完整页面截图、轨迹、
  resize 前后测量和独立 F3（适用路径）；同时验证资源满幅能力与生产场景的
  实际 viewport 覆盖。F2/F3 必须由非作者提供可复现证据，缺完整 viewport
  证据只能标记“未验证”。

响应式验证的详细记录字段、Hook 契约、禁止的假通过方式、脚本和根因分类，
统一遵循 QA 的[响应式视觉验证](../../phaser4-game-qa-performance/references/responsive-visual-validation.md)。

## 关系记录格式

每个关键 UI 记录父级坐标系、参照物、双方停靠点、水平/垂直距离、尺寸策略、
布局组、顺序、安全区、方向/断点、动态内容和项目量化误差阈值。资源原点/纹理
锚点、布局停靠点和动画偏移分开记录；`x/y` 只能表达相对已声明参照物的本地
距离。截图比较记录 ROI、容差、稳定帧和遮罩理由，但像素差不能替代布局语义、
动态可用性或完整 viewport 证据。
