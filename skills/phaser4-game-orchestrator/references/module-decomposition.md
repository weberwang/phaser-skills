# 模块划分、审计与决策边界

新建模块、首次实现模块，或改动职责、公开契约、状态所有权、依赖方向、持久化或平台边界时读取本文件。模块划分不是按文件夹或类名分组，而是冻结可独立说明、实现、测试和替换的职责边界。

## 划分模块

1. 从已批准 GDD、TDD 和代码事实提取玩家行为、状态变化、平台能力、资源依赖、失败路径和验收证据；优先扩展边界清晰的现有模块。
2. 建立候选模块图，记录职责与非目标、公开入口和输入/输出、状态/数据所有权、生命周期、错误与降级、资源/平台依赖、允许/禁止依赖、测试边界和负责人。
3. 规定单向依赖和调用契约。公共代码和公共正式资源只有被至少两个已确认场景稳定复用，或属于启动运行必需时才提取；消除或明确处理循环依赖、双向状态写入、无边界 `common`/`utils`、公共素材库、全局事件和绕过公开入口的访问。
4. 给出 G1 内可独立验证的实施计划：先完成覆盖全部授权场景和必需瞬态宿主上下文图的全局视觉效果图冻结门，再由 `executionUnits` 按 `SHARED` 最小骨架→`MODULE`→按场景组织的 `SCENE`+紧邻 `DISPLAY_LAYER`→`INTEGRATION`/联合验收推进。全局视觉冻结是 A3 实施包/代码单元的前置门，不新增 `unitType`；数组是控制面执行顺序的唯一权威，不通过依赖图计算顺序。每个场景内部完成规则、适配与表现、正式视觉、全部显示层、清理和联合证据后再关闭；并行拆分必须具有互斥写范围和状态所有权。
5. 把每个模块、场景、共享基础和集成点拆成实施单元，按数组位置记录单元 ID、类型、范围、并行模式/并行组、负责人、互斥写范围、状态所有权、验收命令或证据；同一非空并行组的 PARALLEL 单元必须在数组中连续出现并视为一个顺序阶段，串行单元必须写明原因，禁止只写笼统的“可并行”。
6. 主动识别安全并行：`SHARED` 骨架、共享基础、宿主场景装配和 `INTEGRATION` 单元强制串行；`MODULE` 可在骨架完成后按互斥所有权并行，`SCENE` 仍按计划顺序推进。SERIAL 单元的 READY 需要其前面全部单元有当前有效 PASS Unit Result，PARALLEL 单元的 READY 只需要其并行组首项之前全部单元有当前有效 PASS，同组 peer 不互相等待，不得手工自填。其后至少两个 MODULE/SCENE/DISPLAY_LAYER 单元属于同一非空组且写范围与状态所有权互斥时，使用完整不可变批次原子委派；`DISPLAY_LAYER` 必须绑定宿主场景身份、紧邻宿主 `SCENE` 并在该宿主场景内闭环，不能在所有场景之后单独实施。跨模块/跨场景集成点保持串行；并行组不得分散在数组多个位置，也不得跳过预设前序门或验收。
7. 场景与模块使用同一粒度规则逐个标注。当前共享工作区可依独占所有权并行；不得自动创建 worktree，只有人工明确要求时才按既有规则使用。

## 场景与公共基础边界

- 全局视觉效果图冻结通过后，`SHARED` 公共基础只提供稳定契约和最小运行骨架，不拥有单场景业务状态；Boot/Preload 只提供最小启动和加载能力，不提前实现完整模块或场景业务。
- `gameplay` 与 `supporting` 是完整场景覆盖的分类；各场景的实际顺序由计划制定者冻结，不再强制某一类别先于另一类别。每个 `SCENE` 必须连同其全部 HUD、UI、modal、popup、drawer、toast 等显示层一起闭环。
- 场景之间通过公开服务、状态仓库或明确消息契约协作，不直接读取或写入另一 Scene 实例的内部状态。
- 单场景逻辑和资源归属具体场景；只有满足公共提取条件的内容才能标记为 shared。

## 审计与审核

模块候选按统一 [审核漏斗](review-funnel.md) 执行：F0 授权与流程合规，F1 规格一致性，F2 架构/QA 领域质量，F3 工程验证；只有 A4-A6 使用 F4。首次模块或边界变化先审计事实，不机械停止或 grilling。

在生产实现前，先用代码、配置、权威工件和确定性执行关闭事实。若实质范围、风险、验收、依赖或不可逆架构选择阻断候选模块图形成，可在候选前 grilling 并绑定决策 ID/工件版本；已有候选时，候选相关 F4 必须在 F3 后。没有未决用户决定时直接继续。

## 实现与变更

1. 在 `docs/TDD.md` 记录已确认模块清单、依赖矩阵、候选身份和审核结论；F4 只链接精确集成/发布决定。不得把沉默、功能范围批准或旧候选批准扩张为当前架构或实现决定。
2. 实现发现边界变化时停止直接受影响范围并更新模块图。只有无法从事实确定且存在实质架构/数据/产品取舍时才 grilling；否则依任务授权继续并重跑受影响门。模块内部、私有实现无需 grilling。
3. 逐模块验证公开契约、单一状态写入所有者、禁止依赖、错误边界和可复现集成证据。模块只有边界与实现一致、测试通过、下游使用公开入口且无未批准依赖时才可标为“已实现”。
