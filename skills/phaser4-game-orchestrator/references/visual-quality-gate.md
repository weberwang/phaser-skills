# 视觉质量硬门

本门禁判断最终运行中的玩法视觉，不被静态效果图、像素接近、资源齐全、源码结构或构建结果替代。

## V0 路径

- 原子资源：视觉方向已冻结、结构/交互/布局不变，并有适用且有效的玩法视觉契约、视觉可交付结论与预算基线可引用的单个或小批同类正式资源，走 V3-V5；缺少可引用基线时升级组件/资源集或场景路径。
- 组件/资源集：走 V1-V5，V2/V4 做非作者 F2，V5 做 F3。
- 场景、整套 UI、视觉系统、参考还原：走完整 V1-V5，V2/V3/V4 做非作者 F2，V5 做 F3。
- 快速通道：不新增正式资源、不改变方向、拆分、结构、交互或布局的局部修复，只做 F0/F1。

F3 只处理集成或跨域风险。F4 只处理受保护决策。

任何“重做、重新设计、提升游戏感、替换整套 UI”任务都不得当作原子资源跳过 V2。场景、整套 UI、视觉系统和参考还原必须执行 V2a/V2b；组件/资源集按影响执行。原子资源只能继承当前适用且有效的视觉可交付基线。

## 游戏感与视觉可交付

V2 必须完整执行美术角色的 [游戏感质量硬门](../../phaser4-game-asset-integration/references/game-feel-quality-gate.md)，并在同一 V2 阶段内保留两个不可省略的检查点：`V2a 方向基准`与 `V2b 整体视觉审阅`。不得新增 V 阶段或用 V3/V4 证据反向替代 V2。

重做类任务在 V2a 正式基准前至少提交 3 个在构图、场景容器、核心焦点、材质或情绪上有实质差异的方向，不得只换色。每个方向分别说明玩家幻想、核心玩具、主要交互、奖励表达和状态扩展。严格参考复刻可免三方向，但必须保留同条件参考/候选对比和差异说明。

V2a/V2b 的每个核心结论必须引用当前候选截图、具体区域和可观察事实。逐项审阅玩家幻想、核心玩具、行动召唤、选中/错误/提示/购买/成功/失败反馈、奖励期待、情绪峰值、移除文字后的场景用途与狐狸主题、角色/图标/面板/按钮/光源/材质/描边/色彩一致性、主页/关卡/藏品/签到/排行榜/锦标赛/挑战的场景差异，以及开发口径残留。任一核心项缺证、明显失败或只有主观声明时不得进入 V3。

以下候选默认至少登记 P1/P2 并退回 V2；根因在信息结构、布局几何、资源槽或页面模板时提交结构修订包退回 V1：后台/表单/工具应用/PPT/网页模板感，无职责大空白，多页面同“标题 + 白卡片 + 灰按钮”，主要识别依赖通用线性工具图标，材质体系割裂，成功失败只换文字或小图，玩法页缺少专属视觉对象，以及仅给灰盒增加圆角、阴影、渐变和插画的伪高保真。结构修订必须保持功能语义、业务状态、交互语义和状态所有权；美术不得改玩法。

V2a/V2b 必须由非作者独立美术执行 F2。总控代审只可检查流程和证据完整性，不可单独给出艺术方向或视觉可交付通过；缺少独立美术时标记“专业视觉未验证”并阻断 V3。“用户批准方向”不能替代 V2b；明显审美缺陷、游戏感缺失、开发文案残留和缺证不得提交 F4 豁免。

V2a/V2b 只判断“视觉可交付”；此时尚未产生 V4 文件，不要求“工程可交付”。V4/V5 再以文件、透明边缘、尺寸、锚点、九宫格、性能、加载和响应式证据判断工程可交付。进入 V5 或报告视觉完成时，两类结论必须同时有效。

## 硬要求

1. 适用 V1 时逐状态定义第一视觉目标、玩家/目标/危险/交互/装饰优先级、明度/色彩/轮廓/运动区分、可供性（affordance）、前摇/命中/受击/奖励时序、遮挡、小屏、高速、灰阶和色觉差异阈值；原子资源记录所引用契约的版本、适用范围和有效性。
2. 适用 V1 时前置场景级纹理、图集、帧数、动画采样、内存、包体、过绘、Draw Call 和最大纹理预算；原子资源引用已有适用且有效的预算基线；V3 写入机器清单，V4 只验证。
3. 适用 V2 时依次完成 V2a/V2b，并在 V2b 及所有 V5 提供动态可玩片段或可复现交互轨迹，验证识别、预警、反馈、遮挡和移动端缩小可读性。
4. V3 按资产类型保存可编辑源文件和运行时输出。只有 AI 合成栅格路线使用框选拆分；不得将整张效果图作为交互场景。
5. V4 的 `accepted` 资源具备唯一 ID、纹理键、输出路径、可编辑来源或生成记录、授权、运行时输出、Phaser 证据和玩法视觉证据。
6. V5 使用独立 GameObject、命名容器、图层和布局/表现数据结构化集成，并清除低保真代码、资源、纹理键和引用。

## 视觉 QA

同条件截图记录视口、设备像素比、状态、轨迹、语言、ROI、容差、动态时间采样/稳定帧与遮罩理由。并排、叠加和像素差是工具，不是唯一结论；生成式内容、动画和 VFX 必须结合动态时序、可读性和遮挡判断。

UI 同时执行精准布局契约。装饰满幅背景只适用于屏幕空间无交互背景；世界空间关卡、Tilemap、碰撞和玩法环境必须走相应资产路线。

## 完成审计

完成报告必须回答：

1. V0 类型与路径是什么？重做类任务是否错误跳过 V2？
2. 本任务产出的 V1 契约/预算或原子资源引用的既有基线在哪里？
3. V2a/V2b 的候选版本、截图、具体区域、可观察事实和 P0-P3 结论在哪里？
4. 第一视觉焦点、玩家幻想、核心玩具、行动召唤、反馈强度、奖励期待、情绪峰值和狐狸主题分别由哪些事实证明？
5. 主页、关卡、藏品、签到、排行榜、锦标赛和挑战如何形成差异？是否存在应用模板感或无职责大空白？
6. V2a/V2b 的非作者独立美术是谁？缺失时是否标记“专业视觉未验证”并阻断 V3？
7. 候选画面是否残留“未实现”“本地演示”“操作未启用”、stable ID、调试说明或其他开发口径？
8. 适用 V2 与 V5 的动态轨迹在哪里？
9. V3 路线、可编辑来源和机器清单在哪里？
10. V4 的非作者 F2、授权、Phaser、预算和工程可交付证据在哪里？
11. V5 的协作所有权、集成 F1、适用时 F3 和低保真清理证据在哪里？
12. 当前视觉可交付与工程可交付结论是否同时有效？哪些事项按规则进入 F4？

任一适用证据缺失标记未验证，不进入 F4 兜底。
