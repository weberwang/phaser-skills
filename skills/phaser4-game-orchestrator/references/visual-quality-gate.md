# 视觉质量门

视觉领域规则只能收紧 [`phaser4-game-workflow-control`](../../phaser4-game-workflow-control/SKILL.md)。V0-V5 是 `stageId`；全局状态、审批与 F0-F4 语义不得改写。

## 路径

- V0 分流原子资源、组件/资源集、场景/整套 UI/视觉系统/参考还原。
- V1 建立玩法视觉契约、低保真、布局合同和早期预算。当前对象审批只覆盖结构、交互与布局意图。
- V2 建立并冻结视觉方向、高保真和动态样片。方向审批不授权 V3/V4 正式资源。
- V3 形成生产规格、可编辑来源、运行时输出和机器清单；进入实施前冻结 Implementation Package。
- V4 生产正式资源并由独立美术完成资源与跨资源 F2。
- V5 结构化集成、动态玩法视觉验证、响应式证据和低保真清理；资源批准不授权 Scene 或玩法代码。

原子资源只有在结构、交互、布局和视口行为不变，且现有契约、两类对象审批、冻结基线、预算和证据均适用当前范围时才可从 V3 开始。任一引用失效即升级路径。

## 统一门

- F0：Work Item、审批、A 等级、路径、基线、模块门与停止门合规。
- F1：候选与已批准视觉需求、阶段对象、范围和 Implementation Package 一致。
- F2：独立审查视觉方向、可读性、游戏感、资源质量、跨资源一致性、授权与布局质量。
- F3：绑定当前代码/diff 的动态轨迹、响应式测量、清单校验、加载、构建、性能和测试证据。
- F4：当前 V5 候选的精确集成决定；发布必须转入独立发布 Work Item。

两类视觉对象审批使用 Approval Ledger 的当前明确下一门，不得误记为可以扩展到生产或集成的 blanket F4。静态图、像素接近、资源齐全或构建成功都不能单独证明完成。

## 失效与返回

需求或结构变化返回 V1；方向/基线变化返回 V2；生产规格或绑定变化返回 V3；资源执行偏差返回 V4；运行态问题返回 V5。模块边界变化强制模块门与 grilling。任何基线、范围、路径、对象或代码/diff 指纹变化都会让覆盖事实的审批与证据失效。
