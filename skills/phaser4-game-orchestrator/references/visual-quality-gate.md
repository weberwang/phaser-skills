# 视觉质量硬门

本门禁判断最终运行中的玩法视觉，不被静态效果图、像素接近、资源齐全、源码结构或构建结果替代。

## V0 路径

- 原子资源：视觉方向已冻结、结构/交互/布局不变，并有适用、有效、绑定版本且覆盖当前范围的玩法视觉契约、高保真效果图确认记录、视觉可交付结论、冻结全局视觉基线与预算基线可引用的单个或小批同类正式资源，走 V3-V5；缺少任一可引用基线或确认记录时升级组件/资源集或场景路径。
- 组件/资源集：走 V1-V5；候选定义或改变用户可见高保真形态时执行 V2a/V2b、出口确认，V4 做非作者 F2，V5 做 F3。
- 场景、整套 UI、视觉系统、参考还原及所有重做、重新设计、提升游戏感、替换整套 UI 任务：走完整 V1-V5，必须执行 V2a/V2b 与出口确认，V3/V4 做非作者 F2，V5 做 F3。
- 快速通道：不新增正式资源、不改变方向、拆分、结构、交互或布局的局部修复，只做 F0/F1。

F3 只处理集成或跨域风险。F4 只处理受保护决策；适用 V2 的出口高保真效果图用户确认是强制受保护决策例外，但不能豁免专业缺陷。

任何“重做、重新设计、提升游戏感、替换整套 UI”任务都不得当作原子资源跳过 V2。场景、整套 UI、视觉系统、参考还原和重做类任务必须执行 V2a/V2b 与出口确认；组件/资源集只要适用 V2 且候选定义或改变用户可见高保真形态也必须执行。原子资源只能继承当前适用、有效且绑定版本的确认记录与视觉可交付基线。

## 游戏感与视觉可交付

V2 必须完整执行美术角色的 [游戏感质量硬门](../../phaser4-game-asset-integration/references/game-feel-quality-gate.md)，并在同一 V2 阶段内保留两个不可省略的检查点：`V2a 方向基准`与 `V2b 整体视觉审阅`。不得新增 V 阶段或用 V3/V4 证据反向替代 V2。

重做类任务在 V2a 正式基准前至少提交 3 个在构图、场景容器、核心焦点、材质或情绪上有实质差异的方向，不得只换色。每个方向分别说明玩家幻想、核心玩具、主要交互、奖励表达和状态扩展。严格参考复刻可免三方向，但必须保留同条件参考/候选对比和差异说明。

V2a/V2b 的每个核心结论必须引用当前候选截图、具体区域和可观察事实。逐项审阅玩家幻想、核心玩具、行动召唤、选中/错误/提示/购买/成功/失败反馈、奖励期待、情绪峰值、移除文字后的场景用途与狐狸主题、角色/图标/面板/按钮/光源/材质/描边/色彩一致性、主页/关卡/藏品/签到/排行榜/锦标赛/挑战的场景差异，以及开发口径残留。任一核心项缺证、明显失败或只有主观声明时不得进入 V3。

以下候选默认至少登记 P1/P2 并退回 V2；根因在信息结构、布局几何、资源槽或页面模板时提交结构修订包退回 V1：后台/表单/工具应用/PPT/网页模板感，无职责大空白，多页面同“标题 + 白卡片 + 灰按钮”，主要识别依赖通用线性工具图标，材质体系割裂，成功失败只换文字或小图，玩法页缺少专属视觉对象，以及仅给灰盒增加圆角、阴影、渐变和插画的伪高保真。结构修订必须保持功能语义、业务状态、交互语义和状态所有权；美术不得改玩法。

V2a/V2b 必须由非作者独立美术执行 F2。总控代审只可检查流程和证据完整性，不可单独给出艺术方向或视觉可交付通过；缺少独立美术时标记“专业视觉未验证”并阻断 V3。“用户批准方向”不能替代 V2b；明显审美缺陷、游戏感缺失、开发文案残留和缺证不得提交 F4 豁免。

V2a/V2b 与独立美术 F2 只形成“专业视觉通过”的预结论；此时尚未产生 V4 文件，不要求“工程可交付”，也未获得进入 V3 的最终放行。只有当前候选取得下述高保真效果图用户确认后，才能形成绑定确认记录的“视觉可交付”结论。V4/V5 再以文件、透明边缘、尺寸、锚点、九宫格、性能、加载和响应式证据判断工程可交付。进入 V5 或报告视觉完成时，两类结论必须同时有效。

## V2 出口：高保真效果图用户确认

V2 出口顺序固定为 `V2a → V2b 与动态样片 → 独立美术 F2 → 总控提交当前候选确认包 → 用户结论`，不得新增 V 阶段编号。确认包必须包含审核/确认 ID、当前候选版本、适用范围、全局视觉基线 ID/版本/风格指纹、代表性高保真效果图与关键状态、动态可玩样片或可复现轨迹、与参考或上一版差异、独立美术 F2 结论、已关闭问题、V3 生产范围及不可逆/返工影响。

记录用户结论、日期、修改意见和适用范围。只有当前版本明确“通过”才形成绑定该确认 ID 的视觉可交付结论并进入 V3；沉默、继续工作、旧版本批准、方向级批准或参考输入均不算通过。“修改后重提”保留旧记录、创建新候选版本，并重做受影响 V2b/F2 后重新提交；“拒绝”按根因退 V2a，结构根因退 V1。明显审美问题、游戏感缺失、动态样片缺失或证据不足必须先修复，不能交给用户兜底。

## 全局视觉控制

所有正式视觉路径执行美术角色的 [全局视觉控制约束](../../phaser4-game-asset-integration/references/global-visual-control.md)。V1 建立全局基线候选，V2a 冻结唯一基线 ID、版本、主锚点、分系统锚点、全局不变量、允许变量与禁止项，并将基线文档完整文件的 SHA-256 作为 `sha256:<64 位小写十六进制>` 风格指纹；V3 将每个资源绑定当前基线；V4 用多资源联系表与同屏截图执行一致性 F2；V5 在目标视口、关键状态和动态时间点验证运行态一致性。`--check-files` 计算结果与指纹不同即视为冻结文档被静默修改。

局部资源不得自行创造新材质、光源、描边、角色比例或图标语法。场景差异必须在全局不变量内通过用途、焦点、专属对象、允许色彩与节奏实现，既不能退化为同一模板，也不能形成不同美术体系。相同关键词、模型、调色板或作者声明不得单独证明一致。

总控只核对基线绑定、版本、风格指纹、锚点与证据完整性；非作者独立美术判断视觉一致性。方向或全局规则漂移退 V2，生产规格、绑定或生成包缺失退 V3，资源执行偏差退 V4，构图/信息层级/资源槽/页面模板/布局结构根因退 V1。冻结基线变更必须提交影响面，标记失效证据，并从最早受影响阶段重验。

## 硬要求

1. 适用 V1 时逐状态定义第一视觉目标、玩家/目标/危险/交互/装饰优先级、明度/色彩/轮廓/运动区分、可供性（affordance）、前摇/命中/受击/奖励时序、遮挡、小屏、高速、灰阶和色觉差异阈值，并建立全局视觉基线候选；原子资源记录所引用契约与冻结基线的版本、适用范围和有效性。
2. 适用 V1 时前置场景级纹理、图集、帧数、动画采样、内存、包体、过绘、Draw Call 和最大纹理预算；原子资源引用已有适用且有效的预算基线；V3 写入机器清单，V4 只验证。
3. 适用 V2 时依次完成 V2a/V2b、动态样片、独立美术 F2 与当前候选高保真效果图确认，并在 V2b 及所有 V5 提供动态可玩片段或可复现交互轨迹，验证识别、预警、反馈、遮挡和移动端缩小可读性。
4. V3 按资产类型保存可编辑源文件和运行时输出。只有 AI 合成栅格路线使用框选拆分；不得将整张效果图作为交互场景。
5. V4 的 `accepted` 资源具备唯一 ID、纹理键、输出路径、与根基线一致的 ID/版本/风格指纹、可编辑来源或生成记录、授权、运行时输出、跨资源一致性、Phaser 证据和玩法视觉证据。
6. V5 使用独立 GameObject、命名容器、图层和布局/表现数据结构化集成，并清除低保真代码、资源、纹理键和引用。

## 视觉 QA

同条件截图记录视口、设备像素比、状态、轨迹、语言、ROI、容差、动态时间采样/稳定帧与遮罩理由。并排、叠加和像素差是工具，不是唯一结论；生成式内容、动画和 VFX 必须结合动态时序、可读性和遮挡判断。

UI 同时执行精准布局契约。装饰满幅背景只适用于屏幕空间无交互背景；世界空间关卡、Tilemap、碰撞和玩法环境必须走相应资产路线。

## 完成审计

完成报告必须回答：

1. V0 类型与路径是什么？重做类任务是否错误跳过 V2？
2. 本任务产出的 V1 契约/预算或原子资源引用的既有基线在哪里？
3. V2a/V2b 的候选版本、截图、具体区域、可观察事实和 P0-P3 结论在哪里？
4. 第一视觉焦点、玩家幻想、核心玩具、行动召唤、反馈强度、奖励期待、情绪峰值和狐狸主题分别由哪些事实证明？
5. 主页、关卡、藏品、签到、排行榜、锦标赛和挑战如何形成差异？是否存在应用模板感或无职责大空白？
6. V2a/V2b 的非作者独立美术是谁？缺失时是否标记“专业视觉未验证”并阻断确认包与 V3？
7. 候选画面是否残留“未实现”“本地演示”“操作未启用”、stable ID、调试说明或其他开发口径？
8. 适用 V2 与 V5 的动态轨迹在哪里？
9. 当前高保真确认包的确认 ID、候选版本、适用范围、基线身份、代表图/关键状态、动态样片、差异、F2、已关闭问题和 V3 影响是否完整？
10. 用户是否对当前版本明确“通过”，并记录日期、意见与适用范围？视觉可交付结论绑定哪个确认 ID？
11. 修改后重提或拒绝是否保留旧记录，并按根因完成版本更新与受影响 V2b/F2、V2a 或 V1 回退？
12. V3 路线、可编辑来源和机器清单在哪里？
13. V4 的非作者 F2、授权、Phaser、预算和工程可交付证据在哪里？
14. V5 的协作所有权、集成 F1、适用时 F3 和低保真清理证据在哪里？
15. 当前视觉可交付与工程可交付结论是否同时有效？哪些事项按规则进入 F4，V2 出口确认例外是否执行？
16. 当前冻结全局基线的 ID、版本、风格指纹、主锚点与分系统锚点在哪里？
17. 每个正式资源如何绑定该基线？跨资源联系表、同屏截图和运行态一致性证据在哪里？
18. 是否存在只能由关键词、模型、调色板或主观声明支持的一致性结论？
19. 基线是否发生变更？失效证据、影响面和从最早阶段开始的重验记录在哪里？

任一适用证据缺失标记未验证，不进入 F4 兜底。
