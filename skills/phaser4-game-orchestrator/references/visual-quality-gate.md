# 视觉质量硬门

本门禁判断最终运行中的玩法视觉，不被静态效果图、像素接近、资源齐全、源码结构或构建结果替代。

## V0 路径

- 原子资源：视觉方向已冻结、结构/交互/布局不变，并有适用、有效、绑定版本且覆盖当前范围的玩法视觉契约、低保真/高保真确认记录、视觉可交付结论、冻结全局视觉基线与预算基线可引用的单个或小批同类正式资源，走 V3-V5；缺少任一项时升级组件/资源集或场景路径。
- 组件/资源集：走 V1-V5；结构/交互/布局变化执行 V1 确认，高保真形态变化执行 V2 确认；各候选先 F0、冻结身份、F1，再做适用 F2，V5 后 F3。
- 场景、整套 UI、视觉系统、参考还原及重做类任务：完整 V1-V5，两道确认强制；各候选先 F0、冻结身份、F1，V2a/V2b、V3/V4 做适用 F2，V5 后 F3。
- 快速通道：符合边界的局部修复仍执行 F0→F1→轻量 F3；记录缺失时升级 V0 路径。

所有候选都由总控执行 F3 收敛；light 可为轻量自检，复杂候选同时汇合集成或跨域风险。F4 只处理受保护决策；V1 低保真与适用 V2 高保真确认是两个独立强制例外。

任何“重做、重新设计、提升游戏感、替换整套 UI”任务都不得当作原子资源跳过 V1/V2。场景、整套 UI、视觉系统、参考还原和重做类任务必须执行两道出口确认；组件/资源集按结构变化与高保真变化分别执行。原子资源只能继承当前适用、有效、绑定版本且覆盖当前范围的两类确认记录与视觉可交付基线。

## V1 出口：低保真草图用户确认

V1 出口采用 [审核漏斗](review-funnel.md#v1-低保真确认) 的固定顺序：`V1 契约/草图或灰盒 → 适用 F0 → 冻结候选身份 → F1 → 必需 F2 → F3 → F4 用户确认 → V2`，不得新增 V 阶段编号。确认仅覆盖结构、交互与布局意图，不批准视觉风格、材质、光影、正式资源质量或最终游戏感。

确认包必须包含审核/确认 ID、当前候选版本、适用范围、功能契约/模块契约版本、低保真草图或运行灰盒路径、关键场景/页面/状态、信息层级、稳定 ID/层级/资源槽、交互区与输入轨迹、布局几何/安全区/断点意图、失败与恢复、明确排除项、待 V2 探索的视觉变量、已关闭问题、进入 V2 的范围及返工影响。用户结论只允许“通过”“修改后重提”或“拒绝”，并记录日期、修改意见与适用范围；沉默、继续工作、旧版本批准、功能范围批准或参考输入均无效。

“修改后重提”按 [候选修订与重提](review-funnel.md#候选修订与重提) 产生新候选、重跑受影响 F0/F1、重开变化事实对应 F2、重新 F3，再重提 F4。“拒绝”按根因留 V1 或退制作契约/GDD；模块边界变化重新审计，仅剩受保护取舍时 grilling。

## 游戏感与视觉可交付

V2 必须完整执行美术角色的 [游戏感质量硬门](../../phaser4-game-asset-integration/references/game-feel-quality-gate.md)，并在同一 V2 阶段内保留两个不可省略的检查点：`V2a 方向基准`与 `V2b 整体视觉审阅`。不得新增 V 阶段或用 V3/V4 证据反向替代 V2。

重做类任务在 V2a 正式基准前至少提交 3 个在构图、场景容器、核心焦点、材质或情绪上有实质差异的方向，不得只换色。每个方向分别说明玩家幻想、核心玩具、主要交互、奖励表达和状态扩展。严格参考复刻可免三方向，但必须保留同条件参考/候选对比和差异说明。

V2a/V2b 的每个核心结论必须引用当前候选截图、具体区域和可观察事实。逐项审阅玩家幻想、核心玩具、行动召唤、选中/错误/提示/购买/成功/失败反馈、奖励期待、情绪峰值、移除文字后的场景用途与狐狸主题、角色/图标/面板/按钮/光源/材质/描边/色彩一致性、主页/关卡/藏品/签到/排行榜/锦标赛/挑战的场景差异，以及开发口径残留。任一核心项缺证、明显失败或只有主观声明时不得进入 V3。

以下候选默认至少登记 P1/P2 并退回 V2；根因在信息结构、布局几何、资源槽或页面模板时提交结构修订包退回 V1：后台/表单/工具应用/PPT/网页模板感，无职责大空白，多页面同“标题 + 白卡片 + 灰按钮”，主要识别依赖通用线性工具图标，材质体系割裂，成功失败只换文字或小图，玩法页缺少专属视觉对象，以及仅给灰盒增加圆角、阴影、渐变和插画的伪高保真。结构修订必须保持功能语义、业务状态、交互语义和状态所有权；美术不得改玩法。

V2a/V2b 必须由非作者独立美术执行只读 F2 并返回结构化结论。总控只可检查流程、候选身份和证据完整性，不可单独给出艺术方向或视觉可交付通过；缺少独立美术时标记“专业视觉未验证”并阻断 V3。“用户批准方向”不能替代 V2b；明显审美缺陷、游戏感缺失、开发文案残留和缺证不得提交 F4 豁免。

V2a/V2b 与独立美术 F2 只形成“专业视觉通过”的预结论；此时尚未产生 V4 文件，不要求“工程可交付”，也未获得进入 V3 的最终放行。只有当前候选取得下述高保真效果图用户确认后，才能形成绑定确认记录的“视觉可交付”结论。V4/V5 再以文件、透明边缘、尺寸、锚点、九宫格、性能、加载和响应式证据判断工程可交付。进入 V5 或报告视觉完成时，两类结论必须同时有效。

## V2 出口：高保真效果图用户确认

V2 出口采用 [审核漏斗](review-funnel.md#v2-高保真确认) 的固定顺序：`V2a → V2b/动态样片 → 适用 F0 → 冻结候选身份 → F1 → 独立美术及其他必需 F2 → F3 → F4 用户确认 → V3`，不得新增 V 阶段编号。

记录用户结论、日期、意见和范围。只有当前候选“通过”才形成视觉可交付；修改后按统一候选修订规则重跑受影响 F0/F1、重开变化事实对应 F2、重新 F3，再重提 F4；拒绝按根因退 V2a 或 V1。低保真确认不能跳过高保真专业与人工门禁。

## 全局视觉控制

所有正式视觉路径执行美术角色的 [全局视觉控制约束](../../phaser4-game-asset-integration/references/global-visual-control.md)。V1 建立全局基线候选，V2a 冻结唯一基线 ID、版本、主锚点、分系统锚点、全局不变量、允许变量与禁止项，并将基线文档完整文件的 SHA-256 作为 `sha256:<64 位小写十六进制>` 风格指纹；V3 将每个资源绑定当前基线；V4 用多资源联系表与同屏截图执行一致性 F2；V5 在目标视口、关键状态和动态时间点验证运行态一致性。`--check-files` 计算结果与指纹不同即视为冻结文档被静默修改。

局部资源不得自行创造新材质、光源、描边、角色比例或图标语法。场景差异必须在全局不变量内通过用途、焦点、专属对象、允许色彩与节奏实现，既不能退化为同一模板，也不能形成不同美术体系。相同关键词、模型、调色板或作者声明不得单独证明一致。

总控只核对基线绑定、版本、风格指纹、锚点与证据完整性；非作者独立美术判断视觉一致性。方向或全局规则漂移退 V2，生产规格、绑定或生成包缺失退 V3，资源执行偏差退 V4，构图/信息层级/资源槽/页面模板/布局结构根因退 V1。冻结基线变更必须提交影响面，标记失效证据，并从最早受影响阶段重验。

## 硬要求

1. 适用 V1 时逐状态定义第一视觉目标、玩家/目标/危险/交互/装饰优先级、明度/色彩/轮廓/运动区分、可供性（affordance）、前摇/命中/受击/奖励时序、遮挡、小屏、高速、灰阶和色觉差异阈值，并建立全局视觉基线候选；完成必要低保真草图或灰盒并取得当前版本低保真确认后才能进入 V2。原子资源记录所引用契约、低保真确认与冻结基线的版本、适用范围和有效性。
2. 适用 V1 时前置场景级纹理、图集、帧数、动画采样、内存、包体、过绘、Draw Call 和最大纹理预算；原子资源引用已有适用且有效的预算基线；V3 写入机器清单，V4 只验证。
3. 适用 V2 时依次完成 V2a/V2b、动态样片、独立美术 F2 与当前候选高保真效果图确认，并在 V2b 及所有 V5 提供动态可玩片段或可复现交互轨迹，验证识别、预警、反馈、遮挡和移动端缩小可读性。
4. V3 按资产类型保存可编辑源文件和运行时输出。只有 AI 合成栅格路线使用框选拆分；不得将整张效果图作为交互场景。
5. V4 的 `accepted` 资源具备唯一 ID、纹理键、输出路径、与根基线一致的 ID/版本/风格指纹、可编辑来源或生成记录、授权、运行时输出、跨资源一致性、Phaser 证据和玩法视觉证据。
6. V5 使用独立 GameObject、命名容器、图层和布局/表现数据结构化集成，并清除低保真代码、资源、纹理键和引用。

## 响应式视觉审计路由

响应式契约、适用范围和 V1-V5 门禁的唯一详细规则见总控的
[`phaser4-game-ui-layout` 布局合同](../../phaser4-game-ui-layout/references/layout-contract.md)；本文件只并列核对以下
审计重点，不复制字段或阈值：

- V1 是否冻结浏览器 viewport、Canvas、逻辑坐标和 safe area 四层关系，FIT/
  RESIZE/COVER/响应式锚点/断点重排、背景覆盖目标、留白/裁切/拉伸许可，以及
  基准/最窄/最宽/横屏/安全区和动态行为矩阵。
- V2 是否用同一页面的动态可玩样片覆盖矩阵；只有基准静态图时阻断 V3。
- V4/V5 是否由非作者以完整 viewport 证据验证资源满幅能力、生产场景实际覆盖、
  安全区、层级、最小可读性、多比例重锚定、间距、显隐、滚动和 resize；缺完整
  viewport 证据只标记“未验证”。
- FIT 结论不得被写成满屏或响应式重排通过；Canvas ROI、逻辑画布、背景不溢出和
  构建成功只能作为补充证据。

测量字段、假通过禁令、只读 Hook、脚本用法和根因分类统一引用 QA 的
[响应式视觉验证](../../phaser4-game-qa-performance/references/responsive-visual-validation.md)。

## 视觉 QA

同条件截图记录视口、设备像素比、状态、轨迹、语言、ROI、容差、动态时间采样/稳定帧与遮罩理由。并排、叠加和像素差是工具，不是唯一结论；生成式内容、动画和 VFX 必须结合动态时序、可读性和遮挡判断。

UI 同时执行 [`phaser4-game-ui-layout`](../../phaser4-game-ui-layout/SKILL.md) 的通用布局合同。合同负责坐标空间、相对锚点、尺寸、断点、安全区、滚动、动态文案、遮挡回退和证据矩阵；本门只判断视觉结果。装饰满幅背景只适用于屏幕空间无交互背景；世界空间关卡、Tilemap、碰撞和玩法环境必须走相应资产路线。

## 完成审计

完成报告必须回答：

1. V0 类型与路径是什么？重做类任务是否错误跳过 V1/V2？
2. 本任务产出的 V1 契约/预算或原子资源引用的既有基线在哪里？当前低保真确认 ID、候选版本、范围和有效性是什么？
3. 低保真确认包是否覆盖契约版本、草图/灰盒、关键状态、信息层级、稳定 ID/层级/资源槽、交互与输入、布局/安全区/断点、失败恢复、排除项、待 V2 变量、已关闭问题与返工影响？用户是否明确“通过”？
4. V2a/V2b 的候选版本、截图、具体区域、可观察事实和 P0-P3 结论在哪里？
5. 第一视觉焦点、玩家幻想、核心玩具、行动召唤、反馈强度、奖励期待、情绪峰值和狐狸主题分别由哪些事实证明？
6. 主页、关卡、藏品、签到、排行榜、锦标赛和挑战如何形成差异？是否存在应用模板感或无职责大空白？
7. V2a/V2b 的非作者独立美术是谁？缺失时是否标记“专业视觉未验证”并阻断确认包与 V3？
8. 候选画面是否残留“未实现”“本地演示”“操作未启用”、stable ID、调试说明或其他开发口径？
9. 适用 V2 与 V5 的动态轨迹在哪里？
10. 当前高保真确认包的确认 ID、候选版本、适用范围、基线身份、代表图/关键状态、动态样片、差异、F2、已关闭问题和 V3 影响是否完整？
11. 用户是否对当前版本明确“通过”，并记录日期、意见与适用范围？视觉可交付结论绑定哪个确认 ID？
12. 修改后重提是否产生新候选，重跑受影响 F0/F1、重开变化事实对应 F2、重新 F3 后再重提 F4？
13. V3 路线、可编辑来源和机器清单在哪里？
14. V4 的非作者 F2、授权、Phaser、预算和工程可交付证据在哪里？
15. V5 的协作所有权、实际 F0 命令与动态集成证据、F1 分诊、F3 收敛和低保真清理在哪里？
16. 当前低保真确认、视觉可交付与工程可交付结论是否同时有效？哪些事项按规则进入 F4，V1/V2 两道出口确认例外是否独立执行？
17. 当前冻结全局基线的 ID、版本、风格指纹、主锚点与分系统锚点在哪里？
18. 每个正式资源如何绑定该基线？跨资源联系表、同屏截图和运行态一致性证据在哪里？
19. 是否存在只能由关键词、模型、调色板或主观声明支持的一致性结论？
20. 基线是否发生变更？失效证据、影响面和从最早阶段开始的重验记录在哪里？

任一适用证据缺失标记未验证，不进入 F4 兜底。
