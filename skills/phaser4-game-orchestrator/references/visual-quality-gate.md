## 通道判定

出现“重做、重新设计、高保真、复刻、还原参考图、对齐截图、提升细节、替换整套 UI、正式美术”任一目标，或实际工作包含成套视觉重做、正式资源替换、资源重新拆分、参考截图/录屏/效果图还原时，强制进入标准通道并完整执行 A1 至 A6。模块边界、交互和状态所有权不变，不构成降级理由。

快速通道仅允许以下不改变视觉方向、不新增正式资源、不改变资源拆分的局部修复：

- 已批准正式资源的尺寸、锚点、采样或九宫格小修；
- 单个动态文本、间距、颜色或低风险显示缺陷；
- 能以现有批准资源完成、影响范围明确且可回退的局部修复。

任务描述含强制标准通道目标时，不得再以“模块不变”“只是 UI”“可以代码绘制”“先快速接近”或“已有参考图”为由进入快速通道。任务执行中一旦新增正式资源、改变资源拆分或扩大视觉方向，立即升级标准通道并从 A1 开始；已有局部实现不能抵扣任何阶段。

## 人工确认记录

用户提供的参考截图、录屏、效果图、现有页面或“按这个实现”指令只属于参考输入和目标方向，不是 A1、A2、A4、A5 或 A6 的确认。继续任务、未提出异议、批准其他阶段、批准旧版本或批准代表性样张，也不能推断当前阶段通过。

每个人工确认门必须保存针对当前阶段产物的可追溯记录，至少包含：

- 阶段、产物 ID/路径和版本；
- 提交确认的时间或记录位置；
- 人工对当前产物的明确答复；
- 结论是“通过”“修改后重提”或“拒绝”；
- 适用范围、保留意见和批准人可识别信息。

只有记录明确指向当前版本且结论为“通过”时，文档才可写“用户已批准”。缺少答复或记录时状态只能是“待人工确认”或“未验证”。A2、A4、A5 的确认互不替代；A6 运行验收也不能由此前任何批准推断。

## 正式资源与代码绘制边界

`Phaser.Graphics` 只允许用于动态进度、遮罩、点击区域、简单线条、调试显示、无明显材质要求的基础几何，以及无法预先烘焙的实时变化。点击区域和遮罩如果不应可见，必须保持为非视觉对象；调试显示不得进入正式候选画面。

参考图中具有明显材质、体积、纹理、复杂高光、内外阴影、装饰花纹或角色化造型的下列对象，不得以 `Phaser.Graphics` 作为正式高保真实现：

- 主面板和成套弹窗外壳；
- 复杂按钮底图；
- 道具和商品图标；
- 徽章、折扣牌和礼包装饰；
- 翅膀、爱心、金币堆等插画对象；
- 承担主要视觉识别的其他 UI 元素。

这些对象必须进入 A4 完整单图清单，并在 A5 以正式透明位图、九宫格、序列帧或获批准的矢量资源交付。所有计划保留的代码绘制对象也必须列入 A4，结论标为“代码绘制”，并记录其符合允许范围的理由；无法给出理由时改为正式资源。

## A4 与 A5 证据契约

A4 必须同时交付：

1. 不覆盖原效果图的带唯一编号框选图；
2. 覆盖所有可见对象和状态变体的完整单图清单；
3. 每个对象的用途、目标尺寸、透明要求、锚点、九宫格参数和纹理键；
4. 动画帧、状态、复用关系、遮挡补全和来源要求；
5. “代码绘制、复用、新生成、重绘、删除”五类之一的明确结论；
6. 指向当前版本的 A4 人工确认记录。

A5 必须同时交付：

1. 清单中每个正式资源的实际文件；
2. 资源登记、来源版本、授权/生成记录、交付路径和纹理键；
3. 深色与浅色背景上的透明边缘检查；
4. Phaser 实际加载与缩放截图；
5. 目标视口中的运行证据；
6. 尺寸、锚点、九宫格、采样、帧序和性能检查；
7. 未完成与未验收资源清单，清单为空时也要明确记录；
8. 指向当前文件版本的 A5 人工确认记录。

任何主要视觉对象缺少 A4 处置结论、正式文件、登记、Phaser 验证或 A5 确认时，不得进入 A6，不得报告“高保真完成”或“视觉还原通过”。

## UI 精准布局

UI 任务必须完整执行 `ui-layout-precision.md`。A1 为每个组件冻结父级坐标系、参照物、参照与自身停靠点、水平/垂直距离、尺寸策略、横纵布局组、安全区、方向/断点和误差阈值；A2、A3 沿用并按参照线审阅这些几何关系；A6 通过统一布局入口从契约值计算，不得以无语义的孤立屏幕坐标或逐屏手调替代。

只修改已有契约中的单个距离或间距、影响明确且可回退时可走快速通道。改变参照物、停靠边、坐标系、布局组、换行、安全区或响应式策略时进入标准通道并返回 A1；效果图改变上述布局几何时也必须返回 A1，不能只重新确认 A2。

UI 精度证据必须覆盖基准、最窄、最宽视口、支持方向和代表性安全区，逐组件输出期望与实测边界、中心和间距，并检查动态文本、成员显隐、关键状态与 resize 后重排。缺少布局契约、超过已批准误差、出现重复项累计漂移或安全区越界时，视觉结果不得通过。

## 同条件视觉对比

参考还原的每个检查点必须让参考输入与运行结果使用一致的视口宽高、设备像素比、游戏状态、操作轨迹、文本语言和动画时间点。必须同时保存参考图和运行图，并至少生成一种并排图、叠加图或像素差异图；原图、运行图和对比产物都要可追溯。

视觉验收至少逐项检查：外轮廓与构图、元素位置和尺寸、层级与遮挡、字体/描边/阴影、材质/纹理/高光、图标细节、安全边距、裁切与越界、九宫格变形，以及不同宽度下的等比缩放。参考图和运行图的视口或其他必需条件不一致时只能标记“未验证”，不得标记通过。

以下证据不能单独证明视觉通过：搜索源码方法名、检查固定坐标字符串、TypeScript 类型检查、单元测试、生产构建成功、控制台无错误、主观描述“看起来接近”，以及只验证元素存在。源码标记测试只验证结构契约，测试名和报告必须使用“结构回归”，禁止命名或表述为“视觉回归”。

## 完成、撤销与总控审计

只有同时满足以下条件，才可使用“高保真完成”“视觉还原通过”或“A6 完成”：

- A1 至 A5 均有有效证据；
- 所有人工确认门均有指向当前产物的明确记录；
- 正式资源全部登记并通过 Phaser 加载、缩放和目标视口验证；
- 运行时不再使用未批准的低保真替代物；
- 涉及 UI 时布局契约完整，逐组件精度与响应式验证通过；
- 同条件逐状态视觉对比通过；
- 功能契约通过；
- 低保真实现和占位资源已清理；
- 构建与回归测试通过。

人工指出运行结果存在明显细节不足时，立即撤销上述完成状态：结构或状态表达问题退回 A2，漏项或资源拆分问题退回 A4，文件本身的材质、透明边缘、细节、缩放或接入质量问题退回 A5。不得继续以局部坐标调整掩盖资源质量问题；返工后重跑受影响阶段及 A6。

总控在汇报视觉任务完成前必须逐项回答并提供证据链接：

1. 本任务为什么不能或可以进入快速通道？
2. A2、A4、A5 的人工确认记录分别在哪里？
3. 哪些元素使用正式资源，哪些使用代码绘制？
4. 每个代码绘制对象为什么符合允许范围？
5. 参考图和运行图是否使用相同视口及其他必需条件？
6. 视觉测试验证的是结构还是最终画面？
7. 涉及 UI 时，其布局契约、逐组件精度表和响应式证据在哪里？
8. 是否仍有低保真或占位实现？

任一问题无法提供可追溯证据时，结论必须是“未完成”或“未验证”，不得报告完成。
