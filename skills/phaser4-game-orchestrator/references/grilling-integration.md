# 拷问集成

总控在候选物完成 `review-funnel.md` 的适用 F0 至 F3、确有受保护决策需要进入 F4 时执行；适用 V2 的当前高保真效果图出口确认是强制受保护决策例外：

1. 读取审核包、现有文档、实现和证据，确认完整性、技术缺陷和专业问题已在 F0 至 F3 处理，分离事实与取舍。
2. 只有产品范围与体验方向、不可逆或高成本模块边界、视觉方向、预算/授权/合规、风险豁免、目标指标或发布放行仍需人工取舍时才调用 `$grilling`；新建模块、模块首次实现、模块边界变化，以及适用 V2 的出口高保真效果图确认是强制例外。高保真确认只能在 V2b、动态样片、独立美术 F2 和专业问题关闭后提交，不能豁免明显审美问题或缺证。相关低风险默认项可组成一个决策包，高影响、相互依赖或冲突项逐项询问，并给出影响、推荐项和理由。
3. 未获结论前仅冻结直接受影响范围；无依赖工作继续。确认后才改对应需求、实现、资源或发布状态。
4. 在 docs/control-plane.md 记录审核/确认 ID、候选版本、适用范围、触发原因、事实、问题、结论日期、修改意见、影响和下一步；将细节写入受影响交付物。高保真确认结论只允许“通过”“修改后重提”或“拒绝”：只有当前版本明确“通过”才放行 V3；修改后重提保留旧记录、创建新版本并重做受影响 V2b/F2；拒绝按根因退 V2a 或 V1。沉默、继续任务、方向级批准或其他候选版本的批准不得推断为本次 F4 通过。

功能增删、优先级或验收变化、渠道或能力开关变化、技术或数值路线变化、模块职责/契约/状态所有权/依赖方向变化、视觉/资源变化、质量指标变化和发布豁免，均按需求修改处理。影响既有质量门时标为待复核，并从最早失效的 F 层重新筛选，不直接回到人工。
