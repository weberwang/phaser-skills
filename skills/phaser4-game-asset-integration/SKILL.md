# Phaser 4 美术接入

让视觉资源服务体验，并满足移动端性能和上架权属要求。

快速通道仅读取任务直接相关的资源、代码、规格和验证；标准、发布通道读取 docs/project-profile.yaml、docs/GDD.md、docs/TDD.md、docs/control-plane.md，美术流从 A1 启动时读取 docs/asset-license-register.md，已有性能计划时再读取 qa-plan。视觉方向、生成式资源、授权、预算或发布资格需取舍时，向总控提交决策包，等待其完成决策门禁。

1. 新建或重做场景、界面、预制体或成套视觉资源时，完整读取并严格顺序执行 [references/visual-production-pipeline.md](references/visual-production-pipeline.md)；任何人工确认门未通过时，只返工当前阶段，不得提前生成下游产物。
2. 进入单图生成阶段后，完整读取 [references/effect-image-splitting.md](references/effect-image-splitting.md)，只以已确认的框选效果图和单图清单作为输入；效果图只作为视觉来源，不得直接冒充可接入资源。
3. 在资源登记中为每个单图维护唯一拆分 ID、来源效果图版本、状态、用途、规格与锚点、交付路径与纹理键、授权或生成记录、发布资格和 Phaser 验证。开工前先查重；已有完整且验证有效的产物时直接复用，不得重复生成。
4. 按已确认的低保真结构、玩法资源依赖清单和 TDD 接入单图、图集、动画和 UI，避免重复纹理、无界尺寸、无效透明区域与采样溢色，并在目标设备验证。玩法反馈问题时，修复受影响资源、更新登记并交回复验。
5. 正式结构化预制体或场景验收通过后，确认运行时不再引用低保真代码、资源和纹理键，再删除低保真实现；保留结构说明、确认记录和验证证据。
6. 标准、发布通道在控制面追加当前美术门、证据或阻断项；快速通道仅在产生未决决策或阻断项时追加。

向玩法提供已确认的低保真结构、框选效果图、单图清单、复用项、规格、锚点、纹理键和路径约定，并接收游戏内实测问题形成修复回路；向测试提供各确认门、逐图检查、正式装配和低保真清理证据；向发布提供权属清单。任一前置门、正式资源验证、结构化装配或低保真清理未完成时，不得标为可交付。
