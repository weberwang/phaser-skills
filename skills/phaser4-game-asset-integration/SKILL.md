# Phaser 4 美术设计与接入

让视觉资源服务体验，并满足移动端性能和上架权属要求。

快速通道只处理已批准正式资源的尺寸、锚点、采样或九宫格小修，单个动态文本、间距、颜色或低风险显示缺陷，以及不改变视觉方向、不新增正式资源、不改变资源拆分的局部修复；仅读取直接相关的资源、代码、规格和验证。凡包含重做、重新设计、高保真、复刻、还原参考图、对齐截图、提升细节、替换整套 UI 或正式美术目标，或实际涉及成套视觉重做、正式资源替换、参考图还原，一律进入标准通道并完整执行 A1 至 A6，即使模块边界、交互和状态所有权不变也不得降级。标准、发布通道读取总控 [多级漏斗审核](../phaser4-game-orchestrator/references/review-funnel.md) 以及 docs/project-profile.yaml、docs/GDD.md、docs/visual-design.md、docs/TDD.md、docs/control-plane.md，美术流从 A1 启动时读取 docs/asset-license-register.md，已有性能计划时再读取 docs/qa-plan.md。视觉方向、授权、预算或发布资格需取舍时，只有完成 F1 至 F3 后才向总控提交最小 F4 决策包。

1. 在 `docs/visual-design.md` 冻结风格关键词、色彩、字体、造型、场景、UI、图标、动画、特效、技术约束、禁用方向和代表性基准画面；视觉基线未获人工批准时，不得批量生成正式资源。
2. 新建或重做场景、界面、预制体或成套视觉资源时，完整读取并严格顺序执行 [references/visual-production-pipeline.md](references/visual-production-pipeline.md)；当前 A 阶段的适用漏斗层未通过时，只返工当前阶段，不得提前生成下游产物。
3. 需要适配不同宽高比、消除黑边或制作场景背景时，完整读取 [references/full-bleed-background.md](references/full-bleed-background.md)。在 A2 高保真阶段优先生成无交互满幅背景，通过 F2/F3；视觉方向变化时再取得 F4 结论，然后通过统一适配器应用到每个可见场景。
4. 输入是参考截图、录屏、现有界面、运行场景或源代码且需要还原时，完整读取 [references/visual-reconstruction.md](references/visual-reconstruction.md)。要求制作策划和玩法先建立参考功能契约；将固定视口截图、操作轨迹、对象与功能清单以及代码绘制/复用/新生成/重绘/删除结论纳入 A1，将代表性样张纳入 A2，随后继续 A3 至 A6，并保留同条件逐状态视觉对比与功能复现证据。
5. 进入单图生成阶段后，完整读取 [references/effect-image-splitting.md](references/effect-image-splitting.md)，只以 A4 已通过漏斗的框选效果图和单图清单作为输入；效果图不得直接冒充可接入资源。
6. 在资源登记中为每个背景、重构项和单图维护唯一 ID、输入/来源版本、状态、用途、规格与锚点/焦点、交付路径与纹理键、授权或生成记录、发布资格和 Phaser 验证。开工前先查重；已有有效同规格产物时直接复用。
7. A4 必须交付带编号框选图和完整单图清单，每个对象记录用途、尺寸、透明要求、锚点、九宫格、纹理键，并明确“代码绘制、复用、新生成、重绘、删除”结论。A5 必须交付每个正式资源的实际文件、登记与来源、深浅背景透明边缘检查、Phaser 加载与缩放截图、目标视口运行证据及未完成/未验收资源清单。任一主要视觉对象缺少正式资源或验收时不得进入 A6。
8. `Phaser.Graphics` 只允许用于动态进度、遮罩、点击区域、简单线条、调试显示、无明显材质要求的基础几何和无法预先烘焙的实时变化。主面板/成套弹窗外壳、复杂按钮底图、道具/商品图标、徽章/折扣牌/礼包装饰、翅膀/爱心/金币堆等插画对象及主要识别 UI，如有明显材质、体积、纹理、复杂高光、内外阴影、装饰花纹或角色化造型，必须进入 A4 并由正式透明位图、九宫格、序列帧或获批准矢量资源完成 A5。
9. 按已通过漏斗的低保真结构、背景规则、资源依赖清单和 TDD 交付通过 A5 的正式资源、资源登记与接入契约，并配合玩法在目标设备验证黑边、输入、尺寸、锚点、焦点、帧序、九宫格、采样和性能问题。美术角色不修改正式场景或预制体的玩法代码。
10. A6 的结构化装配和低保真实现删除由玩法角色独占执行；美术角色只审阅视觉一致性、资源使用与背景覆盖证据，发现资源问题时退回 A5。
11. 标准、发布通道向总控提交审核 ID、候选版本、当前 A 阶段、F1/F2 证据、需要 F3 处理的跨域问题和按需 F4 决策包，由总控更新控制面；快速通道提交 F0/F1 结果。

参考输入和“按这个实现”不构成漏斗审核结论；继续任务、未提出异议、批准其他阶段或旧版本也不得推断通过。只有 F4 可追溯记录明确指向当前候选版本时才允许写“用户已批准”；未触发 F4 的客观事项写对应 F 层通过。

向架构和玩法提供已通过漏斗的视觉基线、背景覆盖规则、低保真结构、框选效果图、单图清单、复用项、规格、锚点/焦点、纹理键和路径约定；向测试提供 A1 至 A5 的 F1/F2 证据、全场景宽高比、逐状态视觉对比和逐图检查证据，并审阅玩法提交的参考功能复现、A6 正式装配与低保真清理证据；向发布提供权属清单。功能契约、适用审核层、背景覆盖、正式资源验证、结构化装配或低保真清理任一未完成时，不得标为可交付。人工指出明显细节不足时立即撤销上述状态，先归因到 F1/F2/F3，再按问题退回 A2、A4 或 A5。
