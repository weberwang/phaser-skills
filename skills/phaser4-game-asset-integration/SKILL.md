# Phaser 4 游戏美术生产与接入

## 工作流

1. 读取项目配置、GDD、visual-design、TDD、控制面和资源登记；执行 [V0-V5 视觉生产管线](references/visual-production-pipeline.md)。
2. V0 先判断任务属于原子资源、组件/资源集，还是场景/整套 UI/视觉系统/参考还原，再选择规定路径。原子资源只有在结构、布局、交互不变，且已有适用、有效、绑定版本并覆盖当前范围的玩法视觉契约、低保真/高保真确认记录、视觉可交付结论与预算基线可引用时才能跳过 V1/V2；否则升级为组件/资源集或场景路径。“重做、重新设计、提升游戏感、替换整套 UI”不得按原子资源跳过 V1/V2。快速通道也只有在结构、布局、交互不变且既有低保真确认仍有效时才可使用。
3. 适用 V1 时建立玩法视觉契约、必要低保真草图或可运行灰盒和早期预算；相关玩法/架构/UI 布局证据与可判定问题关闭后，总控提交当前低保真候选确认包，用户明确“通过”后才进入 V2。原子资源则记录所引用基线、两类确认记录及有效性。读取 [玩法视觉契约](references/gameplay-visual-contract.md)。V1 建立、V2a 冻结 [全局视觉控制约束](references/global-visual-control.md) 的单一版本化基线；V2 另行执行 [游戏感质量硬门](references/game-feel-quality-gate.md) 的 V2a 方向基准、V2b 整体视觉审阅、独立美术 F2 和出口高保真效果图用户确认。低保真批准不能替代任何 V2 步骤；静态效果图、像素接近和资源齐全都不能证明游戏性。
4. V3 按 [资产生产路线](references/asset-production-routes.md) 选择可编辑源文件、运行时输出和机器清单，每个资源绑定当前基线 ID、版本、风格指纹和锚点。只有选择 AI 合成栅格路线时才读取 [效果图拆分](references/effect-image-splitting.md)。
5. V4 生产正式资源并逐项验证来源、授权、预算、基线绑定、跨资源联系表、同屏一致性、Phaser 加载和玩法视觉证据。运行 `scripts/validate_visual_manifest.py` 检查 `docs/visual-assets.json`。
6. V5 与玩法协作完成结构化集成、运行态全局一致性、动态玩法视觉验收和低保真清理。玩法独占规则、状态和交互代码；美术可维护纯表现资源配置、布局/表现预制数据和视觉集成调整，但不得改变玩法规则。

## 条件参考

- 参考截图、录屏、运行项目或源码还原：读取 [视觉还原](references/visual-reconstruction.md)。
- 装饰性屏幕空间满幅背景：读取 [满幅背景](references/full-bleed-background.md)；世界空间关卡、Tilemap 或玩法环境改读资产生产路线。
- UI：同时读取 [`phaser4-game-ui-layout`](../phaser4-game-ui-layout/SKILL.md) 的布局合同、Phaser 适配器和证据矩阵；资源 origin、布局锚点与动画偏移按合同分离，资产接入不得重新发明布局规则。

## 审核与交付

所有候选先完成适用 F0 并冻结 Git SHA，或记录候选 ID、工件 SHA-256 和绑定代码 SHA，再由总控 F1 分诊。F2 必须由独立非作者只读审阅并返回结构化结论；V2a/V2b 与跨资源一致性必须由独立美术判断，总控只能核对流程、候选绑定和证据完整性，缺独立美术时标记“专业视觉未验证”并阻断下游。场景、整套 UI、视觉系统、参考还原和重做类任务必须执行 V1/V2 两道确认；组件/资源集按结构变化和高保真变化分别触发。总控 F3 收敛后才提交适用 F4 确认包。每个交付包记录候选身份、风险、适用 V/F 路径、确认 ID、基线/风格指纹、锚点、来源、授权、输出、预算、一致性、Phaser 与动态玩法证据。新增或修改的类、函数、实体及复杂逻辑使用简体中文注释。
