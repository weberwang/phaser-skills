# Phaser 4 美术设计与接入

让视觉资源服务体验，并满足移动端性能和上架权属要求。

快速通道仅读取任务直接相关的资源、代码、规格和验证；标准、发布通道读取 docs/project-profile.yaml、docs/GDD.md、docs/visual-design.md、docs/TDD.md、docs/control-plane.md，资源进入制作后读取 docs/asset-license-register.md，已有性能计划时再读取 qa-plan。视觉方向、生成式资源、授权、预算或发布资格需取舍时，向总控提交决策包，等待其完成决策门禁。

1. 在 `docs/visual-design.md` 冻结风格关键词、色彩、字体、造型、场景、UI、图标、动画、特效、技术约束、禁用方向和代表性基准画面；确定尺寸、分辨率、锚点、帧率、图层、九宫格、安全区与本地化要求。视觉基线未获人工批准时，不得批量生成正式资源。
2. 输入是截图、现有界面、运行场景或源代码，且任务包含整理、翻新、统一风格或重新生成美术时，完整读取 [references/visual-reconstruction.md](references/visual-reconstruction.md)，执行“归档输入与权属 → 代码运行/固定视口截图 → 可见对象清单 → 保留/重构/新生成/删除决策 → 代表性样张审查 → 生成/重绘 → 人工确认或修改循环 → 拆分与接入 → 固定视口前后对比”。
3. 输入是包含多个元素的效果图、概念图或界面稿时，执行“效果图拆分为 Phaser 单图”任务，并完整读取 [references/effect-image-splitting.md](references/effect-image-splitting.md)。先提交拆分方案并完成审查，审查未通过不得开始拆图；效果图只作为视觉来源，不得直接冒充可接入资源。
4. 在资源登记中为每个拆分或重构项维护唯一 ID、输入/来源版本、状态、用途、规格与锚点、交付路径与纹理键、授权或生成记录、发布资格和 Phaser 验证。开工前先查重；已有完整且验证有效的同规格产物时直接复用。占位资源标明替换负责人和质量门。
5. 按玩法资源依赖清单和 TDD 接入单图、图集、动画和 UI，避免重复纹理、无界尺寸、无效透明区域与采样溢色，并在目标设备验证。玩法反馈尺寸、锚点、帧序、九宫格或采样问题时，修复受影响资源、更新登记并交回复验。
6. 标准、发布通道在控制面追加资源范围、视觉基线版本、证据或阻断项；快速通道仅在产生未决决策或阻断项时追加。

向玩法提供已批准的视觉基线、人工确认过的重构/拆分清单、复用项、规格、锚点、纹理键和路径约定，并接收游戏内实测问题形成修复回路；向测试提供人工确认记录、固定视口前后对比、预算、逐图检查结果与 Phaser 加载证据，向发布提供权属清单。代表性样张或拆分方案未通过审查不得批量开工；生成/重绘产物未获人工确认不得拆分或接入；输入清单、重复检查、产物验证、视觉一致性或游戏内复验未通过时，不得标为可交付。
