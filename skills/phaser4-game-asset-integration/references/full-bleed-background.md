# 装饰性满幅背景

## 适用边界

只适用于不承载交互、文字、关键目标、碰撞、导航或玩法信息的屏幕空间装饰背景。
世界空间关卡、Tilemap、可交互物、玩法环境和影响遮挡判断的场景层，使用
`asset-production-routes.md` 的场景/Tilemap 或世界/玩法环境路线。

背景在 V1/V2 与关键对象联合确定性机器验证。普通背景在已有明确需求或冻结基线且结构、布局、交互不变时记录 `AUTO`；新方向、裁切焦点或高返工取舍只请求一次选择并记录 `USER_DECISION`。Work Item 指定效果图忠实还原时受[视觉还原](visual-reconstruction.md)约束，参考中的背景焦点、构图和可见裁切是冻结视觉事实；只有不存在可见偏差或实质取舍且处于项目预定义容差内才可 `AUTO`，任何可见裁切、焦点或构图偏差必须形成精确 `USER_DECISION` 并绑定已批准例外。后续绑定当前决策记录。
响应式合同的详细字段和门禁以 [`phaser4-game-ui-layout` 布局合同](../../phaser4-game-ui-layout/references/layout-contract.md) 为准。

## 生产与适配

1. 适用 V1 时定义背景与玩家、目标、危险、交互、装饰的层级关系、焦点安全区、
   对比和遮挡预算，并冻结覆盖目标（viewport、safe area 或仅 Canvas）、裁切焦点、
   运行时覆盖、留白/拉伸和横屏策略；这些是适配器行为，不得替代 ImageGen 归一化合同。
2. 适用 V2 时同时放入关键对象和最高干扰状态，按基准/最窄/最宽/横屏/安全区矩阵
   验证完整 viewport 无非允许留白、背景覆盖、安全区、层级与最小可读性；原子背景
   在 V4 动态轨迹中完成同类验证，只看空背景不能通过。
3. V3 记录可编辑源文件/生成记录、基准尺寸、最大纹理、内存、方向变体、
   裁切和延展规则，明确资源是否有覆盖目标 viewport 的像素/渐变/纹理容量。
4. 使用统一适配器：竖屏通常按高度覆盖、横屏通常按宽度覆盖；具体规则由项目契约
   定义，并保持背景在最低装饰层且不接收输入。
5. V4 确定性机器 F2 **分别**验证资源本身的满幅能力（尺寸、透明边缘、延展/裁切）和
   适配规则；V4/F3 再在生产场景以完整 viewport 验证实际覆盖、safe area、UI 层级、
   动态 resize 和过渡。资源算法验证不是生产集成证据；Canvas ROI 只能补充。

测量字段、Hook 缺失时的“未验证”规则和禁止的假通过方式统一见 QA 的
[响应式视觉验证](../../phaser4-game-qa-performance/references/responsive-visual-validation.md)。

不允许用纯色带、透明缝或复制拉伸掩盖未定义区域；如需生成式扩展，保留生成与编辑
记录。完整背景仅可替代装饰层，不得把交互场景扁平化。

背景 ImageGen 同样消费通用比例修正规则，并非背景专属能力：首次输出比例不符时最多
重生一次，第二次仍不符时，在已冻结焦点和安全事实允许的前提下记录两次真实原始 ImageGen
attempt 后执行 `crop-and-resize-to-contract`，否则先生成式延展到目标比例再普通归一化。透明
路线的 attempts 仍指向去背前的不透明原始输出；受控裁切可在唯一一次背景移除后的同尺寸含
Alpha 输入上执行，生成式延展必须发生在背景移除之前。该规则同样适用于主体、UI、图标和其他
ImageGen 单图；禁止裁切冻结 `reference_target`，也禁止
非等比拉伸、padding、contain 和复制边缘。
