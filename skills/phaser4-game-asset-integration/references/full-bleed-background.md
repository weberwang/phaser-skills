# 无交互满幅背景

当需要消除不同宽高比下的黑边、为一个或多个场景生成纯装饰背景，或把背景接入所有运行时场景时，完整读取本文件。背景只负责覆盖视口和承接视觉氛围，不承载交互、文字、关键目标、碰撞或玩法判定。

## 背景先行

1. 从 `docs/project-profile.yaml`、TDD 和测试矩阵取得支持的方向、最窄与最宽宽高比、基准分辨率、设备像素比、安全区和纹理预算；缺少边界时提交决策包，不以单台开发设备代替目标矩阵。
2. 在生成角色、场景前景、UI 或特效前，先生成全局背景或按视觉族分组的背景。默认分别生成竖屏和横屏版本；仅当同一图片同时满足两种定轴覆盖条件且构图通过验证时才复用。构图保留中心焦点安全区和四周裁切/延展区；裁切区不得放置文字、按钮、关键角色、路线、奖励提示或其他玩法信息。
3. 生成尺寸必须匹配定轴适配：竖屏按高度缩放，图片宽高比不得小于目标竖屏矩阵中最大的 `(viewportWidth + 2 × overscan) / (viewportHeight + 2 × overscan)`；横屏按宽度缩放，图片高宽比不得小于目标横屏矩阵中最大的 `(viewportHeight + 2 × overscan) / (viewportWidth + 2 × overscan)`。无法经济满足时使用“主背景 + 边缘延展层/渐变/可平铺纹理”，不得用纯黑填充空余区域，也不得生成超过目标设备纹理上限的大图。
4. 每轮生成后遵循 `visual-reconstruction.md` 的人工确认与修改门禁。未获人工确认的背景不得拆分、登记为正式资源或应用到场景。

## 统一接入

1. 由技术架构提供单一背景适配器或基类，玩法不得在各场景复制缩放公式。每个可见场景必须声明已确认的背景资源或已批准的程序化背景；加载场景可先使用与背景边缘一致的非黑色清屏色，再无闪烁切换到正式背景。
2. 将背景置于最低渲染层，禁止启用输入、命中区域、碰撞、物理、焦点或无障碍交互语义。屏幕空间背景固定到相机；世界空间背景也不得影响玩法碰撞与可达区域。
3. 创建、唤醒、恢复、方向变化、画布尺寸变化和设备像素比变化时都重新选择方向资源并适配。场景切换时在前景出现前完成背景创建与覆盖，避免首帧或过渡帧露出相机清屏色。
4. 竖屏固定按高度缩放并在水平方向围绕批准焦点裁切或延展：

   `portraitScale = (viewportHeight + 2 × overscan) / assetHeight`

   必须同时满足 `assetWidth × portraitScale ≥ viewportWidth + 2 × overscan`。
5. 横屏固定按宽度缩放并在垂直方向围绕批准焦点裁切或延展：

   `landscapeScale = (viewportWidth + 2 × overscan) / assetWidth`

   必须同时满足 `assetHeight × landscapeScale ≥ viewportHeight + 2 × overscan`。
6. `overscan` 至少覆盖取整与采样误差；以最终渲染像素验证，不把固定经验值当作跨设备结论。显示尺寸向上取整，纹理采样、相机和画布取整策略保持一致。禁止用通用 `contain`、固定宽高拉伸或未受控的非等比缩放替代上述方向规则。

## 全场景验收

1. 枚举启动、加载、菜单、玩法、暂停、成功、失败、结算、设置及所有实际可见场景；临时调试场景明确排除。逐场景记录背景 ID、接入入口、最低层级、交互关闭状态和适配证据。
2. 在支持矩阵的最窄、最宽、最高、最矮视口，以及方向切换、窗口连续缩放、暂停恢复和场景过渡期间截图或录屏。四条边和四个角不得出现黑边、透明缝、闪烁、重复采样线或未批准的纯色带。
3. 同时检查焦点未被错误裁切、背景未遮挡 UI、背景不截获输入、纹理清晰度和内存符合预算。发现问题时修订资源或统一适配器，并重新验证所有受影响场景。
4. 只有正式背景获人工确认、所有可见场景均已接入、目标宽高比矩阵无黑边且运行验证通过时，才将无交互背景任务标为完成。
