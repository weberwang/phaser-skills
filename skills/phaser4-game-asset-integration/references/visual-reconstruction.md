# 参考截图或代码驱动的视觉与功能还原

当任务要求根据截图、现有界面、录屏、运行中的 Phaser 场景或源代码进行还原时，完整读取本文件。此类任务强制进入标准通道并完整执行 A1 至 A6，即使模块边界、交互和状态所有权不变也不得降级。目标是同时还原可观察功能和视觉表现：先建立可追溯的参考功能契约与视觉基线，再实现、生成、装配并逐状态验收；不得只做截图翻新、裁图替换或静态画面近似。

参考截图、录屏、效果图和“按这个实现”只属于参考输入与目标方向，不等于 A1、A2、A4、A5 或 A6 确认。继续任务、未提出异议、批准另一阶段或批准旧版本也不得推断当前阶段通过；只有人工明确答复指向当前阶段产物和版本，并保存记录时，才允许写“用户已批准”。

## 输入归档

1. 记录输入类型、位置、版本、目标场景、视口、设备像素比、游戏状态、操作路径和权属。外部截图或第三方项目只提炼获准借鉴的视觉特征与可观察交互规律，不复制受限角色、商标、独特素材或受保护实现。
2. 保留未经修改的截图、录屏、操作步骤、状态样本和预期结果。截图只能证明单一时刻的可见状态；无法证明的输入响应、状态迁移、计时、随机、失败处理、存档或平台行为一律标为“证据缺口”，不得自行补成参考功能。
3. 代码输入先定位场景、组件、布局、样式、资源加载、输入、规则、状态、动画、持久化和平台入口，再在可复现环境中运行，捕获固定视口截图并记录操作轨迹。仅凭源码猜测最终画面或仅凭截图猜测交互不得进入正式还原。
4. 对每个可见对象和交互路径建立清单，标注稳定 ID、语义、层级、输入、前置状态、状态迁移、反馈、时序、失败路径、现有资源、文本/代码绘制方式，并给出“代码绘制、复用、新生成、重绘、删除”之一的结论。

## 双基线门禁

1. 由制作策划和玩法在 `docs/GDD.md`、`docs/TDD.md` 建立参考功能契约，逐项记录前置状态、玩家输入、规则、状态迁移、时序、动画/音效反馈、成功/失败结果、异常与恢复、适配行为及参考证据。证据不足的条目标为“待人工定义”，不得进入实现。
2. 由美术对照 `docs/visual-design.md` 建立参考视觉基线，整理信息层级、构图、角色、场景、UI、图标、字体、色彩、光影、动画、特效和各状态差异。全局规则未冻结时先提交决策包，不得批量生成。
3. 将对象稳定 ID 同时关联参考功能契约、固定视口基准图和资源槽，明确必须一致的行为与视觉、允许变化项及验收容差。视觉优化不得改变已批准功能，功能修复也不得绕过视觉确认。
4. A1 使用低保真实现复现完整可观察功能，包括输入、导航、规则、状态迁移、时序、反馈、成功/失败、重开和受影响异常路径；人工明确确认当前 A1 运行产物的功能路径、信息结构和交互边界后才能冻结 A1。只还原布局不视为 A1 通过。
5. 选择至少一个代表性场景和关键状态制作目标效果图或局部样张，在 `docs/visual-design.md` 记录输入、问题、处置、功能契约、目标规格和验收状态；在资源登记记录来源或生成方式、提示词/模型/人工编辑摘要、版本、授权和发布资格。
6. 审查目标效果图与参考功能契约、玩法可读性、触控、安全区、性能预算和全局视觉规则是否一致。功能基线与视觉基线均通过后只能进入 A4；必须完成带编号框选图、完整单图清单和当前版本 A4 人工确认，才可批量生成、拆分或替换正式资源。

## 生成、人工确认与修改

1. A2 存在可见场景时，先按 `full-bleed-background.md` 制作并确认无交互满幅背景效果，再处理角色、前景、UI 或特效效果图；此时不得把效果图登记为正式资源。A4 确认后，复用符合视觉基线且验证有效的现有资源，其余对象才按清单新生成或重绘。生成提示与编辑要求必须引用已冻结规则、对象用途、镜头、目标尺寸、透明背景或可平铺要求，避免仅使用“更好看”等不可验收描述。
2. 每轮效果图、生成或重绘完成后，保存带版本号的预览和生成记录，标为“待人工确认”，并向总控提交确认包：阶段、预览及版本、适用对象、对应功能状态、与视觉基线的对应关系、已知偏差，以及“确认使用、按意见修改、拒绝并重定方向”三种处置。相关且同批的资源可合并确认，但不得用代表性样张、A2 效果图或 A4 框选的批准替代 A5 正式产物确认。
3. 等待人工明确确认。选择修改时记录具体意见，生成新版本并重新提交确认；选择拒绝或改变视觉方向时保留旧版本为“已拒绝”，退回视觉基线或双基线门禁。A2 未确认时不得进入 A3，A4 未确认时不得生成正式资源，A5 未确认时不得接入 A6 或进入候选构建。
4. 不得静默覆盖原始输入、已批准基准画面或上一轮产物；只有新版本获人工确认后，才将上一有效版本标为“已取代”。

## 拆分与接入

1. 人工确认后的合成效果图继续执行 `effect-image-splitting.md` 的查重、拆分方案审查、拆图、逐图检查和 Phaser 验证流程。`Phaser.Graphics` 只允许用于动态进度、遮罩、点击区域、简单线条、调试显示、无明显材质要求的基础几何和无法预先烘焙的实时变化。
2. 主面板和成套弹窗外壳、复杂按钮底图、道具与商品图标、徽章/折扣牌/礼包装饰、翅膀/爱心/金币堆等插画对象及主要识别 UI，如果参考图具有明显材质、体积、纹理、复杂高光、内外阴影、装饰花纹或角色化造型，不得以 `Phaser.Graphics` 作为正式高保真实现。它们必须进入 A4 带编号框选图和完整清单，并在 A5 以正式透明位图、九宫格、序列帧或获批准矢量资源交付。
3. A4 为每个对象记录用途、尺寸、透明要求、锚点、九宫格、纹理键和“代码绘制、复用、新生成、重绘、删除”结论；A5 逐项提交实际文件、资源登记与来源、深浅背景透明边缘检查、Phaser 加载与缩放截图、目标视口运行证据，以及未完成/未验收资源清单。任一主要视觉对象缺失时不得进入 A6。
4. 由玩法逐项装配已确认资源，保持稳定 ID、纹理键、锚点、九宫格、布局、输入与状态映射可审计；如需改变参考功能契约、玩法结构或交互语义，退回制作策划和模块门禁重新批准。
5. 接入或运行验证暴露出视觉问题时返回对应美术门；暴露出功能差异时返回 A1、GDD/TDD 或模块门禁。不得以技术修复名义绕过任一确认。

## 对比验收

1. 在与输入一致的视口宽高、设备像素比、游戏状态、操作轨迹、文本语言和动画时间点运行还原版本，逐检查点捕获截图或录屏；同时保存参考图与运行图，并至少生成一种并排图、叠加图或像素差异图。代码输入同时记录复现命令和提交或变更文件。任一条件不一致时只能标记“未验证”，不得标记通过。
2. 视觉验收逐项检查外轮廓与构图、元素位置和尺寸、层级与遮挡、字体/描边/阴影、材质/纹理/高光、图标细节、安全边距、裁切与越界、九宫格变形、不同宽度下的等比缩放，并继续检查触控区域、关键反馈、动画状态、采样边缘、纹理预算和加载性能；所有偏差必须有位置、影响和批准结论。
3. 功能验收逐项重放参考功能契约，核对输入响应、状态迁移、规则结果、时序、动画/音效反馈、成功/失败、重开、异常恢复和适配行为；使用契约测试、集成测试或可复现录屏证明结果。
4. 不以单张静态截图代替运行验证，也不以功能测试通过代替视觉对比。搜索源码方法名、检查固定坐标字符串、类型检查、单元测试、生产构建成功、控制台无错误、主观描述“看起来接近”或只验证元素存在，均不能单独作为视觉通过证据。源码标记测试只能命名为“结构回归”，不得命名或表述为“视觉回归”。
5. 至少覆盖默认、交互反馈、成功、失败、弹窗和受影响异常状态，并在一个目标设备或渠道运行。
6. 只有 A1 至 A5 有效证据、所有人工确认门均有当前版本明确记录、正式资源全部登记并通过 Phaser 验证、运行时不再使用未批准低保真替代物、同条件逐状态视觉对比通过、功能契约通过、低保真和占位资源已清理、构建与回归测试通过时，才可将任务标为“高保真完成”“视觉还原通过”或“A6 完成”。证据缺口必须在实现前补证、由人工定义或从批准范围中明确排除，不得在验收时用豁免代替还原。
7. 人工指出运行结果明显细节不足时，立即撤销完成状态。结构表达问题退回 A2，框选漏项或拆分问题退回 A4，资源材质、纹理、边缘、细节、缩放或接入质量问题退回 A5；不得继续用局部坐标调整掩盖资源质量问题。
