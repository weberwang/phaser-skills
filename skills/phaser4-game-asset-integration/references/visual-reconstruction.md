# 截图或代码驱动的美术重构

当任务要求根据截图、现有界面、运行中的 Phaser 场景或源代码整理并重新生成美术时，完整读取本文件。目标是保留已批准的信息结构与玩法语义，建立统一视觉基线，再生成和接入可追溯的正式资源；不得把截图翻新等同于裁图替换。

## 输入归档

1. 记录输入类型、位置、版本、目标场景、视口、设备像素比、游戏状态和权属。外部截图或第三方项目只提炼获准借鉴的视觉特征，不复制受限角色、商标或独特素材。
2. 截图输入保留未经修改的基准图；缺少关键状态、弹窗、交互反馈或适配尺寸时，先列为证据缺口。
3. 代码输入先定位场景、组件、布局、样式、资源加载、动画和状态入口，再在可复现环境中运行并捕获固定视口截图。仅凭源码猜测最终画面不得进入生成。
4. 对每个可见对象建立清单，标注语义、层级、交互状态、现有资源、文本/代码绘制方式及“保留、重构、新生成、删除”结论。

## 重构方案门禁

1. 对照 `docs/visual-design.md` 整理信息层级、构图、角色、场景、UI、图标、字体、色彩、光影、动画和特效规则。全局规则未冻结时先提交决策包，不得批量生成。
2. 选择至少一个代表性场景制作目标效果图或局部样张，明确哪些结构必须保留、哪些表现允许改变，以及截图无法证明的假设。
3. 在 `docs/visual-design.md` 的重构清单记录输入、问题、处置、目标规格和验收状态；在资源登记记录来源或生成方式、提示词/模型/人工编辑摘要、版本、授权和发布资格。
4. 审查目标效果图与玩法语义、可读性、触控、安全区、性能预算和全局视觉规则是否一致。审查结论为“通过”后才可批量生成、拆分或替换正式资源。

## 生成、人工确认与修改

1. 存在可见场景时，先按 `full-bleed-background.md` 生成并确认无交互满幅背景，再处理角色、前景、UI 或特效。复用符合视觉基线且验证有效的现有资源；其余对象按重构清单生成或人工重绘。生成提示与编辑要求必须引用已冻结规则、对象用途、镜头、目标尺寸、透明背景或可平铺要求，避免仅使用“更好看”等不可验收描述。
2. 每轮生成或重绘完成后，保存带版本号的预览和生成记录，标为“待人工确认”，并向总控提交确认包：预览、适用对象、与视觉基线的对应关系、已知偏差，以及“确认使用、按意见修改、拒绝并重定方向”三种处置。相关且同批的资源可合并确认，但不得用代表性样张的批准替代后续正式产物确认。
3. 等待人工明确确认。选择修改时记录具体意见，生成新版本并重新提交确认；选择拒绝或改变视觉方向时保留旧版本为“已拒绝”，退回视觉基线或重构方案门禁。未得到明确确认的产物不得拆分、替换正式资源、进入候选构建或标为可交付。
4. 不得静默覆盖原始输入、已批准基准画面或上一轮产物；只有新版本获人工确认后，才将上一有效版本标为“已取代”。

## 拆分与接入

1. 人工确认后的合成效果图继续执行 `effect-image-splitting.md` 的查重、拆分方案审查、拆图、逐图检查和 Phaser 验证流程。需要代码绘制的简单几何、遮罩、进度条或动态文本应保留为代码实现，不强制烘焙成图片。
2. 逐项替换已确认资源，保持纹理键、锚点、九宫格、布局和状态映射可审计；如需改变玩法结构或交互语义，退回制作策划重新批准验收增量。
3. 接入或运行验证暴露出问题时，生成或重绘修订版并重新经过人工确认，不得以技术修复名义绕过确认。

## 对比验收

1. 在与输入一致的视口、设备像素比和游戏状态下捕获重构后截图，形成重构前、目标基准、重构后三方对比；代码输入同时记录复现命令和提交或变更文件。
2. 检查构图与信息层级、风格一致性、文字可读性、触控区域、关键反馈、不同宽高比裁切、动画状态、采样边缘、纹理预算和加载性能。
3. 不以单张静态截图代替运行验证。至少覆盖默认、交互反馈、失败/成功或弹窗等受影响状态，并在一个目标设备或渠道运行。
4. 只有清单全部有处置结论、所有生成/重绘产物均有明确人工确认记录、正式资源可追溯、固定视口对比通过、Phaser 场景验证通过且无未批准结构变化时，才将本次美术重构标为已验收。
