# 视觉与功能还原

参考截图、录屏、运行项目和源码是输入，不是通过结论。参考还原属于 V0 的完整路径，执行 V1-V5；先建立原创玩法视觉契约，再分析参考如何满足或偏离契约，避免把临摹顺序置于玩法目标之前。

## V1-V2

1. 玩法建立功能契约：前置状态、输入、规则、状态迁移、时序、反馈、成功/失败和异常恢复。静态输入无法证明的行为标为待定义。
2. 记录参考版本、权属、视口、设备像素比、语言、状态、操作轨迹、随机种子和动画时间点。
3. V1 逐状态定义第一视觉目标、优先级、区分信号、反馈时序、遮挡与小屏阈值。
4. V2 产出关键画面和动态可玩样片。还原“像”但识别、预警、反馈或操作失败时不得通过。

## V3-V4

按对象稳定 ID 选择资产生产路线和“代码绘制、复用、新生成、重绘、删除”结论。整屏效果图不得直接作为交互场景；只有 AI 合成栅格路线按需框选拆分。所有正式资源保留可编辑来源或生成记录、授权和机器清单，并完成资源级验收。

## V5 同条件与动态验收

参考和运行证据使用相同视口、设备像素比、语言、状态、操作轨迹和时间点。截图对比必须记录 ROI、容差、动态时间采样/稳定帧及遮罩理由，可保存并排、叠加和像素差；生成式内容、动画和 VFX 不得只靠像素差判断。

V5 还必须重放可复现交互轨迹，验证功能契约、第一视觉目标、预警、反馈、遮挡、移动端缩小和性能峰值。玩法负责规则、状态和交互；美术负责表现资源和视觉集成，双方共同关闭 V5 的 F3 跨域问题。
