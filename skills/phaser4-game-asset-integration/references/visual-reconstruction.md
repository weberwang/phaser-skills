# 视觉与功能还原

参考截图、录屏、运行项目和源码是输入，不是通过结论。参考还原属于 V0 的完整
路径，执行 V1-V5；先建立原创玩法视觉契约，再分析参考如何满足或偏离契约，
避免把临摹顺序置于玩法目标之前。

## V1-V2

1. 玩法建立功能契约：前置状态、输入、规则、状态迁移、时序、反馈、成功/失败和异常恢复。静态输入无法证明的行为标为待定义。
2. 记录参考版本、权属、视口、设备像素比、语言、状态、操作轨迹、随机种子和动画时间点。
3. V1 逐状态定义第一视觉目标、优先级、区分信号、反馈时序、遮挡与小屏阈值。
4. V1 以低保真草图或可运行灰盒确认信息结构、页面/场景构图、层级、资源槽、关键状态、交互区、输入流程、布局几何、安全区/响应式意图与失败恢复。总控提交绑定当前参考/候选版本和功能/模块契约版本的确认包；只有用户明确“通过”才进入 V2，参考输入本身无效。
5. 读取并冻结 [`phaser4-game-ui-layout` 的布局合同](../../phaser4-game-ui-layout/references/layout-contract.md)，定义四层坐标关系、Scale 策略、响应式锚点、断点重排、背景覆盖、留白/裁切/拉伸许可、视口矩阵，以及动态文本、显隐、滚动、触控和 resize；任一适用项缺失标记“响应式契约缺失”，阻断 V2。
6. V2 产出关键画面和覆盖矩阵的动态可玩样片，验证完整 viewport、背景覆盖、安全区、层级、最小可读性、多比例重锚定、间距、显隐、滚动与 resize；完整测量字段和脚本见 QA 的 [响应式视觉验证](../../phaser4-game-qa-performance/references/responsive-visual-validation.md)。通过 V2a/V2b 与独立美术 F2 后，由总控另行提交绑定当前参考/候选版本、全局视觉基线和差异说明的高保真效果图确认包。只有用户对当前版本明确“通过”后才形成视觉可交付并进入 V3；低保真确认不能批准风格或最终游戏感，还原“像”但识别、预警、反馈或操作失败时不得送用户兜底或通过。

## V3-V4

按对象稳定 ID 选择资产生产路线和“代码绘制、复用、新生成、重绘、删除”结论。V3 输入必须同时绑定仍有效的当前低保真确认 ID，以及当前候选明确“通过”的高保真确认 ID；旧版本、功能范围批准、方向级批准、沉默或继续工作均无效。整屏效果图不得直接作为交互场景；只有 AI 合成栅格路线按需框选拆分。所有正式资源保留可编辑来源或生成记录、授权和机器清单，并完成资源级验收。V4 的非作者 F2 必须以完整 viewport 检查资源满幅能力和响应式绑定；算法验证、逻辑画布或 Canvas ROI 不能替代生产场景证据。

## V5 同条件与动态验收

参考和运行证据使用相同视口、设备像素比、语言、状态、操作轨迹和时间点。截图对比
必须记录 ROI、容差、动态时间采样/稳定帧及遮罩理由，可保存并排、叠加和像素差；生成
式内容、动画和 VFX 不得只靠像素差判断。完整 viewport 截图是过程证据，Canvas ROI
只能补充。

V5 还必须在同一页面重放可复现交互轨迹和动态 resize，验证功能契约、第一视觉目标、
预警、反馈、遮挡、移动端缩小和性能峰值。非作者在 F2 给出独立领域质量结论，F3 只验证当前候选工程证据；
缺完整 viewport 证据只能标记“未验证”。玩法负责规则、状态和交互；美术负责表现
资源和视觉集成，双方提交 V5 证据，由 F3 对当前候选执行工程验证。
