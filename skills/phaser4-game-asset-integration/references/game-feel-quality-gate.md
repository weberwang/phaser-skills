# 游戏感质量硬门

在当前 V1 低保真候选已明确“通过”后，V2 内执行两个不可省略的专业检查点：`V2a 方向基准`与 `V2b 整体视觉审阅`，并在其后执行独立的出口高保真效果图用户确认。场景、整套 UI、视觉系统、参考还原和所有重做类任务必须执行；组件/资源集只要适用 V2 且候选定义或改变用户可见高保真形态也必须执行。低保真确认不能跳过 V2a/V2b、独立美术 F2 或高保真确认。任何“重做、重新设计、提升游戏感、替换整套 UI”任务不得当作原子资源跳过 V1/V2。所有候选执行 [全局视觉控制约束](global-visual-control.md)；原子资源只能继承当前适用、有效、绑定版本且覆盖当前范围的低保真/高保真确认记录、视觉可交付与冻结全局基线。

本门禁拦截“文件与工程证据充分，但画面仍像后台、表单、工具应用、PPT 或网页模板”的候选物。不得用清晰度、圆角、阴影、渐变、插画数量、构建通过或主观声明代替游戏感证据。

## 门禁原则

1. 每个核心项同时引用候选版本、候选截图、截图内具体区域和可观察事实。只写“有游戏感”“风格统一”“构图无问题”等结论视为缺证。
2. 任一核心项缺证、明显失败或只有主观声明时，V2a、V2b 与对应 F2 均不通过，候选不得进入 V3。
3. 区分两类结论：
   - **视觉可交付**：V2a/V2b 与独立美术 F2 已证明游戏感、构图、世界感、反馈、奖励、状态差异和视觉一致性，且用户已对当前高保真候选明确“通过”；该结论必须绑定确认 ID 才允许进入 V3，且不声称 V4 文件已经存在。
   - **工程可交付**：V4/V5 已证明文件、透明边缘、尺寸、锚点、九宫格、性能、加载和响应式有效。
4. V2a/V2b 与独立美术 F2 先形成专业预结论；当前候选再经出口确认明确“通过”后，才以绑定确认记录的视觉可交付结论放行 V3。完成 V4/V5 或报告视觉完成时，必须同时保持视觉可交付结论与确认记录有效，并取得相应阶段的工程可交付结论。
5. V2a 与 V2b 必须由非产物作者的独立美术角色执行 F2。总控只能代查流程和证据完整性，不能单独给出艺术方向或视觉可交付通过；没有独立美术审阅时标记“专业视觉未验证”，禁止提交确认包或进入 V3。

## V1 与 V2 的结构边界

V1 冻结功能语义、业务状态、交互语义和状态所有权，同时提供能够承载视觉方向的构图、信息层级、资源槽与页面几何。完成必要低保真草图或可运行灰盒及相关证据问题关闭后，总控提交当前低保真候选确认包；只有用户明确“通过”才进入 V2。该确认不批准视觉风格、材质、光影、正式资源质量或最终游戏感。高保真重做不是给必要灰盒更换皮肤：不得把占位矩形、通用白卡和默认列表直接美化为最终结构。

V2a、V2b 或对应 F2 发现下列任一结构无法支持游戏感时，提交“结构修订包”并退回 V1：

- 构图把核心玩具、角色或主要行动压成次要信息；
- 信息层级无法形成第一视觉焦点或清晰行动召唤；
- 资源槽不足以承载角色、奖励、反馈、专属场景对象或状态变体；
- 页面模板迫使多个页面重复同一容器和内容节奏；
- 几何、响应式或安全区约束导致核心对象失去舞台感、反馈空间或可读性。

结构修订包必须包含候选截图与标注区域、失败事实、需要重审的 V1 几何/层级/资源槽/页面模板、保持不变的功能语义与业务状态，以及修订后的验收条件。返回 V1 时不得由美术改变玩法规则、业务状态、交互语义或状态所有权；原低保真确认记录标记失效或缩小适用范围，新候选必须重新确认。

严格参考复刻在参考证据足以证明结构时保持参考结构。重新设计、重做或提升游戏感时，必须允许视觉方向推动 V1 几何重审；用户低保真确认不得阻止专业回退或豁免结构缺陷，禁止用“V1 已通过”强迫高保真继续套用不支持游戏感的灰盒结构。

## V2a 方向基准

任务包含重做、重新设计、提升游戏感或替换整套 UI 时，在建立正式视觉基准前至少提交 3 个实质差异方向。三个方向不得只是换色、换字体、换阴影或替换同构插画；必须在构图、场景容器、核心焦点、材质体系或情绪表达中至少一项形成实质差异。

每个方向分别说明并以候选图证明：

1. 玩家幻想与所处世界；
2. 核心玩具及其第一视觉焦点；
3. 主要交互和行动召唤；
4. 奖励期待与情绪峰值；
5. 选中、错误、提示、购买、成功和失败状态如何扩展。

只有选定方向通过本门禁后，才制作完整关键状态和动态可玩样片。严格参考复刻可免除三方向探索，但必须提供同视口、同状态、同语言和同动画时点的参考/候选对比，并逐项说明有意差异及原因；参考输入本身不等于视觉通过。

V2a 通过时将选定方向冻结为单一版本化全局视觉基线，记录 ID、版本、风格指纹、主锚点、分系统锚点、全局不变量、允许变量、禁止项和 AI 固定提示前缀。未冻结基线不得进入 V2b；局部候选不得自行创造新材质、光源、描边、角色比例或图标语法。

## V2b 整体视觉审阅

对完整关键状态、页面集合与动态可玩样片执行整体审阅。除下列游戏感核心项外，继续验证第一视觉目标、预警、遮挡、小屏缩放、灰阶/色觉差异、动态反馈时序和方向一致性。用户批准 V2a 方向不能替代 V2b；静态效果图不能替代动态样片。

## V2 出口：高保真效果图用户确认

顺序固定为 `V2a → V2b 与动态样片 → 独立美术 F2 → 总控提交当前候选确认包 → 用户结论`，不得新增 V 阶段编号。确认包至少包含审核/确认 ID、当前候选版本、适用范围、全局视觉基线 ID/版本/风格指纹、代表性高保真效果图及关键状态、动态可玩样片或可复现轨迹、与参考或上一版差异、独立美术 F2 结论、已关闭问题、V3 生产范围和不可逆/返工影响。

用户结论只允许“通过”“修改后重提”或“拒绝”。修改后产生新候选，重跑 F0 授权合规、F1 规格一致、受影响 F2 和 F3，再请求当前 pending approval；F4 只用于精确集成/发布决定。拒绝按根因退 V2a，结构根因退 V1。

## 核心审核项与评分

每项按下列尺度评分，并保留证据引用：

- `2`：候选截图中有明确、稳定、可观察的视觉事实，能够支持该项；
- `1`：方向可识别但强度不足、覆盖不全或存在明显冲突，必须修改后复核；
- `0`：缺证、明显失败，或只有主观声明。

任一核心项为 `0` 时直接阻断 V2a/V2b；任一核心项为 `1` 时结论只能是“修改后复核”。不得用总分平均掩盖单项失败。

### 1. 玩家幻想与世界身份

- 指出玩家扮演、照料、收集、挑战或推进的幻想，并标注承载该幻想的角色、场景、道具或空间。
- 移除所有文字后，画面仍应能识别场景用途，并能从狐狸角色、狐狸造型语言、狐狸世界道具或叙事线索辨识本项目主题；只剩通用卡片和工具图标时不通过。

### 2. 核心玩具感与第一焦点

- 标注第一视觉焦点，说明核心可玩对象为何像可触摸、可操控、可获得反馈的游戏玩具，而不是数据展示组件。
- 检查体积、层级、尺度、材质、状态空间和交互暗示；核心玩法若被导航、表格、说明或装饰压制则不通过。

### 3. 行动召唤与主要交互

- 标出主要行动入口，证明玩家无需阅读说明即可判断下一步。
- 用位置、尺度、对比、形状、姿态、光效或动势建立行动召唤；不得只依赖灰色按钮文字或网页式链接。

### 4. 状态反馈强度

- 分别提供选中、错误、提示、购买、成功和失败的关键截图或状态分镜。
- 证明每种状态在构图、角色表演、材质、光色、特效、动势、尺度或场景反应上有足够差异。成功/失败只换文字、颜色或小图标时不通过。

### 5. 奖励期待与情绪峰值

- 标注奖励预告、稀有度、进度临界点、开启/领取动作和结果展示如何制造期待。
- 证明成功、购买、收藏完成或挑战达成至少有一个高于常态的情绪峰值；只有数值增加或静态提示时不通过。

### 6. 视觉语言一致性

- 对照冻结基线的风格指纹、主锚点和分系统锚点检查角色、图标、面板、按钮、光源、材质、描边和色彩，引用具体区域说明它们共享的造型与渲染规则。
- 任何主要系统出现互不相容的扁平线框、写实材质、塑料高光、纸张纹理、描边粗细、光源方向或色彩逻辑时，判定材质体系割裂。
- 不得用“同一关键词”“同一模型”“同一调色板”或作者声明代替多资源联系表、同屏截图和可观察事实。

### 7. 页面场景差异

逐页证明主页、关卡、藏品、签到、排行榜、锦标赛和挑战在全局不变量内具有不同的场景身份、核心对象和内容节奏。场景差异不得退化为同一模板，也不得变成不同美术体系：

- 主页承担世界入口与主行动；
- 关卡突出核心玩具、即时反馈和胜负张力；
- 藏品具有可收集、陈列或成长的专属视觉对象；
- 签到具有日历、连续轨迹、宝箱或领取仪式等专属对象；
- 排行榜具有名次、对手、领奖台或竞争进度等专属对象；
- 锦标赛具有赛制、对阵、奖杯、赛场或阶段晋级等专属对象；
- 挑战具有目标、限制、风险、倒计时或特殊奖励等专属对象。

六个或更多页面复用“标题 + 白卡片 + 灰按钮”模板，或藏品/签到/排行榜/锦标赛缺少专属视觉对象时不通过。

### 8. 沉浸完整性

- 检查所有可见文案、角标、标签、日志区和占位区域。
- 候选画面不得出现“未实现”“本地演示”“操作未启用”、stable ID、调试说明、开发状态、测试口径、资源键、组件名或面向开发者的限制说明。
- 必需的不可用状态必须改写为世界内、玩家可理解的反馈，并以游戏内视觉状态表达原因和下一步。

## 自动退回规则

发现下列问题时默认至少登记 P1/P2 并退回 V2；根因属于信息结构、布局几何、资源槽或页面模板时提交结构修订包并退回 V1：

- 整体呈现后台、表单、工具应用、PPT 或网页模板感；
- 存在无职责的大空白，不能解释为焦点留白、动效空间、场景纵深或安全区；
- 六页面或更多页面重复“标题 + 白卡片 + 灰按钮”；
- 主要识别元素由通用线性工具图标承担；
- 角色、图标、面板、按钮、光源或材质体系割裂；
- 成功与失败仅更换文字、颜色或小图；
- 藏品、签到、排行榜、锦标赛或其他玩法页缺少专属视觉对象；
- 所谓高保真只是给灰盒增加圆角、阴影、渐变和插画；
- F2 只写“构图无问题”“风格无问题”等结论，没有截图、区域和事实。

明显审美缺陷、游戏感缺失、开发文案残留和证据缺口均属于可由专业规则裁决的问题，不得提交 F4 请求豁免或交给任一确认兜底。“用户批准低保真/方向”不能替代 V2b、当前候选的独立 F2 审阅或出口确认。V1 与 V2 出口确认都不能接收未关闭的技术/专业缺陷。

出现全局规则或方向漂移时退 V2；基线绑定、生产规格或生成包缺失时退 V3；正式资源执行偏差退 V4；构图、信息层级、资源槽、页面模板或布局结构根因退 V1。冻结基线变更必须提交影响面并重验受影响锚点、资源、状态、页面和运行证据。
