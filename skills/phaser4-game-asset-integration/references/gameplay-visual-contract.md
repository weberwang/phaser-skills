# 玩法视觉契约

## 目的

把“好看”转换成玩家在运动和压力下可识别、可预判、可操作的约束。每个关键玩法状态都要填写契约；静态效果图、像素接近、资源齐全或单次截图不能证明游戏性。

场景、整套 UI、视觉系统和参考还原还必须冻结 [`phaser4-game-ui-layout` 的布局合同](../../phaser4-game-ui-layout/references/layout-contract.md)。
其中四层坐标、适配策略、背景覆盖、留白/裁切/拉伸许可、视口矩阵和动态 resize 是
响应式唯一详细规范；QA 的[响应式视觉验证](../../phaser4-game-qa-performance/references/responsive-visual-validation.md)
负责测量和证据格式。原子资源只有在已有有效契约与预算基线时可引用，否则按影响升级。

## 逐状态契约

| 字段 | 要求 |
| --- | --- |
| 第一视觉目标 | 玩家进入状态后最先必须看见并理解的对象或变化，只写一个主目标 |
| 视觉优先级 | 按玩家、目标、危险、交互、装饰排序；同级冲突写出化解方式 |
| 明度/色彩 | 定义前景背景对比、状态色与灰阶仍可识别的辅助信号 |
| 轮廓/尺度 | 定义小屏和高速运动时仍稳定的外轮廓、最小占屏和安全留白 |
| 运动区分 | 定义方向、速度、节奏或轨迹差异，避免只靠颜色表达 |
| 可供性（affordance） | 明确可点击、可拖动、可拾取、可伤害、可阻挡等可供性及反馈 |
| 反馈时序 | 定义前摇、命中、受击、奖励出现、峰值、保持和收尾时长 |
| 遮挡预算 | 定义关键目标最大遮挡比例、遮挡持续时间和同屏特效上限 |
| 差异条件 | 覆盖小屏、高速运动、灰阶和项目要求的色觉差异模式 |
| 量化阈值 | 由项目定义对比度、最小像素/角尺寸、响应延迟、持续时间、遮挡比例、同时出现数量等阈值 |

没有通用数值时，适用 V1 的路径标记“项目待定义”，由项目负责人和测试共同冻结；原子资源只有在既有基线已经给出适用有效阈值时才可走轻量路径。不得假装存在行业默认值。

## V1 低保真证据与确认

适用 V1 的路径必须用低保真草图或可运行灰盒证明关键场景/页面/状态、信息层级、稳定 ID/层级/资源槽、交互区、输入轨迹、布局几何、安全区/断点意图、失败与恢复以及明确排除项。相关玩法、架构与 UI 布局问题关闭后，总控提交绑定功能/模块契约版本的当前候选确认包；用户明确“通过”后才进入 V2。该确认不批准视觉风格、材质、光影、正式资源质量或最终游戏感，也不能替代 V2a/V2b、独立美术 F2 或高保真确认。

用户结论只允许“通过”“修改后重提”或“拒绝”。修改后产生新候选，重跑 F0 授权合规、F1 规格一致、受影响 F2 和 F3，再请求当前 pending approval；F4 只用于精确集成/发布决定。

## 动态可玩样片

V2 以最小可玩切片验证契约，至少包含正常操作、错误/受击、奖励/成功、遮挡峰值和性能压力中的适用项；适用响应式路径还必须按基准、最窄、最宽、横屏和安全区矩阵覆盖动态文本、成员显隐、滚动、触控、重锚定和 resize。只有基准静态图阻断 V3。证据可以是录屏加输入日志，或能复现相同状态、随机种子、视口、输入与时间点的自动轨迹。

对每条轨迹记录：构建版本、设备/视口、设备像素比、输入序列、随机种子、状态起点、关键时间采样、稳定帧规则、预期第一视觉目标、观察结果和失败回退阶段。

## V5 验收

- 第一视觉目标在目标设备、小屏缩小和高速运动中仍可识别。
- 危险前摇早于伤害，命中/受击/奖励反馈顺序与持续时间符合契约。
- 颜色不是唯一信号；灰阶和目标色觉差异条件仍能区分关键状态。
- 装饰、VFX、字幕和 UI 不超过遮挡预算，不抢占玩家、目标、危险与交互层级。
- 正式资源、动画采样、图集压缩和运行时缩放没有破坏当前低保真确认覆盖的结构，以及 V2 独立美术 F2 已通过、且由当前高保真确认记录绑定的动态表现。
- 运行态使用完整 viewport 截图和同页面 resize 轨迹；Canvas ROI、逻辑画布或背景不溢出只能作为补充，缺完整 viewport 证据标记“未验证”。

任一项失败按根因返回 V4、V3、V2 或 V1；不以补一张静态截图关闭问题。
