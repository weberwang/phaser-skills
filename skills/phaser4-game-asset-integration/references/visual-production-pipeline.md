# V0-V5 视觉生产管线

## V0 分流

先记录范围、视觉方向是否冻结、结构/交互/布局是否变化、正式资源数量与跨域风险，再选择且只选择一条路径。

| 类型 | 判定 | 阶段 | 审核 |
| --- | --- | --- | --- |
| 原子资源 | 视觉方向已冻结，结构、交互、布局不变，并有适用且有效的玩法视觉契约、视觉可交付结论与预算基线可引用的单个或小批同类正式资源；缺少基线时升级路径 | V3 → V4 → V5 | F0 一次；F1 逐交付包；V4 资源验收做 F2；V5 做集成 F1 与动态证据；只有跨域风险才 F3 |
| 组件/资源集 | 同一组件、角色状态组、图标集或可复用资源集，需要局部探索与一致性控制 | V1 → V2 → V3 → V4 → V5 | V2、V4 做 F2；V5 做 F3 |
| 场景/视觉系统/参考还原 | 场景、整套 UI、世界环境、跨场景视觉系统或参考还原 | V1 → V2 → V3 → V4 → V5 | V2、V3、V4 做 F2；V5 做 F3 |

快速通道只允许不新增正式资源、不改变视觉方向、拆分、结构、交互或布局的局部尺寸、锚点、采样、九宫格、文本、间距或颜色修复，执行 F0/F1。任务中一旦超出边界，重新执行 V0，不默认回到最重路径。

场景、整套 UI、视觉系统和参考还原必须执行 V2a/V2b；组件/资源集按影响执行。任何“重做、重新设计、提升游戏感、替换整套 UI”任务都不得当作原子资源跳过 V2；原子资源只继承当前适用且有效的视觉可交付基线。所有路径同时执行 [全局视觉控制约束](global-visual-control.md)，不得生产未绑定当前冻结基线的正式资源。

F2 必须由非作者执行。V2a/V2b 必须由独立美术给出专业视觉结论；缺少独立美术时，总控只能代查流程与证据完整性并标记“专业视觉未验证”，禁止进入 V3。原子资源在 V0 记录所引用契约、预算、视觉可交付结论、适用范围、版本和有效性；任一项缺失或失效，升级为组件/资源集或场景路径。F4 始终只处理视觉方向、授权/预算风险、范围、不可逆成本等受保护决策，不因阶段存在而自动触发；明显审美缺陷、游戏感缺失和缺证不得提交 F4 豁免。

## V1 玩法视觉契约与必要灰盒

1. 逐状态定义第一视觉目标，以及玩家、目标、危险、交互、装饰的优先顺序。
2. 定义明度、色彩、轮廓和运动区分，可供性（affordance），前摇、命中、受击、奖励反馈时序，遮挡预算及小屏、高速、灰阶、色觉差异阈值。
3. 只有结构、交互或节奏尚不能被运行证据证明时制作必要灰盒；不得为了流程完整重复已冻结灰盒。
4. 在生产前定义每场景纹理、图集、帧数、动画采样、纹理内存、包体、过绘、Draw Call 和最大纹理预算。未能量化的阈值标为项目待定义，不能推迟到 V4。
5. 保留已批准的功能语义、业务状态、交互语义和状态所有权，同时检查构图、信息层级、资源槽、页面模板和布局几何是否足以承载核心玩具、专属场景对象、关键反馈与奖励表达。必要灰盒是功能与结构证据，不是必须原样换皮的最终视觉模板。
6. 建立全局视觉基线候选，记录基线 ID/版本、风格指纹、主锚点与分系统锚点、世界幻想及形状、比例、镜头、色彩、材质、光源、描边、密度、字体、图标、面板、动画和 VFX 规则，并明确允许变量与禁止项。未冻结内容不得作为批量生产依据。

玩法拥有规则、状态、交互和功能灰盒。美术拥有视觉契约中的表现目标，不得通过视觉实现改写玩法规则。

## V2 视觉探索与动态可玩样片

V2 内依次执行 `V2a 方向基准`和 `V2b 整体视觉审阅`，不得把两者拆成新的 V 阶段。场景、整套 UI、视觉系统、参考还原及所有重做类任务不得省略；组件/资源集按影响执行。完整读取并执行 [游戏感质量硬门](game-feel-quality-gate.md)。

### V2a 方向基准

1. 重做、重新设计、提升游戏感或替换整套 UI 时，正式基准前至少提交 3 个实质差异方向。各方向必须在构图、场景容器、核心焦点、材质或情绪上形成差异，且分别说明玩家幻想、核心玩具、主要交互、奖励表达和状态扩展；不得只换色。严格参考复刻可免三方向，但必须提交同条件参考/候选对比和差异说明。
2. 每个候选必须引用截图、具体区域和可观察事实，证明玩家幻想、核心玩具、行动召唤、反馈强度、奖励期待、情绪峰值、移除文字后的场景用途与狐狸主题、视觉一致性、页面场景差异和沉浸完整性。
3. 独立美术执行 F2。任一核心项缺证、失败或只有主观声明时不得通过；选定方向通过 V2a 后，才制作完整关键状态与动态样片。用户批准方向不能替代专业结论。
4. V2a 或对应 F2 发现 V1 构图、信息层级、资源槽、页面模板或布局几何无法支持游戏感时，提交包含标注截图、失败事实、待修订结构、保持不变的功能语义/业务状态和新验收条件的结构修订包，退回 V1。不得在候选图中静默改玩法或勉强套用灰盒。
5. 将选定方向固化为唯一 `frozen` 全局视觉基线，冻结 ID、版本、风格指纹、主/分系统锚点、全局不变量、允许变量、禁止项和 AI 固定提示前缀。局部方向不得自行创造新材质、光源、描边、比例或图标语法。

### V2b 整体视觉审阅

1. 将选定候选装入最小可玩切片，覆盖关键状态、运动、反馈和遮挡峰值。V2 必须提供动态可玩片段或可复现交互轨迹；静态效果图不能替代动态样片。
2. 非作者独立美术再次以当前完整候选执行 F2，逐截图、区域和可观察事实审阅游戏感，并对照全局基线的风格指纹与锚点检查第一视觉目标、形状、比例、材质、光源、描边、图标语法、预警、反馈、遮挡、小屏缩放、灰阶/色觉差异、动态时序和方向一致性。
3. F2 结论只使用“通过”“修改后复核”“退回 V1”或“专业视觉未验证”。缺少独立美术时总控不得给出艺术方向或视觉可交付通过，必须标记“专业视觉未验证”并阻断 V3。
4. 用户批准 V2a 方向不能替代 V2b。方向或其他受保护取舍才进入 F4；明显审美缺陷、游戏感缺失和缺证留在 F2 修复，冻结方向内的状态派生不重复请求人工。

V2a/V2b 都通过后，才形成“视觉可交付”结论并进入 V3。此时尚未生产 V4 正式文件，不要求“工程可交付”。

## V3 生产设计与机器清单

1. 按资产类型选择源文件、运行时输出、生产工具、命名、切片、锚点、图集、帧和压缩策略；保留可编辑源文件或完整生成记录，并继承当前全局基线与适用分系统锚点。
2. 将资源写入 `docs/visual-assets.json`，声明唯一资源 ID、纹理键、输出路径、路线、状态、证据、项目已定义预算，以及与根节点完全一致的基线 ID、版本和风格指纹。
3. UI、像素美术、逐帧/骨骼动画、Tilemap、VFX、背景和玩法环境走各自路线。框选效果图拆单图只属于 AI 合成栅格路线，不是默认管线。
4. 场景/系统/参考还原在 V3 做非作者 F2；原子资源和组件集不重复设置 V3 审核。
5. AI 生成包固定使用“全局提示前缀 + 资产特定段 + 状态段 + 负向段”，并记录模型/版本、种子、参考输入、控制参数和后处理。相同关键词、模型或调色板不得单独证明一致。

V3 只能使用当前有效的视觉可交付与全局视觉基线。生产规格、基线绑定、锚点或生成包缺失时留在 V3；方向或全局规则漂移退回 V2；结构根因退回 V1。不得用生产清单替代游戏感审核。

## V4 正式资源生产与资源级验收

1. 按 V3 清单生产运行时文件，不静默覆盖已验收版本；同步登记来源、生成记录和授权。
2. 逐资源验证透明边缘、尺寸、采样、锚点、九宫格、帧序、缩放、压缩、Phaser 加载、目标视口和预算。
3. `accepted` 资源必须有可编辑来源或生成记录、授权记录、运行时输出、Phaser 证据和玩法视觉证据。运行清单验证器；启用 `--check-files` 时所有声明文件必须存在。
4. V4 只验证 V1 已定义或原子资源已引用且在 V3 写入的预算；超预算返回 V3 调整生产计划，不能在验收时临时放宽。
5. 所有标准路径都在 V4 做非作者 F2。资源问题留在 V4；跨域集成风险不在资源层提前做 F3。
6. 每个生产包提交跨资源联系表与同屏组合截图，引用具体区域和可观察事实检查角色、图标、面板、按钮、场景对象与 VFX 的形状、比例、材质、光源、描边、色彩和渲染密度。独立美术判断一致性；总控只核对基线绑定和证据完整性。

V4 以文件、透明边缘、尺寸、锚点、九宫格、性能、加载、响应式和一致性证据判断“工程可交付”。正式资源执行偏差留在 V4；方向漂移退 V2，生产规格缺失退 V3，结构根因退 V1。工程可交付通过不能覆盖 V2a/V2b 视觉可交付或全局一致性失效；进入 V5 时各结论必须同时有效。

## V5 结构化集成与动态玩法视觉验收

1. 玩法与美术协作，把已验收资源装配为独立 GameObject、命名容器、图层、布局/表现预制数据和纯表现配置；不得用整张效果图替代可交互结构。
2. 玩法独占规则、状态、交互代码；美术可以调整不改变玩法的布局与表现集成。跨边界改动停止并交回所有者。
3. 提供动态可玩片段、同屏截图或可复现交互轨迹，对照主锚点和分系统锚点验证跨场景/状态的形状、比例、材质、光源、描边、图标语法、识别、预警、反馈、遮挡、移动端缩小可读性、关键状态和性能峰值。原子资源以该证据完成 V5 集成 F1。
4. 清除低保真纹理、路径、代码分支和引用；保留调试工具必须与正式运行隔离。
5. 组件/资源集和场景/系统路径在 V5 用 F3 聚合集成与跨域风险；原子资源只有出现跨域风险才执行 F3。资源执行偏差返回 V4，生产设计或基线绑定问题返回 V3，方向/动态样片/全局规则漂移返回 V2，结构或玩法视觉契约问题返回 V1；原子资源引用基线失效时升级路径。冻结基线变更后标记失效证据，并从最早受影响阶段重验。只有受保护决策进入 F4。

## 完成条件

适用 V 阶段证据、适用 F2、适用时 F3、按需 F4、视觉可交付与工程可交付、当前冻结全局基线、资源绑定、跨资源联系表、同屏/运行态一致性、契约与预算来源、机器清单、授权、正式资源、动态玩法视觉证据、结构化集成与低保真清理全部有效后才能报告视觉完成。原子资源可引用既有 V1 契约、视觉可交付结论、全局基线与预算，不为形式重跑 V1。静态高保真、像素接近、资源齐全、源码检查或构建成功都不能单独通过。
