# 美术生产与结构化装配

新建或重做场景、界面、预制体或成套视觉资源时，强制使用标准通道并严格按 A1 至 A6 顺序执行；每个候选产物同时执行总控 [多级漏斗审核](../../phaser4-game-orchestrator/references/review-funnel.md) 的 F0 至 F3，只有受保护决策按需进入 F4。不得用后续产物反向替代前置审核。参考截图、录屏、效果图和“按这个实现”只是输入，不是审核结论；继续任务、未提出异议、批准其他阶段或旧版本也不能推断当前候选通过。

## A1 低保真结构审核

1. 玩法使用代码和 Phaser 基础图形生成可运行的灰盒结构，不使用最终美术：矩形、圆形、文本标签、占位颜色和明确边界。
2. 为场景、容器、组件、交互区和资源槽分配稳定 ID，说明尺寸、相对位置、层级、锚点、状态、输入区域、响应式约束、动画意图及复用关系。
3. 将低保真代码、占位资源和纹理键放在独立路径或命名空间，禁止与正式资源共用键，确保最后可完整删除。
4. 在目标画布和至少一种目标输入下运行，提交截图或录屏、结构说明、资源依赖清单和功能验收记录。F1 重放功能契约，F2 审核玩法与结构，F3 关闭跨域问题；只有行为未知、信息结构取舍或范围变化时才进入 F4。只还原布局不得通过 A1。

未通过 A1 漏斗时只修改低保真结构，不生成高保真效果图。

## A2 高保真效果图审核

1. 以已确认的低保真截图、结构说明、画布比例和视觉方向为约束生成高保真效果图；不得擅自改变已确认的交互结构、内容层级或资源槽。
2. 效果图展示完整状态和关键变体，使用目标分辨率或可证明足够的源分辨率，并记录生成提示、模型或编辑来源、版本及授权信息。
3. 提交低保真与当前版本高保真效果图对照。F1 检查版本与状态覆盖，F2 审核构图、色彩、材质、角色和 UI 风格，F3 核对功能结构；新的视觉方向或代表性基准画面进入 F4 并保存当前版本结论，已冻结方向内的派生状态由 F2/F3 关闭。

未通过 A2 漏斗时只迭代效果图，不制作正式单图。

## A3 效果图审阅

1. 审阅效果图是否保持 A1 结构，是否覆盖全部状态、反馈、文本安全区和目标宽高比。
2. 检查玩法可读性、视觉层级、遮挡、透视、光照、边缘信息、缩放清晰度、风格一致性、平台安全区和单图可生成性。
3. 在 F2 把问题标为“通过”“待修改”或“阻断”，一次性提交位置、影响和证据；修订效果图后从 A2 最早受影响的审核层复核。

只有审阅通过的效果图可以进入 A4。

## 正式代码绘制边界

1. `Phaser.Graphics` 只允许用于动态进度、遮罩、点击区域、简单线条、调试显示、无明显材质要求的基础几何，以及无法预先烘焙的实时变化；调试显示不得进入正式候选画面。
2. 主面板和成套弹窗外壳、复杂按钮底图、道具和商品图标、徽章/折扣牌/礼包装饰、翅膀/爱心/金币堆等插画对象，以及参考图中承担主要视觉识别的 UI 元素，只要具有明显材质、体积、纹理、复杂高光、内外阴影、装饰花纹或角色化造型，就不得使用 `Phaser.Graphics` 作为正式高保真实现。
3. 上述对象必须进入 A4，并在 A5 使用正式透明位图、九宫格、序列帧或获批准的矢量资源。允许保留的代码绘制对象也必须在 A4 标记用途和允许理由；理由不成立时改为正式资源。

## A4 单图框选审核

1. 在已审阅效果图副本上用清晰矩形或轮廓框出所有需要生成或处置的独立对象，并赋予唯一编号；不得覆盖或修改原始效果图。带编号框选图是必交产物。
2. 框选必须覆盖角色及状态、部件、道具、地形、背景层、按钮状态、UI 装饰、图标、特效帧和其他运行时资源；允许保留的纯代码图形和动态文本明确标为“代码绘制”，无需拆分且使用已批准正式资源的内容标为“复用”。
3. 完整单图清单逐项关联框选编号、用途、复用关系、目标尺寸、透明要求、锚点、九宫格、动画帧、纹理键和遮挡补全方式，并明确归入“代码绘制、复用、新生成、重绘、删除”五类之一。标为代码绘制时必须记录符合允许范围的理由。
4. 对遮挡、重叠或效果图中不完整的元素说明补全方式；检查遗漏、重复、错误合并和无运行时用途的碎片。
5. 提交框选效果图与单图清单：F1 检查完整性，F2 审核拆分和技术规格，F3 核对运行用途；只有新增预算、授权风险、主要识别对象处置或不可逆批量生产成本时进入 F4。任何框选或清单变化都从最早失效层复核。

未通过 A4 漏斗时不得生成、拆分或补绘正式单图。

## A5 正式单图生成与验收

1. 按已通过漏斗的框选效果图和单图清单执行 references/effect-image-splitting.md，先查重，再生成、拆分或补绘正式单图。
2. 为清单中每个正式资源交付可访问的实际文件，并完成深色与浅色背景透明边缘、尺寸、锚点、帧序、九宫格、采样溢色、纹理键和性能检查。
3. 在 Phaser 中实际加载并按目标规则缩放，保存加载与缩放截图以及目标视口运行证据；只检查文件存在或尺寸不算 Phaser 验证。
4. 将正式路径、拆分 ID、来源版本、授权/生成记录、验证证据和发布资格写回资源登记。A4 未列出的新资源必须返回 A4 补充确认。
5. 维护“未完成和未验收资源清单”，即使为空也明确记录；F1 完成文件与 Phaser 验证，F2 审核资源质量和权属，只有偏离视觉方向或出现授权/成本取舍时进入 F4。不得用 A2 的方向批准或 A4 的处置结论替代 A5 客观审核。

任一主要视觉对象缺少正式文件、登记、深浅底检查、Phaser 加载与缩放截图、目标视口证据或适用审核层结论时，不得开始对应预制体或场景的正式装配，不得进入 A6。

## A6 结构化装配与低保真清理

1. 玩法使用通过 A5 的资源拼装正式 Phaser 预制体或场景。保持对象独立，以命名容器、图层和 GameObject 表达层级、变换、锚点、深度、交互区、动画、响应式约束和复用关系；除明确批准的完整背景外，不得把效果图或整屏截图扁平化为场景。
2. 对照 A1 结构、参考功能契约和 A2 效果图验证布局、输入、规则、状态迁移、时序、反馈、成功/失败、异常恢复、缩放、动画、资源释放和目标设备表现；记录视觉与功能偏差。F1 执行测试与对比，F2 分别审核功能和视觉，F3 完成跨域回归与风险聚合；资源问题返回 A5，结构、功能或交互变化返回 A1，并从最早失效层复核。只有验收标准外的主观取舍或明确要求人工终验时进入 F4。
3. 正式预制体或场景验收通过后，搜索低保真路径、模块、资源键和引用。只有确认没有运行时、测试、构建或配置引用时，才删除低保真代码和占位资源，并重新运行测试和生产构建。
4. 视觉检查至少覆盖外轮廓与构图、元素位置和尺寸、层级与遮挡、字体/描边/阴影、材质/纹理/高光、图标细节、安全边距、裁切与越界、九宫格变形和不同宽度下的等比缩放。视口或其他对比条件不一致时只能标记“未验证”。
5. 保留低保真结构说明、各层审核记录、框选效果图、资源登记、参考图、运行图、对比产物和正式装配证据，便于审计；只删除低保真实现产物。

源码方法名、固定坐标字符串、TypeScript 类型检查、单元测试、生产构建成功、控制台无错误、元素存在或“看起来接近”不能单独作为视觉通过证据。源码标记测试只能称为“结构回归”，禁止命名或表述为“视觉回归”。

完成定义：只有 A1 至 A6 的 F1/F2/F3 证据有效、按规则触发的 F4 均有当前版本明确结论、正式资源全部登记并通过 Phaser 验证、运行时没有未批准低保真替代物、同条件逐状态视觉对比和功能契约通过、低保真与占位资源已清理、构建和回归测试通过，才能报告“高保真完成”“视觉还原通过”或“A6 完成”。人工指出明显细节不足时立即撤销完成状态，先归因到 F1/F2/F3，再按问题退回 A2、A4 或 A5；只有取舍本身需要人工时才进入 F4。
