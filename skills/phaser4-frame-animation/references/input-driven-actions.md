# 操作驱动的多段动作设计

当动作包含连击、跳跃攻击、蓄力释放或其他由输入与状态决定的后续段时读取本文件。游戏表现、操作手感与表演构思共同决定动作设计；沿用当前玩法合同，并将结论写入既有 Work Item 设计工件，不新增全局阶段或资源 schema。

## 先定义可操作的分段

先列出玩家做什么、何时可以做、角色如何响应，再为每条可达路径设计姿态与节奏。由输入或状态决定是否发生的后续行为，必须拆成可独立进入、结束或切换的动作段；同一段内的准备、释放与收势可以继续细分为表现阶段。整组关系用于保证表演统一，运行时按有效条件逐段推进，不能一次输入后无条件播完整套。

每条分支记录以下内容；不适用项省略，尚未定义的玩法事实标为待确定并交玩法负责方决策：

| 项目 | 设计工件需要说明的内容 |
| --- | --- |
| 当前段与进入条件 | 段标识、地面/空中等状态、前置段、触发输入及允许进入条件 |
| 输入窗口 | 以当前段或指定玩法事件为基准的开启/关闭时点、计时基准、边界是否包含端点；不能仅写“收势时可以连击” |
| 输入语义 | 按下、释放、持续按住或组合输入，方向与目标条件；长按和重复采样是否算新输入由玩法明确 |
| 输入处理 | 是否允许缓冲及其时长、有效条件与消费点；已消费输入不得再次推进下一段，过期、退出或中断后的输入如何清理 |
| 成功与失败路径 | 有效输入后的目标段和切换时点；未输入、过早、过晚、错误输入或状态不满足时的收势、返回或落地去向 |
| 段内事件与权限 | 各段生效事件、允许的取消/打断条件及冲突优先级；输入接受时点、生效时点和实际切换时点分别记录 |
| 表现与资源映射 | 窗口前后姿态、成功连接与失败收尾、位移/朝向承接、各段与真实帧范围或独立资源的映射 |

窗口期内的有效输入才可触发后续段。默认不把窗口外输入保存到窗口开启后使用；只有当前玩法明确允许缓冲时，才按其规则记录和消费。窗口接受一次输入不代表同一输入可以穿透多段，也不代表收到输入后必须立即切换。持续按住、快速连按和自动连击分别处理，不互相替代。

输入窗口使用明确的玩法计时基准，资源帧位只作映射。帧率、采样或播放速度变化不能静默放宽窗口；顿帧、暂停、慢动作或受击时，窗口时钟是否推进与缓冲是否有效由玩法合同确定，不从源视频时间猜测。

## 连击：每段都有继续与结束路径

以需要再次按攻击键推进的三段连击为例，先设计如下路径，窗口和参数按当前任务确定：

| 当前段 | 满足条件的路径 | 不满足条件的路径 |
| --- | --- | --- |
| 第一击 | 在第一击衔接窗口内收到新的有效攻击输入，按约定切换点进入第二击 | 第一击正常收势并返回允许状态，不播放第二击 |
| 第二击 | 在第二击衔接窗口内再次收到有效攻击输入，进入第三击 | 第二击完成自己的结束路径，不播放第三击 |
| 第三击 | 按终段规则完成事件与收势 | 返回终段规定的状态，不自行循环或回到第一击 |

各段必须有可用的未衔接收尾，不能只制作第一击直接接第二击的成功版本。可复用已满足姿态与节奏要求的收尾，不强制每个分支新增文件；需要独立收尾或过渡时纳入真实素材生产。后段入姿承接前段的发力、随动和重心，窗口期的可衔接姿态也应让玩家有机会感知节奏。窗口的开启与关闭不等于角色必须静止等待，表现不擅自延长控制锁定。

只在项目已定义命中确认、资源消耗、方向分支或其他前提时叠加这些条件，不为所有连击添加统一机制。整套成功连击可作为表演审阅路径，但还须审阅只打一段、只打两段和允许的中断路径。

## 跳跃攻击：输入与空中状态共同决定分支

跳跃和空中攻击按操作与状态拆段。按任务选择起跳、上升、下落、空中攻击、落地及恢复等实际需要的段，不能把“跳跃攻击”默认做成从起跳到攻击再落地的自动整段播放。

- 跳跃输入触发跳跃；只有处于允许的空中状态与攻击窗口，并收到有效攻击输入，才进入空中攻击。没有攻击输入时沿正常跳跃路径继续。
- 明确允许上升攻击、下落攻击或两者中的哪些路径，以及每次腾空可攻击次数、是否可重复输入；未定义时不默认无限空中攻击。
- 空中攻击是否改变水平移动、重力、竖直速度或朝向由玩法定义。视觉根运动服从实际角色运动，源素材长度不决定滞空时长。
- 明确攻击尚未播完就落地、落地与攻击输入同一时点、受击或状态退出时的优先级、事件是否仍生效及目标动作。不得为播完素材推迟落地，也不无条件补播未发生的攻击事件。
- 设计正常落地与攻击后落地的可用衔接；确有不同入姿或恢复需求时交付对应过渡，不能用定格悬空等待或强回待机掩盖缺失路径。

这些是需要决策的项目，不是强制为每个游戏增加相同的跳跃规则。确实无法推导的玩法权限只暂停受影响分支的设计，其余明确部分可继续。

## 把操作意图转为游戏表现

在设计理念中说明玩家如何感知响应、蓄势、可衔接时机、输入被接受后的变化及错过后的自然收尾。使用当前风格适合的姿态、轨迹、速度反差，以及已授权的音效或特效帮助读懂操作节奏；不强制新增窗口提示 UI，也不增加尚未成立的攻击或命中反馈。

操作需求会反过来影响关键姿态、段长、恢复时机与过渡资源。先保留即时响应与既有操作权限，再安排夸张和跟随；不能为追求完整表演额外锁输入，也不能只靠提高 FPS 处理窗口与事件错位。方案说明必须包含成功推进与未推进的体验，不能只描述最顺利的整套表演。

## 制作、接入与验证

V2 交付分段关系、逐段局部时间轴、输入窗口、事件、分支去向及资源需求。整组时间轴用于关联各段，实际路径时长随选择变化，不强行给所有分支同一固定总时长。方案确认沿既有流程执行。

V3 可共享连续来源，也可按操作分段制作；来源组织服务于可播放路径，不以减少生成任务为由缺省分支。对共享来源明确各段边界，按实际工具能力剪出派生输入并分别人工验收后抽帧；图片路线保留各段真实来源和依赖。预览以真实素材展示成功路径与各个未衔接结束路径，缺素材时保留未验证项。资源文件和报告不替代运行时输入判断。

V4 由玩法状态决定进入、继续、中断与退出，动画完成回调只处理已定义的结束规则，不能无条件触发下一击。按当前工具与 Phaser 接入能力映射独立动画 key 或可独立播放的帧段，不虚构现有打包工具支持分支或输入窗口参数。切换与中断同步处理过期输入、事件及独立特效/音效的生命周期，避免旧回调重复伤害或错误续段。

验证同时覆盖有效窗口与拒绝路径：无输入、窗口前/内/后、开启与关闭边界、长按与连按、输入只消费一次、第二段未输入、状态变化与中断；跳跃攻击另覆盖无攻击正常落地、允许的空中阶段、攻击中提前落地及落地/输入冲突。命令与测试等级按工作项确定，不要求每项启动完整游戏。确定性测试验证状态、事件次数和资源选择；真实素材衔接、节奏与操作手感由用户人工验收，不自动发起真机或分析截图。仅成功整套连播通过不足以证明可操作分段通过。
