# 动画单元与共用时间轴

在灰盒制作前读取本文件。四类动画共用这里的行为边界、时间规划与优化方法；类型制作细节由 [SKILL.md 的分类入口](../SKILL.md#分类入口)按用途路由。视频提示词、灰盒、抽帧预览和最终接入消费同一份动画计划。

## 动作分组

- 按行为语义确定动画单元：记录触发条件、初态、完整阶段序列、终态或循环周期，以及播放期间需要表达的事件。同一次触发下连续完成的阶段属于同一单元，共享时间轴与完整预览；阶段数量和事件数量不决定视频任务数量。
- 具有独立触发、分支、取消、复用或生命周期的行为可以划为不同单元，记录边界与理由。边界依据现有玩法或状态合同，不由用途类型、阶段数或输入次数反推。区分行为单元、运行时动画 key 和源素材包装：多个 key 可以来自同一完整素材，一个素材文件也不能代替行为边界定义。
- 连续单元内部默认整体制作。确需分段生产时，先写明生产理由、各段入姿/出姿、锚点、连接条件与总时间轴，并在灰盒中连续展示组合结果。不得因任务清单分行、事件数量、工具参数或生成器时长限制自行切断行为。
- 既有完整连击即使由多个输入门逐段推进，仍在共享时间轴记录完整段序、事件和输入衔接；不因拳数拆成独立生成任务。美术计划沿用现有输入、推进、取消与伤害规则，缺失的玩法决策先标明待确定，不自行增加攻击、自动连击或伤害。
- 独立动画单元可按[区域规划](region-planning.md)合并为一个视频生成批次，在同一画面的多个固定区域同时呈现。每个区域分别记录用途类型、完整时间轴、有效源区间、游戏时间映射、FPS 和输出尺寸，批次总时长不能替代各自动画时长。类型、播放方式、行为单元、视频批次和 key 数量分别决定。

当前抽帧工具每次为一个固定区域输出一个覆盖全部输入帧的动画 key；未指定区域时使用整幅画布。一个批次的不同区域分别传入 `--region x,y,width,height`，生成各自图集和合同并共享视频来源。玩法确需按时间边界生成多个 key 时，先剪出保留整幅空间布局的派生输入，再按对应区域抽帧；保留整组来源与连续预览，不直接缩小报告帧范围来冒充时间裁剪。

## 游戏时间先于视频时长

先依据行为节奏决定一次播放的总时长或循环周期，再分配各阶段和事件。优先读取已有玩法时序；没有时序时提出明确建议并通过灰盒确认，不套用生成器或示例的固定时长。相邻阶段按行为要求直接过渡，只有计划明确要求时才返回初态、重复准备或保持姿态；各阶段不必等长。

动画计划保存为项目内设计工件；分类与优化参数不扩展报告或 accepted 合同 schema。至少包含：

| 信息 | 要求 |
| --- | --- |
| 用途类型与视觉依据 | 普通/角色/特效/UI 帧动画、选用的分类参考、当前视觉基线与对象性质 |
| 行为单元与边界 | 名称、触发条件、初态、阶段顺序、终态或循环周期；现有输入/状态机制与生产、运行时分段原因 |
| 整组时长与 FPS | 游戏总时长（毫秒）、目标 FPS 与预计帧数 |
| 阶段区间与关键姿态 | 每段开始/结束毫秒、运动/过渡/保持意图、关键姿态或关键视觉状态与连接方式；区间覆盖整组，无未说明空档 |
| 事件与衔接 | 事件名称、作用、同一时间轴上的毫秒与目标帧、既有输入/状态衔接窗口；无事件时明确记录无 |
| 播放与保持 | 循环、单次、组合、终态保持分别记录，可按任务组合；有意定格的区间、用途、时长或结束条件；循环接缝要求 |
| 锚点与允许位移 | 固定语义根、视角、朝向、允许位移的方向/轨迹/范围及与运行时位置的关系，不把工具默认根点当作设计结论 |
| 运动范围与显示尺寸 | 完整运动包络、安全边距、目标显示宽高、输出 cell；获明确授权的裁剪例外单独记录 |
| 背景与叠加 | 是否保留背景、硬边/真实 Alpha/遮罩或修帧方案；涉及叠加时记录透明度、颜色和混合要求 |
| 类型表现参数 | 重量感、夸张程度、速度变化、停顿和跟随运动的取舍及依据；不适用的项明确不采用 |
| 视频批次与区域 | 批次 ID、默认 768p 或经当前任务确认的 2K、画幅/音频、预期/实际宽高、区域 ID 和 x/y/width/height、效果图尺寸推理依据、独立输出尺寸 |
| 视频时间映射 | 源视频时长独立记录；收到视频后补齐有效区间、裁剪与重定时映射 |

预计帧数按游戏时长乘 FPS 计算并记录取整规则，事件映射至可播放帧；量化容差最多一个目标帧间隔，不能丢失关键事件或短促衔接。若当前 FPS 无法表达事件，调整 FPS 或动作设计并交付灰盒确认，不盲目拉长动作。

提示词对每个阶段同时写出时间区间、动作意图、关键事件和到下一阶段的过渡；灰盒按同一时间轴完整播放。只列姿态名称或笼统写“自然流畅”，不能代替阶段之间的时间与连接约束。

游戏时长、阶段比例、命中停顿、连击次数、FPS 和音频方案由当前用途、玩法与视觉基线确定。示例或工具缺省值不能作为全局制作标准，也不能把当前拳手或三连击案例推广到其他动画。分辨率遵循共用约定：默认 768p，需要 2K 时先说明理由并询问用户，不能直接升级。

## 共用质量与优化

先把反馈对应到可观察的问题，再使用当前类型规则调整；共用质量标准如下：

| 标准 | 判断依据与优化方向 |
| --- | --- |
| 可读性 | 在目标显示尺寸下，初态、主要变化、关键姿态/视觉峰值和终态是否可辨；优先调整轮廓、幅度和关键状态，而非单纯加帧 |
| 节奏 | 阶段长度、速度变化和保持是否表达对象性质与任务意图；按阶段调整时间映射，不统一加速或套用蓄力、爆发、固定停顿 |
| 主次关系 | 主对象、关键信息与事件是否先被识别；辅助运动、光效和装饰的强度与出现时点是否符合层次 |
| 连续性 | 相邻阶段、循环接缝或组合连接是否出现未计划的位置、形态、方向或速度跳变；保留有意保持、遮挡和类型允许的跳变 |
| 事件同步 | 可见动作/效果与已有玩法、宿主或 UI 状态事件是否对齐；修正事件表达和帧时序，不用美术方案改触发次数与行为权限 |

重量感、夸张、停顿与跟随运动是可配置的表现手段，按类型和视觉基线说明采用理由与范围。普通机械运动可以强调规律，角色发力可以使用速度反差，特效可以强调峰值与衰减，UI 可以强调响应和信息层次；这些判断只在对应任务中应用。

优化时先区分时间问题与图像问题：阶段过长、事件错位或重复周期先整理有效区间和阶段重定时；轮廓、姿态、轨迹、颜色与边缘问题修对应帧及相邻帧。改变已确认的游戏时长、阶段、事件、保持或运动方案时，更新灰盒并重新确认；仅按已确认方案纠错和细化时保留有效确认。两类修正均保留已修图成果并更新来源映射、产物与证据，不以来源视频中的缺陷作为最终验收要求。

## 运动、保持与循环

运动阶段须在计划区间内持续推进；静止保持必须在计划中标注区间与意图，不能因源素材没有后续动作就自动延长。低幅度运动仍属于运动，不能默认定格；单次动画按计划结束或保持终态，不自动循环或添加等待。

循环动画需在灰盒和正式预览中跨周期连续播放，覆盖完整周期内部与相邻周期接缝。除计划明确允许的跳变外，接缝应保持姿态、位置、运动方向与速度连续，不重复保持端点，不由播放器加入计划外等待。仅确认首末帧位置相同不能证明循环通过。

缓动极值处短暂减速、有意停顿和终态保持按动作计划保留；未计划的定格、空白等待与重复端点应修正。不要自动删除所有相似帧，避免破坏低幅度运动或设计中的保持阶段。人工审阅分别判断阶段内运动、阶段连接、事件时刻与播放边界，不以某一类动作的运动模式要求所有动画。

## 视频节奏整理

当前 `video-to-atlas.mjs` 支持 `--region` 空间裁剪，但仍对输入视频的完整时间段抽帧，并使用同一 FPS 播放全部帧；没有时间区间选择、分段剪辑或独立播放速度参数。降低 `--fps` 同时减少采样帧数并按同一帧率播放，不能缩短动作。不能把区域裁剪当作时间裁剪，也不要只改报告中的帧率。

1. 保留用户原视频，按区域核对已确认动画计划，分别记录阶段、事件、停顿的实际源时间。某个区域的源时长满足其游戏时序时可直接抽帧，不额外变速。
2. 某区域含前后等待、重复周期或未计划停顿时，用本地剪辑或 `ffmpeg` 先选择该动画的有效区间；多区间依原顺序连接。较长但内容完整时按阶段重定时，不用整体加速掩盖阶段错误。不同区域的有效时间段不必相同，分别准备对应输入。
3. 将整理结果保存为独立派生视频，保留整幅空间布局、尺寸与朝向，再由抽帧工具裁区域，避免重复裁剪或原点失配。源中存在的音轨按当前任务合同维护与时间映射对应的处理，记录是否保留及处理配置。保留原视频与派生视频的路径和 SHA、剪辑命令/配置及各段源时间到游戏时间的映射。生成器最短交付时长只影响源视频与映射，不改变各自动画时长，不用静止填充凑时长。
4. 将派生视频作为 `--input-video` 与合同中的 `source_video`，报告 SHA 对应实际抽帧输入；原视频和时间映射保存在 Work Item 设计证据中。缺失动作或不能平滑连接时，记录缺陷并在正式帧阶段补齐/修正，不伪造已有源视频事件，也不默认重新生成视频。
5. 抽帧后核对 `帧数 / FPS` 与整组游戏时长（最多一个目标帧间隔的量化差）、各事件帧、阶段顺序和计划保持。偏差先修正时间映射或按来源顺序删去未计划保持帧，再交付人工检查完整行为、阶段连接与对应的单次/循环/终态播放方式；文件 SHA、格式校验和报告 `PASS` 不能证明节奏通过。

抽帧后才发现时间问题时，可以按来源顺序删去未计划保持帧，或在已有帧槽位修正过渡姿态；保留已修正图片，重新连续编号，并保留剩余帧真实的来源时间戳与 SHA，更新来源映射、图集、报告与预览。现有合同要求来源时间戳严格递增，不支持交换来源顺序、复制来源帧或无来源的新帧；需要这些操作时，先将编辑结果保存为新的真实视频来源，再抽帧、记录其 SHA 与来源时间，并迁移修图成果，不以改写来源字段绕过校验。为落实已确认时间轴而整理源视频不需要重新确认；改变游戏总时长、阶段节奏、关键事件或有意停顿则先更新灰盒并重新确认。
