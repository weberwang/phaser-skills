# 通用帧动画工作流接入合同

执行者按[执行代理](../SKILL.md#执行代理)固定为 `gpt-6.1-sol`、`max` 的子代理；主代理交接人工确认、实际视频和限定任务包，同一 Work Item 的连续制作与修正复用该代理。

帧动画先按 [SKILL.md 的分类入口](../SKILL.md#分类入口)选择普通、角色、特效或 UI 帧动画规则，再走统一生产流程。正式资源以视频抽帧得到初始帧，不采用首末帧递归插帧路线；视频作为动作草图，抽帧后可局部修正，最终动画以游戏要求与视觉基线为准。灰盒不是正式抽帧来源。全局视觉阶段仍是 V0→V5，灰盒与确认属于 V2 内部步骤，不改写全局 `visualStage`。

用途类型、行为单元、播放方式、视频批次与 key 数量分别确定。按[区域规划](region-planning.md)组织兼容的多区域来源；各区域分别记录类型、有效源区间和游戏时间映射，每个输出独立绑定图集、报告、预览与播放设置。分类与优化参数放在设计工件中，沿用现有报告及 accepted schema。

| 步骤 | 产物 | 停止条件 |
| --- | --- | --- |
| 动画与批次规划 | 用途类型及对应规则、独立单元时间轴、事件、播放方式、FPS、效果图尺寸推理、区域与输出 cell | 完整行为不因阶段或拳数拆生成任务；保留既有输入机制，类型不决定批次数量 |
| 灰盒预览 | 隔离的可播放 HTML、动作参数、当前候选文件身份 | 交付后等待用户明确确认；调整意见只推进灰盒修改 |
| 灰盒确认 | 当前候选版本、预览与参数 SHA、用户确认依据 | 无确认或文件变化时不进入视频提示词与正式制作 |
| 写视频提示词 | 共用约束＋当前类型规则＋动画参数，每批保存；默认 768p，音频按任务合同 | 需要 2K 时说明依据并询问用户，确认前不升级；提示词交付后等待真实视频 |
| 接收视频 | 原视频、实际显示尺寸、音轨和校准后的区域 | 文件不存在、不可解码或区域未确定时不抽帧；记录生成参数偏差 |
| 视频节奏整理 | 有效动作区间、源到游戏时间映射、必要时生成独立派生视频 | 未计划停顿、重复周期或时间偏差未处理时不交付正式动画 |
| 抽帧与图集 | 每个区域独立的固定 cell 图集、JSON 报告、HTML 预览 | 按固定区域裁剪后去背景和等比缩放；区域、FPS 或尺寸变化要重做 |
| 审阅与接入 | 浏览器播放审阅、Phaser 合同 | 动作和外观问题均修对应图片并更新图集与证据；最终动画按游戏要求验收；运行态在全局 V5 验证 |

## 灰盒确认

按[共用时间轴](action-timing.md)规划各独立动画，确认覆盖用途类型、当前类型的具体判断、行为边界、批次分组、尺寸推理、区域布局、游戏时长、阶段、关键姿态/视觉状态、事件、允许位移和播放方式。多阶段或组合行为展示完整时间轴；循环跨周期检查接缝，单次检查结束，终态保持检查结束条件。批次预览检查完整入镜与跨区干扰；类型相关的叠加或界面上下文按对应参考展示。

灰盒必须能播放实际完整动画，不能只交文字方案或静态关键帧。优先复用隔离预览；无现成能力时生成无需启动服务即可打开的独立 HTML，以 Canvas/SVG 几何、轮廓或关节示意表达设计，不依赖正式美术、真实视频或正式 Scene。提供播放/暂停、重播与逐帧查看，标出阶段、关键事件、局部锚点、区域尺寸和安全边距；标记属于预览界面，不烘入正式资源。多区域可有各自尺寸、FPS 和时间轴。涉及输入门或状态切换时，展示既定推进和衔接，完整演示不构成修改玩法输入的授权。

灰盒及其参数、候选版本、文件 SHA 和人工确认依据保存到当前 Work Item 设计证据，不放入正式 `asset.runtime_outputs`，也不冒充 accepted 图集。**交付后等待用户明确确认当前候选**；反馈只推进灰盒修订，确认前不写正式提示词、抽帧或接入。超时、文件生成成功、视频交付或其他候选确认均不替代本次确认。

确认只对当前方案有效；时序、关键姿态、事件时机、播放方式、锚点、位移或运动范围变化时旧确认失效，先更新灰盒并重新交付确认，再推进正式制作。沿用已确认方案的局部纠错与美术细化可保留有效确认。灰盒和抽帧预览均由用户人工验收，不自动截图、不自动启动真机验收。

## 视频提示词

仅在当前灰盒候选得到用户确认后编写，动作描述须沿用确认的参数与关键事件。

提示词组合为三层，保留当前候选的实际参数，不把类型规则写成笼统的“流畅”“有张力”：

| 层 | 内容 |
| --- | --- |
| 共用视觉与资源约束 | 当前基线/参考身份、用途、视角、比例、固定资源镜头、区域布局、锚点、完整入框与获授权裁剪例外、背景和输出尺寸 |
| 当前类型规则 | 只从选中的分类参考提取本动画适用的具体判断，例如对象运动规律、身体承重与发力、特效峰值/消散或 UI 状态可读性；说明允许夸张、停顿和跟随运动的依据与范围 |
| 当前动画参数 | 行为边界、初态/终态、游戏时长、各阶段区间与关键姿态/视觉状态、事件及既有输入衔接、播放方式、允许位移、FPS、源到游戏时间映射、生成画幅/音频和实际交付路径 |

视频默认 **768p**；质量或区域像素预算需要 **2K** 时，先说明依据并询问用户，取得当前任务确认后再采用并记录计划宽高。音频及角色素材中的特效、声音、镜头反馈按任务合同选择，不默认烘入。多区域逐项描述类型、`x/y/width/height`、局部锚点和完整时间轴，各区域独立呈现，不能串动作；完整运动范围默认入框，不绘制标签或边框。只有明确授权后才逐项描述裁剪例外。尺寸推理与实际视频校准见[区域规划](region-planning.md)。

独立精灵区域不混入无关 UI、文字或场景；场景层与 UI 帧动画遵循自身资源合同。允许的位移、形变和姿态夸张须有设计依据，禁止未计划漂移或比例变化。各区域关键状态与事件须在目标尺寸和 FPS 下可读。颜色去背景只用于已确认纯色硬边，实际抽帧须显式传入 `--edge-profile hard-edge --color-separation-verified`，裁剪区域整圈为背景；复杂或半透明边缘使用真实 Alpha、遮罩或图片修复。提示词交付后等待真实视频，收到文件后记录实际动作、时机与裁剪缺陷；提示词不能替代内容检查。

## accepted 资源文件门

文件门只证明产物身份和结构一致，不证明分类、表现或节奏正确。提交 accepted 前须在 Work Item 设计证据中保留用途类型与优化依据、完整动画计划、当前灰盒确认、每个区域的有效源区间/游戏时间映射及最终人工验收结果。按类型检查可读性、节奏、主次、连续性和事件同步，核对时长误差不超过一个目标帧间隔、关键事件不缺失、阶段间无未计划重置、运动/保持和播放边界符合计划；不新增 schema 字段来替代设计证据。

发生视频剪辑或重定时时，`source_video` 绑定实际用于抽帧的派生视频，`quality_report.input.video_sha256` 与之匹配；原始视频身份、剪辑命令/配置与时间映射另存设计证据，不新增未经工具支持的 manifest 字段。结构校验器不会自动执行上述人工节奏检查。

每个动画的 `asset.frame_animation` 绑定提示词、真实视频、自己的报告、预览和 spritesheet 路径与 SHA。共享输入时，提示词和视频绑定可以相同，区域与独立图集不能混用。文件门复算 SHA，核对视频 SHA、区域位置与宽高、真实显示画布边界、FPS、帧数、输出 cell、去背景配置、图集尺寸与 Phaser 帧范围。图集必须位于 `asset.runtime_outputs`，`spritesheet.runtime_url` 与报告的 `phaser.preload.url` 相同。

合同使用 `phaser4-video-atlas-workflow/1`，必需字段示例：

```json
{
  "schema": "phaser4-video-atlas-workflow/1",
  "status": "accepted",
  "work_item_id": "work-item-animation-batch",
  "candidate_version": "candidate-animation-batch-v1",
  "settings": {
    "fps": 12, "width": 160, "height": 144, "remove_background": true,
    "region": { "x": 16, "y": 16, "width": 320, "height": 288 },
    "anchor": { "x": 160, "y": 264 }
  },
  "video_prompt": { "file": "evidence/animation-batch.prompt.txt", "sha256": "sha256:<64位十六进制>" },
  "source_video": { "file": "art/animation-batch.mp4", "sha256": "sha256:<64位十六进制>" },
  "quality_report": { "file": "evidence/mechanism-open.video-atlas.json", "sha256": "sha256:<64位十六进制>" },
  "preview": { "file": "evidence/mechanism-open.preview.html", "sha256": "sha256:<64位十六进制>" },
  "spritesheet": { "file": "public/assets/mechanism-open.png", "runtime_url": "assets/mechanism-open.png", "sha256": "sha256:<64位十六进制>" }
}
```

`settings.width/height` 是最终 cell 尺寸，`settings.region.width/height` 是源视频裁剪尺寸，两者可以不同。区域模式下，清单的 `settings.region`、报告的 `input.region` 与 `settings.region` 必须逐字段一致；显示画布宽高必须有效且完整容纳区域。整画布模式不填区域字段。以上 SHA 占位符须替换为真实摘要。

显式 `settings.anchor` 是区域内部的局部语义根坐标，与报告 `input.anchor/settings.anchor` 绑定一致；省略时由工具使用底部中心建议点（源宽/2、源高-1）。每份报告都必须包含 `cell.source_anchor`、实际缩放内容矩形 `cell.content_rect` 和 `cell.target_anchor`，整画布模式也适用。文件门核对显式或默认源点、缩放留白变换和 Phaser origin，避免把根点绑定到留白边缘；删除布局字段不能绕过校验。源点可以位于特效中心、物件安装点等，不限定角色脚底。

合法空透明帧保留帧索引和来源时间，例如特效消失或 UI 隐藏；整段全空时抽帧工具拒绝，不能通过删除空终态来缩短动画。单帧空结果仅由动画调用显式允许，不改变普通静态资产去背景的空图拒绝规则。

默认 768p、经确认的 2K 与按合同选择的音频属于生成计划和接收检查项，记录当前请求、2K 确认依据、实际显示尺寸与 `input.has_audio` 事实；不把缺省值当作报告字段扩展或文件门的新要求。结构通过不等于生成参数或人工验收通过。原视频与派生视频保留来源身份和空间布局；源中存在且任务要求保留的音轨随时间整理维护，图集交付不代表游戏音效已接入。

初始帧数由整理后的抽帧输入时长和目标 FPS 决定，不再要求 `3、5、9、17…`；输入时长应匹配已确认的游戏时间轴，而非生成器的固定交付时长。替换抽帧输入或调整抽样 FPS、输出尺寸时重新抽帧并审阅，保留已修图成果；修改提示词或发现动作错误不默认重新生成视频。背景与外观修正优先直接处理抽帧图片，时间问题按[视频节奏整理](action-timing.md#视频节奏整理)处理。

## 抽帧后的动作与图片修正

- 视频只提供动作流程草图的期望，不作为最终正确动作的硬约束。抽帧后不论动作还是外观有问题，都直接修正对应图片或图集 cell；只有用户要求更换草图来源时才替换视频。
- 动作修正包括姿态、动作轨迹、朝向、阶段时序/关键事件/终态与循环衔接；外观修正包括造型、颜色、背景残留、透明边缘、局部缺陷和锚点对齐。按修改范围检查相邻帧，保留可用帧，以最终游戏动作要求而非视频中的错误验收。
- 保留真实原视频及初始抽帧来源记录，来源身份不代表最终动作必须与视频相同。外观修正保持当前帧索引、帧数、FPS、cell 尺寸与锚点合同；节奏修正允许按来源顺序移除未计划保持帧或修正已有帧槽位的过渡姿态，并更新索引、时间映射、产物与合同；需新增帧或改变来源顺序时，生成新的真实抽帧来源，重新抽帧并迁移已有修图，不能只修改声明或伪造来源。抽样参数错误可使用同一视频重抽，但不能覆盖已完成的修图而不保留修正成果。
- 修改实际图片后重组最终图集，复算 `quality_report.artifacts.sheet.sha256`，更新预览内的 `phaser-atlas-sha256` 和资源合同中的图集、报告、预览文件 SHA；重新审阅逐帧显示、动作连续性、关键时刻和首尾衔接。原 `source_video.sha256`、报告的 `input.video_sha256` 与每帧 `source_sha256` 仍记录初始来源，不能伪装成修改后的图片 SHA。
- 在修正记录中列出实际修改帧索引、动作或外观问题、处理方法和修正前后文件身份。图片改动使旧图集验收失效，完成更新与复核后再提交 accepted；不能只改报告而不处理实际图片。

提示词交付或网页审阅只覆盖本次资源候选；外部系统写入、真机运行、发布和付费仍遵循全局控制面的独立授权。
