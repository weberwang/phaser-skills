# 通用帧动画工作流接入合同

执行者按[执行代理](../SKILL.md#执行代理)固定为 `gpt-6.1-sol`、`max` 的子代理；主代理交接人工确认、实际来源、生成授权和限定任务包，同一 Work Item 的连续制作与修正复用该代理。实际图片生成/编辑另交图片生成代理，动画执行代理集成。

帧动画先按 [SKILL.md 的分类入口](../SKILL.md#分类入口)选择普通、角色、特效或 UI 帧动画规则，再按[来源路线](../SKILL.md#来源路线)处理素材：未指定时默认视频抽帧，固定画布图片递归补帧须有用户明确选择或切换确认。先人工确认动作时间轴设计，随后制作真实素材；视频必须人工验收当前实际抽帧输入后才能抽帧，图片逐张确认首尾和必要关键帧后再补帧。帧动画不制作灰盒或可播放占位示意。全局视觉阶段仍是 V0→V5，时间轴设计确认属于 V2 内部步骤，真实素材验收属于 V3，不改写全局 `visualStage`。

用途类型、来源路线、行为单元、播放方式、来源批次与 key 数量分别确定。按[区域规划](region-planning.md)组织兼容的多区域来源；各区域分别记录类型、有效源区间或帧位和游戏时间映射，每个输出独立绑定图集、报告、预览与播放设置。分类与优化参数放在设计工件中。视频沿用现有 schema；图片来源、报告和 accepted 使用独立 schema，避免伪造视频证据。

| 步骤 | 产物 | 停止条件 |
| --- | --- | --- |
| 动画与批次规划 | 用途类型及对应规则、独立单元时间轴、事件、播放方式、FPS、效果图尺寸推理、区域与输出 cell | 完整行为不因阶段或拳数拆生成任务；保留既有输入机制，类型不决定批次数量 |
| 动作分析与时间轴设计确认 | 动作分析依据、设计取舍、完整阶段表与事件说明、当前版本和设计工件 SHA、用户确认依据 | 无当前方案确认时不进入正式提示词与制作；调整意见只推进分析与设计修订 |
| 写正式提示词 | 共用约束＋当前类型规则＋动画参数，每批/帧保存；默认 768p，声音按任务合同 | 需要 2K 时说明依据并询问用户，确认前不升级；视频等待真实来源，图片生成须在已有授权范围 |
| 视频整理 | 原视频、实际尺寸/音轨、校准区域、有效区间与阶段重定时派生来源 | 不可解码、区域未定或时间偏差未处理时修正；源视频时长不代替游戏时长 |
| 视频人工验收 | 实际抽帧输入视频的路径/SHA、区域与时间映射、检查要点和用户验收依据 | 未验收、验收失败或视频/映射变化时不抽帧；修正方案确认不代替当前视频验收 |
| 图片来源 | 固定画布首尾、逐张确认的必要关键帧、递归计划、真实双父图与完整帧位 | 同一连续行为按前序已确认姿态承接；当前帧经一致性及衔接审阅后才推进后继，父图缺陷先修；原图、修图、生成记录及实际 SHA 齐备，复杂运动不只依赖首尾 |
| 图集 | 视频抽帧或图片清单打包，每区域独立固定 cell、报告与 HTML | 固定区域裁剪后处理背景和等比缩放；参数变化要重建，保留已修图成果；图片循环闭合参考不入图集 |
| 审阅与接入 | 浏览器播放审阅、Phaser 合同 | 动作和外观问题均修对应图片并更新图集与证据；最终动画按游戏要求验收；运行态在全局 V5 验证 |

## 动作时间轴设计确认

先按[动作分析规则](action-timing.md#先分析动作再确认)交付行为、运动、衔接/循环与节奏分析，再给出建议时间轴；分析结论与设计参数一并确认，不为两者重复建立确认门。当前方案未确认前，只推进分析或设计修订，不直接编写正式提示词或制作素材。

按[共用时间轴](action-timing.md)规划各独立动画，以可读阶段表和文字说明交付完整设计。确认覆盖用途类型、来源路线、当前类型的表现依据、行为边界、批次分组、尺寸推理、区域布局、游戏时长、阶段区间、关键姿态/视觉状态意图、事件、允许位移和播放方式。图片路线还确认固定画布、目标帧位和必要关键帧；这些是完整时间轴的采样设计，不把完整行为拆成不同技能。多阶段或组合行为列出整组时间轴，循环明确周期与闭合要求，单次明确结束去向，终态保持明确结束条件。设计中的范围与尺寸区分实测值和推断值，实际可读性、完整入框及跨区干扰留待真实素材检查。

角色按[衔接与循环设计](character-animation.md#衔接与循环设计)说明既有前置/后续行为的入姿、出姿与切换条件；循环说明进入、周期内运动与退出，单次或组合说明结束去向与已定义分支。缺失的相邻动作或玩法条件标为待确定，不自行编造切换路径。时间轴设计确认只批准行为、时序和制作参数，不能证明真实姿态、重量感、尺度稳定或循环连续性通过。

设计工件保存当前 Work Item、候选版本、来源路线、阶段/事件参数、文件 SHA 和用户确认依据，不放入正式 `asset.runtime_outputs`，不扩展报告或 accepted schema。**交付后等待用户明确确认当前时间轴设计**；确认前不写正式提示词、制作正式图片、抽帧或接入。超时、设计文件生成成功、来源交付或其它候选确认均不替代当前确认。不新增几何动画、骨架演示或占位播放页作为确认材料。

确认只对当前设计有效；来源路线、游戏时序、关键姿态意图、事件时机、播放方式、锚点、位移或运动范围发生实质变化时，更新设计并重新确认受影响部分。沿用已确认设计的局部纠错与美术细化可保留有效设计确认，但实际素材变化仍须按下方规则重新人工验收。设计确认与真实素材验收分别记录，不以其中一项代替另一项。

## 真实素材审阅与验收

视频先核对真实内容、显示尺寸、朝向、音轨和区域，再按[视频节奏整理](action-timing.md#视频节奏整理)完成必要的有效区间选择与阶段重定时。将最终实际抽帧输入交付用户人工验收；原视频已经适配时直接使用原视频，发生整理时验收派生视频。逐区域提供当前输入路径/SHA、有效区间与游戏时间映射及类型检查点，按已确认时间轴检查关键姿态、动作节奏、完整运动范围、尺度与锚点稳定、阶段/外部动作衔接、事件同步及循环/终态。用户尚未验收或判定失败时先修正并重新交付，不能先抽帧再用图集代替视频验收。

视频验收绑定当前实际输入的文件身份、区域、时间映射和用户结论，保存到设计证据。视频内容、SHA、有效区间、重定时或区域变化使受影响验收失效，重新人工验收后才抽帧；仅改变输出 cell 等抽帧参数时重新检查图集，不要求重新制作视频。计划确认、修正方案认可、旧版本通过或文件门通过，都不能替代当前实际视频验收。共享视频各区域独立验收，未通过区域不进入抽帧，保留其它区域有效成果。

图片路线在真实首尾、必要关键帧与每层递归帧上执行[一致性及衔接门](image-inbetween.md#关键帧的一致性与衔接门)，人工确认当前帧后才放行依赖它的制作。关键帧未填满的序列标明缺失槽位，不能宣称完整动作通过。两条路线最终用真实完整帧序列检查单次/循环/终态、相邻动作衔接及目标显示尺寸；预览提供播放/暂停、重播和逐帧查看，阶段、事件、锚点和区域标记仅放在预览界面。特效检查不同背景叠加，UI 检查实际布局边界。视觉显示由用户人工验收，不自动截图或启动真机。

### 设计与美术的边界

时间轴向制作交接文字或结构化的行为、时间、关键姿态意图和功能参数。正式美术的视觉依据只能来自当前任务选定的真实美术基线、用户指定图片与已确认的实际父帧，分别记录文件身份。没有现成美术时按用户需求建立真实基线；设计图表、历史占位图、骨架或几何示意不能进入生成/编辑工具的视觉参考，也不能约束正式造型、身体比例、材质或细节。

资源布局依据真实美术及完整运动范围推理。出现空间冲突时保留真实美术基线，先复核画布、统一缩放、留白与语义锚点；需要改变已确认的空间参数时更新设计并重新确认。不得让正式美术贴合占位图或以文件边界通过证明比例与动作正确。

## 视频提示词

仅在当前动作时间轴设计得到用户确认后编写，动作描述须沿用确认的参数与关键事件。

提示词组合为三层，保留当前候选的实际参数，不把类型规则写成笼统的“流畅”“有张力”：

| 层 | 内容 |
| --- | --- |
| 共用视觉与资源约束 | 当前基线/参考身份、用途、视角、比例、固定资源镜头、区域布局、锚点、完整入框与获授权裁剪例外、背景和输出尺寸 |
| 当前类型规则 | 只从选中的分类参考提取本动画适用的具体判断，例如对象运动规律、身体承重与发力、特效峰值/消散或 UI 状态可读性；说明允许夸张、停顿和跟随运动的依据与范围 |
| 当前动画参数 | 行为边界、初态/终态、游戏时长、各阶段区间与关键姿态/视觉状态、事件及既有输入衔接、播放方式、允许位移、FPS、源到游戏时间映射、生成画幅/音频和实际交付路径 |

视频默认 **768p**；质量或区域像素预算需要 **2K** 时，先说明依据并询问用户，取得当前任务确认后再采用并记录计划宽高。音频及角色素材中的特效、声音、镜头反馈按任务合同选择，不默认烘入。多区域逐项描述类型、`x/y/width/height`、局部锚点和完整时间轴，各区域独立呈现，不能串动作；完整运动范围默认入框，不绘制标签或边框。只有明确授权后才逐项描述裁剪例外。尺寸推理与实际视频校准见[区域规划](region-planning.md)。

独立精灵区域不混入无关 UI、文字或场景；场景层与 UI 帧动画遵循自身资源合同。允许的位移、形变和姿态夸张须有设计依据，禁止未计划漂移或比例变化。各区域关键状态与事件须在目标尺寸和 FPS 下可读。颜色去背景只用于已确认纯色硬边，实际抽帧须显式传入 `--edge-profile hard-edge --color-separation-verified`，裁剪区域整圈为背景；复杂或半透明边缘使用真实 Alpha、遮罩或图片修复。提示词交付后等待真实视频，收到文件后记录实际动作、时机与裁剪缺陷；提示词不能替代内容检查。

## accepted 资源文件门

两条来源均登记 `asset.route: frame-animation`。视频合同和下方抽帧修正规则只在视频路线读取；图片的来源清单、生成/父图/修图证据及 `phaser4-image-atlas-workflow/1` 示例见[图片打包与接入](image-inbetween.md#打包与接入)。文件门按 schema 分派，图片不用 `video_prompt/source_video/source_timestamp`。通用资产清单的来源、许可与人工证据仍需填写。

文件门只证明产物身份和结构一致，不证明分类、表现或节奏正确。提交 accepted 前须在 Work Item 设计证据中保留用途类型与优化依据、完整动画计划、当前时间轴设计确认、实际抽帧输入视频或关键帧的人工验收依据、每个区域的有效源区间/游戏时间映射及最终完整序列验收结果。按类型检查可读性、节奏、主次、连续性和事件同步，核对时长误差不超过一个目标帧间隔、关键事件不缺失、阶段间无未计划重置、运动/保持和播放边界符合计划；不新增 schema 字段来替代设计证据。

图片来源阶段先执行[一致性及衔接门](image-inbetween.md#关键帧的一致性与衔接门)，不能把全部关键帧独立生成后才第一次检查相邻关系。固定画布、锚点与 SHA 通过不代表实际对象比例、接触或轨迹正确；关键帧的当前人工确认先于依赖它的生成，最终完整序列验收仍单独进行。发现问题暂停受影响依赖，保留可用成果并交付新候选；结构检查通过、补帧数量增加或旧首尾确认不能替代当前帧的视觉确认。检查点、确认与返修状态记录在设计工件，不扩展来源、报告或 accepted 合同。

视频发生剪辑或重定时时，`source_video` 绑定实际用于抽帧的派生视频，`quality_report.input.video_sha256` 与之匹配；原始视频身份、剪辑命令/配置与时间映射另存设计证据，不新增未经工具支持的 manifest 字段。结构校验器不会自动执行上述人工节奏检查。

视频路线每个动画的 `asset.frame_animation` 绑定提示词、真实视频、自己的报告、预览和 spritesheet 路径与 SHA。共享输入时，提示词和视频绑定可以相同，区域与独立图集不能混用。文件门复算 SHA，核对视频 SHA、区域位置与宽高、真实显示画布边界、FPS、帧数、输出 cell、去背景配置、图集尺寸与 Phaser 帧范围。图集必须位于 `asset.runtime_outputs`，`spritesheet.runtime_url` 与报告的 `phaser.preload.url` 相同。

视频合同使用 `phaser4-video-atlas-workflow/1`，必需字段示例：

```json
{
  "schema": "phaser4-video-atlas-workflow/1",
  "status": "accepted",
  "work_item_id": "work-item-animation-batch",
  "candidate_version": "candidate-animation-batch-v1",
  "settings": {
    "fps": 12, "width": 160, "height": 144, "remove_background": true,
    "region": { "x": 16, "y": 16, "width": 320, "height": 288 },
    "anchor": { "x": 160, "y": 264 }
  },
  "video_prompt": { "file": "evidence/animation-batch.prompt.txt", "sha256": "sha256:<64位十六进制>" },
  "source_video": { "file": "art/animation-batch.mp4", "sha256": "sha256:<64位十六进制>" },
  "quality_report": { "file": "evidence/mechanism-open.video-atlas.json", "sha256": "sha256:<64位十六进制>" },
  "preview": { "file": "evidence/mechanism-open.preview.html", "sha256": "sha256:<64位十六进制>" },
  "spritesheet": { "file": "public/assets/mechanism-open.png", "runtime_url": "assets/mechanism-open.png", "sha256": "sha256:<64位十六进制>" }
}
```

`settings.width/height` 是最终 cell 尺寸，`settings.region.width/height` 是源视频裁剪尺寸，两者可以不同。区域模式下，清单的 `settings.region`、报告的 `input.region` 与 `settings.region` 必须逐字段一致；显示画布宽高必须有效且完整容纳区域。整画布模式不填区域字段。以上 SHA 占位符须替换为真实摘要。

显式 `settings.anchor` 是区域内部的局部语义根坐标，与报告 `input.anchor/settings.anchor` 绑定一致；省略时由工具使用底部中心建议点（源宽/2、源高-1）。每份报告都必须包含 `cell.source_anchor`、实际缩放内容矩形 `cell.content_rect` 和 `cell.target_anchor`，整画布模式也适用。文件门核对显式或默认源点、缩放留白变换和 Phaser origin，避免把根点绑定到留白边缘；删除布局字段不能绕过校验。源点可以位于特效中心、物件安装点等，不限定角色脚底。

合法空透明帧保留帧索引和来源时间，例如特效消失或 UI 隐藏；整段全空时抽帧工具拒绝，不能通过删除空终态来缩短动画。单帧空结果仅由动画调用显式允许，不改变普通静态资产去背景的空图拒绝规则。

默认 768p、经确认的 2K 与按合同选择的音频属于生成计划和接收检查项，记录当前请求、2K 确认依据、实际显示尺寸与 `input.has_audio` 事实；不把缺省值当作报告字段扩展或文件门的新要求。结构通过不等于生成参数或人工验收通过。原视频与派生视频保留来源身份和空间布局；源中存在且任务要求保留的音轨随时间整理维护，图集交付不代表游戏音效已接入。

视频初始帧数由整理后的抽帧输入时长和目标 FPS 决定，不再要求 `3、5、9、17…`；输入时长应匹配已确认的游戏时间轴，而非生成器的固定交付时长。替换实际输入时先人工验收新视频再重抽；仅调整抽样 FPS 或输出尺寸可使用仍有有效验收的同一视频重抽并审阅，保留已修图成果。修改提示词或发现动作错误不默认重新生成视频。背景与外观修正优先直接处理抽帧图片，时间问题按[视频节奏整理](action-timing.md#视频节奏整理)处理。图片按目标槽位补齐，不能套用视频的严格源时间戳规则。

## 抽帧后的动作与图片修正

- 当前视频先经人工验收后抽帧；后续图像处理暴露的动作或外观问题可局部修正对应图片或图集 cell，原视频不作为阻止纠错的硬约束。保留验收与来源记录，不以预先打算抽帧后修图为由跳过视频验收；需要更换来源时沿用明确变更与授权边界。
- 动作修正包括姿态、动作轨迹、朝向、阶段时序/关键事件/终态与循环衔接；外观修正包括造型、颜色、背景残留、透明边缘、局部缺陷和锚点对齐。按修改范围检查相邻帧，保留可用帧，以最终游戏动作要求而非视频中的错误验收。
- 保留真实原视频及初始抽帧来源记录，来源身份不代表最终动作必须与视频相同。外观修正保持当前帧索引、帧数、FPS、cell 尺寸与锚点合同；节奏修正允许按来源顺序移除未计划保持帧或修正已有帧槽位的过渡姿态，并更新索引、时间映射、产物与合同；需新增帧或改变来源顺序时，保存新的真实抽帧来源，人工验收新视频后重新抽帧并迁移已有修图，不能只修改声明或伪造来源。抽样参数错误可使用仍有有效验收的同一视频重抽，但不能覆盖已完成的修图而不保留修正成果。
- 修改实际图片后重组最终图集，复算 `quality_report.artifacts.sheet.sha256`，更新预览内的 `phaser-atlas-sha256` 和资源合同中的图集、报告、预览文件 SHA；重新审阅逐帧显示、动作连续性、关键时刻和首尾衔接。原 `source_video.sha256`、报告的 `input.video_sha256` 与每帧 `source_sha256` 仍记录初始来源，不能伪装成修改后的图片 SHA。
- 在修正记录中列出实际修改帧索引、动作或外观问题、处理方法和修正前后文件身份。图片改动使旧图集验收失效，完成更新与复核后再提交 accepted；不能只改报告而不处理实际图片。

提示词交付或网页审阅只覆盖本次资源候选；外部系统写入、真机运行、发布和付费仍遵循全局控制面的独立授权。
