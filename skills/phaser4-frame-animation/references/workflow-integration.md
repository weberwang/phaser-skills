# 视频抽帧工作流接入合同

执行者按[执行代理](../SKILL.md#执行代理)固定为 `gpt-6.1-sol`、`max` 的子代理；主代理交接人工确认、实际视频和限定任务包，同一 Work Item 的连续制作与修正复用该代理。

帧动画先生成可播放的低保真灰盒，用户确认当前动作方案后才编写视频提示词并继续制作。正式资源以视频抽帧得到初始帧，不采用首末帧递归插帧路线；灰盒不是正式抽帧来源。视频只作为动作流程草图；抽帧后允许直接修正图片中的动作和外观，最终帧动画以游戏要求为准。全局视觉阶段仍是 V0→V5，灰盒与确认属于 V2 内部步骤，不改写全局 `visualStage`。

| 步骤 | 产物 | 停止条件 |
| --- | --- | --- |
| 动作与时间规划 | 完整动作组、游戏总时长、阶段区间、关键事件、播放方式与允许保持、循环、画布和 FPS | 完整行为不按阶段或事件数量拆视频；建议时序交付灰盒确认 |
| 灰盒预览 | 隔离的可播放 HTML、动作参数、当前候选文件身份 | 交付后等待用户明确确认；调整意见只推进灰盒修改 |
| 灰盒确认 | 当前候选版本、预览与参数 SHA、用户确认依据 | 无确认或文件变化时不进入视频提示词与正式制作 |
| 写视频提示词 | 可直接用于视频生成器的文本文件 | 交付提示词后等待真实视频文件 |
| 接收视频 | 原视频文件及内容检查 | 文件不存在或无法解码时不抽帧 |
| 视频节奏整理 | 有效动作区间、源到游戏时间映射、必要时生成独立派生视频 | 未计划停顿、重复周期或时间偏差未处理时不交付正式动画 |
| 抽帧与图集 | 固定 cell 的 PNG 图集、JSON 报告、HTML 预览 | 按 FPS、尺寸、是否去背景生成，参数变化要重做 |
| 审阅与接入 | 浏览器播放审阅、Phaser 合同 | 动作和外观问题均修对应图片并更新图集与证据；最终动画按游戏要求验收；运行态在全局 V5 验证 |

## 灰盒确认

按[完整动作与时间轴](action-timing.md)规划整组动画，确认必须覆盖分组、游戏总时长、阶段区间、关键事件、运动/保持意图与播放方式。多阶段行为展示整组连续播放；循环动画跨周期检查接缝，单次动画检查结束与终态，不用单段预览或首尾静态对齐代替节奏验收。

预览内容与操作要求见[动画灰盒预览](../SKILL.md#动画灰盒预览)。灰盒及其动作参数、候选版本、文件 SHA 和人工确认依据保存到当前 Work Item 的设计证据中，不放入正式 `asset.runtime_outputs`，也不冒充 accepted 图集。确认只对当前动画方案有效；动作时序、关键姿态、事件时机、循环、锚点或运动范围变化时旧确认失效，先更新灰盒并重新交付确认，再推进对应的提示词或图片修正。只有正式美术细化时可沿用有效动作确认。灰盒和抽帧预览均由用户人工进行视觉验收，不自动截图、不自动启动真机验收。

## 视频提示词

仅在当前灰盒候选得到用户确认后编写，动作描述须沿用确认的参数与关键事件。

提示词必须以当前游戏项目的视觉基线和玩法为依据，写出资源用途、游戏视角、角色或物件的既有造型、游戏内显示尺寸、动作状态、玩法生效时刻、循环或终态、固定镜头与语义根锚点。独立精灵不混入 UI、文字、额外角色或场景背景；场景动画则遵循场景图层合同。动作轮廓与关键事件须在目标显示尺寸和抽帧 FPS 下可读。提示词中要求呈现的主体、部件、道具、特效和完整运动范围都必须位于安全边距内，默认禁止任何裁剪；只有用户明确允许时，才能逐项指定可裁剪内容和范围。收到视频后记录动作、姿态、时机与裁剪缺陷，作为抽帧后修正对应图片的依据，不因视频动作有问题退回生成。还须写出时长、画幅、背景处理，以及不允许的闪烁、跳切、变形、漂移和遮挡。若计划移除背景，要求高对比纯色背景，避免主体、道具、半透明特效与背景色混同。提示词是生产输入，不能替代视频内容检查。

## accepted 资源文件门

文件门只证明产物身份和结构一致，不证明动作分组或节奏正确。提交 accepted 前须在 Work Item 设计证据中保留动作计划、当前灰盒确认、源到游戏时间映射及最终人工节奏审阅结果；核对整组时长误差不超过一个目标帧间隔、关键事件不缺失、阶段间无未计划重置、运动与保持符合计划、播放边界正确。

发生视频剪辑或重定时时，`source_video` 绑定实际用于抽帧的派生视频，`quality_report.input.video_sha256` 与之匹配；原始视频身份、剪辑命令/配置与时间映射另存设计证据，不新增未经工具支持的 manifest 字段。结构校验器不会自动执行上述人工节奏检查。

`asset.frame_animation` 绑定本次提示词、真实视频、抽帧报告、网页预览和 spritesheet 的项目内路径与 SHA。文件门复算 SHA，并核对报告中视频 SHA、抽帧 FPS、帧数、cell 尺寸、去背景配置、图集尺寸与 Phaser 帧范围。图集必须位于 `asset.runtime_outputs`，`spritesheet.runtime_url` 必须与报告的 `phaser.preload.url` 相同。

合同使用 `phaser4-video-atlas-workflow/1`，必需字段示例：

```json
{
  "schema": "phaser4-video-atlas-workflow/1",
  "status": "accepted",
  "work_item_id": "work-item-hero-attack",
  "candidate_version": "candidate-hero-attack-v1",
  "settings": { "fps": 12, "width": 128, "height": 128, "remove_background": true },
  "video_prompt": { "file": "evidence/hero-attack.prompt.txt", "sha256": "sha256:<64位十六进制>" },
  "source_video": { "file": "art/hero/attack.mp4", "sha256": "sha256:<64位十六进制>" },
  "quality_report": { "file": "evidence/hero-attack.video-atlas.json", "sha256": "sha256:<64位十六进制>" },
  "preview": { "file": "evidence/hero-attack.preview.html", "sha256": "sha256:<64位十六进制>" },
  "spritesheet": { "file": "public/assets/hero-attack.png", "runtime_url": "assets/hero-attack.png", "sha256": "sha256:<64位十六进制>" }
}
```

`settings` 与报告中的抽帧参数和最终 cell 尺寸逐项匹配。以上 SHA 占位符须替换为真实文件摘要，不能原样写入资源清单。

初始帧数由整理后的抽帧输入时长和目标 FPS 决定，不再要求 `3、5、9、17…`；输入时长应匹配已确认的游戏时间轴，而非生成器的固定交付时长。替换抽帧输入或调整抽样 FPS、输出尺寸时重新抽帧并审阅，保留已修图成果；修改提示词或发现动作错误不默认重新生成视频。背景与外观修正优先直接处理抽帧图片，时间问题按[视频节奏整理](action-timing.md#视频节奏整理)处理。

## 抽帧后的动作与图片修正

- 视频只提供动作流程草图的期望，不作为最终正确动作的硬约束。抽帧后不论动作还是外观有问题，都直接修正对应图片或图集 cell；只有用户要求更换草图来源时才替换视频。
- 动作修正包括姿态、动作轨迹、朝向、阶段时序/关键事件/终态与循环衔接；外观修正包括造型、颜色、背景残留、透明边缘、局部缺陷和锚点对齐。按修改范围检查相邻帧，保留可用帧，以最终游戏动作要求而非视频中的错误验收。
- 保留真实原视频及初始抽帧来源记录，来源身份不代表最终动作必须与视频相同。外观修正保持当前帧索引、帧数、FPS、cell 尺寸与锚点合同；节奏修正允许按来源顺序移除未计划保持帧或修正已有帧槽位的过渡姿态，并更新索引、时间映射、产物与合同；需新增帧或改变来源顺序时，生成新的真实抽帧来源，重新抽帧并迁移已有修图，不能只修改声明或伪造来源。抽样参数错误可使用同一视频重抽，但不能覆盖已完成的修图而不保留修正成果。
- 修改实际图片后重组最终图集，复算 `quality_report.artifacts.sheet.sha256`，更新预览内的 `phaser-atlas-sha256` 和资源合同中的图集、报告、预览文件 SHA；重新审阅逐帧显示、动作连续性、关键时刻和首尾衔接。原 `source_video.sha256`、报告的 `input.video_sha256` 与每帧 `source_sha256` 仍记录初始来源，不能伪装成修改后的图片 SHA。
- 在修正记录中列出实际修改帧索引、动作或外观问题、处理方法和修正前后文件身份。图片改动使旧图集验收失效，完成更新与复核后再提交 accepted；不能只改报告而不处理实际图片。

提示词交付或网页审阅只覆盖本次资源候选；外部系统写入、真机运行、发布和付费仍遵循全局控制面的独立授权。
