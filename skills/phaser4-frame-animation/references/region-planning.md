# 通用动画分组与区域规划

需要合批、效果图尺寸推理或空间裁剪时读取本文件。先按 [SKILL.md 分类入口](../SKILL.md#分类入口)选择用途规则；动画单元、视频批次与区域分别记录，制作批次不改变运行时行为边界。

## 分组规则

- **动画单元**按现有触发、生命周期和完整行为定义，有自己的时间轴、播放方式、FPS、输出尺寸与事件。运行时 key 按玩法/状态合同另列，不由用途类型或单元数直接推导；同一次行为的连续阶段完整制作。
- **视频批次**按可共享的美术风格、视角、背景处理和生成时长组织。可把多个单元放进同一条视频不同区域，同时呈现各自动画；不同用途类型也可合批，但每个区域独立选择类型规则、有效源区间和游戏时间映射。
- 区域数与尺寸取决于效果图和完整运动范围，不预设均分网格或固定每批数量。容纳不下、背景冲突或互相干扰时拆批，并记录理由；不压缩必要像素来凑动画数量。
- 当前 Work Item 的分组不扩大其他工作项的修改范围。每个区域独立验收与输出，可以共享批次提示词和源视频。

## 从效果图推断尺寸

1. 读取当前有效效果图与布局合同，记录参考文件及身份、主体在游戏中的显示宽高和视角；效果图像素应换算到游戏设计尺寸，不能把整张效果图尺寸作为单个动画尺寸。
2. 推断完整运动包络：主体尺寸、位移、部件展开、道具扫掠、发光或粒子范围及可见阴影，围绕语义根锚点保留安全边距。输出 cell 应能容纳整个动画的包络；细长特效、展开机关等可以使用非正方形画布。
3. 根据目标显示质量确定源区域与输出 cell 的比例。区域可以大于最终输出尺寸；宽高比例须服务于运动包络，不能为了均分视频而拉伸主体。各动画尺寸可不同，但同一动画所有帧共享固定 cell 和锚点。
4. 默认按 768p 计划画布布置不重叠区域，留出间隔和画面外边距。逐区域记录用途类型、`x、y、width、height`、输出宽高、局部锚点、允许位移、推理依据和运动安全边距；使用左上角原点的整数像素。若目标细节或区域像素预算确实需要 2K，按下方约定询问，不自行升级。
5. 灰盒展示区域布局与各自完整时间轴，人工确认尺寸可读性、完整入镜和跨区干扰。参考不足时明确哪些尺寸是推断值，通过灰盒确认，不虚构已测量事实。

## 视频参数与空间依据

视频分辨率默认 **768p**。当目标显示细节、完整运动范围或多区域像素预算需要 **2K** 时，先说明具体依据、拟用画幅/宽高及对批次的影响，并询问用户；取得当前任务明确确认后再采用 2K，已有有效确认时沿用记录。未确认前不能把 2K 写成正式采用的参数，可继续不依赖升级的规划。768p 与 2K 都不代表所有画幅具有相同宽高，不能用提升输出 cell 尺寸冒充更高源分辨率。

生成计划记录分辨率、画幅、预期宽高及按任务选择的音频。区域最终以实际视频自动旋转后的显示画布为准；接收时核对实际宽高和音轨，计划与实际不同则重新换算区域，并人工核对边界后抽帧。原点或旋转变化不能只缩放输出 cell 修正。

各区域同时独立呈现，镜头和区域位置固定。默认保持要求呈现的内容与完整运动范围入框；裁剪例外须沿用当前任务的明确授权，逐项记录，不因合批或类型自动放宽。提示词不绘制边框、编号或分隔标签。背景处理按各自类型和边缘选择，不能为了合批把发光/半透明边缘统一按硬边去背。工具的 `input.has_audio` 是实际探测事实，音频与角色素材中的声音/特效/镜头反馈按任务合同选择；图集交付不等于游戏音效已接入。

批次视频时长与每个动画的游戏时长分别记录。较短动画可按计划循环或到达终态，但抽帧只保留对应时间轴需要的区间；不把其他区域尚在运动的时间追加为该动画的无意停顿。时间剪辑和重定时见[视频节奏整理](action-timing.md#视频节奏整理)，派生视频须保留整幅空间尺寸、位置与朝向。

区域计划参数示例（假设显示画布为 1366×768；这些区域、尺寸和锚点仅演示记录方式）：

| 动画与用途类型 | 视频区域 `x,y,width,height` | 输出 cell | 区域内锚点 `x,y` | 尺寸依据 |
| --- | --- | --- | --- | --- |
| 机关展开／普通动画 | `16,16,320,288` | `160×144` | `160,264` | 展开范围与底部安装点 |
| 命中特效／特效动画 | `352,16,640,400` | `320×200` | `320,200` | 横向扩散与光效安全边距 |
| 提示脉冲／UI 帧动画 | `16,320,288,224` | `144×112` | `144,112` | UI 显示尺寸与缩放包络 |

效果图身份、各区域用途类型、有效源区间、游戏时间映射、时长/FPS/事件/锚点及输出路径保存在 Work Item 设计工件；区域表是生产规划，不新增报告或 accepted schema 字段。下方命令假设两个区域已整理为相同有效时间段；不同时间段须各自准备整幅派生来源。

## 按区域抽帧

先检查 `ffmpeg`、`ffprobe` 和项目依赖可用；空间裁剪由本地工具处理，输入视频必须已经满足该动画的游戏时间轴。不同区域共用同一输入时，应先确认各自有效区间相同，否则分别准备保留整幅布局的时间整理视频。

以下示例用于已确认主体与背景颜色分离、四周纯色的硬边素材：

```powershell
node <skill-dir>/scripts/video-to-atlas.mjs `
  --input-video art/animation-batch.mp4 `
  --region 16,16,320,288 `
  --anchor 160,264 `
  --output-sheet public/assets/mechanism-open.png `
  --width 160 --height 144 --fps 12 --no-loop `
  --animation-key mechanism-open --texture-key mechanism-open `
  --runtime-url assets/mechanism-open.png `
  --remove-background --background-color '#00ff00' `
  --edge-profile hard-edge --color-separation-verified

node <skill-dir>/scripts/video-to-atlas.mjs `
  --input-video art/animation-batch.mp4 `
  --region 352,16,640,400 `
  --anchor 320,200 `
  --output-sheet public/assets/impact-burst.png `
  --width 320 --height 200 --fps 12 --no-loop `
  --animation-key impact-burst --texture-key impact-burst `
  --runtime-url assets/impact-burst.png `
  --remove-background --background-color '#00ff00' `
  --edge-profile hard-edge --color-separation-verified
```

工具按固定区域裁剪后才去背景和缩放。纯色去背景须显式声明硬边与颜色分离已确认，复杂/未知边缘需使用真实 Alpha、遮罩或帧图片修复；不要自动加上确认标记。省略输出宽高时使用区域原尺寸；单边输出尺寸等比推导另一边；双边输出尺寸等比缩放并透明留白到指定 cell。每次调用交付独立 PNG、JSON 和 HTML，默认报告与预览和图集同名。

当前 `--fps` 同时控制抽样和播放，示例数值不代表类型默认节奏；游戏时间先按 [action-timing.md](action-timing.md)整理。`--no-loop` 用于计划中的单次播放；结束保持、组合和事件按现有运行时合同记录，不能只改报告来伪造工具能力。未指定 `--region` 时处理整幅画布。`--output-report`、`--output-preview` 可指定证据路径，`--runtime-url` 使用实际部署 URL，并与资源清单 `spritesheet.runtime_url` 一致。

每个动画的 `frame_animation.settings.region`、报告的 `input.region` 与 `settings.region` 必须一致。人工检查区域内是否完整、是否混入邻区内容、运动与锚点是否稳定、透明边缘、阶段事件与循环/终态；文件门通过仅代表结构和身份一致。

显式局部锚点使用 `--anchor x,y`，清单 `settings.anchor` 与报告 `input.anchor/settings.anchor` 一致。局部坐标从该区域左上角起算，允许半像素；输出 origin 使用工具按实际缩放与居中留白变换的结果，不能直接套用输出底边。特效消失或 UI 隐藏的空透明帧按计划保留，整段全空才拒绝交付。
