# Phaser 4 通用帧动画制作

使用统一生产流程，按当前动画的用途选择制作、优化和人工验收规则。正式资源以真实视频抽帧得到初始帧，视频作为动作草图，最终动画以游戏要求和视觉基线为准。当前 Work Item 的资源交付回到既有控制面，不另建动画状态机。

在当前 Work Item 范围内提出动画资源方案、审查灰盒/视频/抽帧预览、修复并重验；交付后回到控制面提交证据与状态迁移。

## 分类入口

每个动画先确定用途类型，只读取对应分类参考；多类型批次逐区域选择规则，不默认加载四份文档。

| 用途类型 | 选择依据 | 读取参考 |
| --- | --- | --- |
| 普通动画 | 物件、环境、装饰、机械运动与状态变化 | [普通动画](references/object-animation.md) |
| 角色动作动画 | 待机、移动、攻击、受击、跳跃等身体行为 | [角色动作动画](references/character-animation.md) |
| 特效动画 | 命中、爆炸、烟尘、光效、状态效果等视觉反馈 | [特效动画](references/effect-animation.md) |
| UI 帧动画 | 按钮反馈、提示、图标等需要逐帧位图资源的界面动效 | [UI 帧动画](references/ui-frame-animation.md) |

用途类型不决定行为单元、视频数量或运行时动画 key 数量。循环、单次、组合、终态保持是各类型共用的播放参数，可按任务组合使用。角色动作可进一步按循环运动、主动行为、被动反应和连续组合选择规则，不为每个动作新增技能。简单程序 UI 动效按既有 UI/程序路线处理。

## 共用流程

1. 读取视觉基线、用途类型参考与[完整动作与时间轴](references/action-timing.md)，建立当前动画的设计工件。先明确行为边界、初态/终态、游戏时长、阶段区间、关键姿态、事件、播放方式、锚点/允许位移、完整运动范围、目标显示尺寸、FPS 和背景处理。按实际需要读取[区域规划](references/region-planning.md)，组织视频批次；共用来源时各区域仍有独立类型、有效区间与游戏时间映射。
2. 交付可播放的完整灰盒与人工检查要点，确认类型规则、节奏、事件、播放边界和区域尺寸。**等待用户确认当前灰盒候选**；调整意见只推进灰盒修订。
3. 当前灰盒确认后，按“共用视觉与资源约束＋类型规则＋当前动画参数”编写正式提示词，按批次保存工件并交付。视频默认 **768p**；需要 **2K** 时先说明依据并询问用户，取得当前任务的明确确认后再采用。画幅、音频和时长按任务记录。**交付后等待实际视频文件**。
4. 接收并检查真实视频，记录实际画布、区域与音轨事实。按[视频节奏整理](references/action-timing.md#视频节奏整理)选择有效区间、按阶段重定时并保存派生来源，让各动画符合已确认的游戏时间轴。批次视频时长不能替代各区域的游戏时长。
5. 使用现有工具按固定区域抽帧、处理背景、等比缩放，交付独立图集、报告与 HTML 预览。依据当前类型的人工反馈局部修帧，保留已有修图成果；记录真实来源与修正身份，更新图集、报告、预览及 SHA。缺陷修复不默认重新生成视频。
6. 保存分类规则、时间映射、灰盒确认与最终人工验收证据，按[工作流接入合同](references/workflow-integration.md)提交资源，再回到控制面完成 Phaser 接入和运行验证。

## 动画灰盒预览

灰盒必须能播放完整动画，提供播放/暂停、重播和逐帧查看，并标出阶段、事件、锚点与区域边界。它是动作设计工件，不能作为真实视频、正式抽帧来源或 accepted 图集。详细预览与候选确认要求见[灰盒确认](references/workflow-integration.md#灰盒确认)。

## 共用质量与关键约束

- 以可读性、节奏、主次关系、连续性和事件同步验收；具体判断及优化方法见[共用质量与优化](references/action-timing.md#共用质量与优化)。重量感、夸张程度、停顿和跟随运动按类型、对象性质与视觉基线配置，不统一套用战斗节奏。
- 游戏时间独立于源视频时长。完整行为共享时间轴，内部可标事件和输入衔接；制作分组不增加攻击次数、自动连击或伤害，也不改变现有输入机制。
- 时长、阶段比例、命中停顿、连击次数与音频均由当前任务确定；具体动作和参数案例不能成为全局默认要求。视频默认 768p，需要 2K 时按[分辨率约定](references/region-planning.md#视频参数与空间依据)说明依据并询问，已有当前任务明确确认时沿用记录。
- 默认保持要求呈现的内容及完整运动范围入框，保留安全边距。裁剪例外须有当前任务的明确授权，逐项记录对象、范围与理由；不能为合批或强调力度自行裁边。
- 稳定锚点不等于禁止运动。允许位移、姿态夸张或形变须在设计工件中说明范围和意图，按计划验收；禁止未计划的漂移、闪烁、比例变化与跨区串入。
- 背景处理按素材边缘与类型选择。颜色去背景只用于已确认的纯色硬边；半透明、发光或未知边缘使用真实 Alpha、遮罩或帧图片修正，不冒充硬边确认。特效、声音和镜头反馈是否烘入按任务合同决定。
- 分类与优化参数保存在设计工件，不扩展报告、manifest 或 accepted 合同 schema，不虚构脚本参数。原视频、派生来源、时间映射与 SHA、修图前后身份按接入合同保留。
- 灰盒和最终视觉显示由人工验收；文件门只验证结构与身份。不得自动截图或启动真机验收，外部写入、付费、发布沿用独立授权边界。

## 执行代理

帧动画 Work Item 的规划、灰盒、提示词、节奏整理、抽帧和修正仍统一委派给 `gpt-6.1-sol`、`max` 的执行子代理。主代理负责需求、任务包、人工反馈、接入范围、审查与最终验证，不接管动画制作。

使用 `collaboration.spawn_agent`，设置 `agent_type="default"`、`model="gpt-6.1-sol"`、`reasoning_effort="max"`、`fork_turns="none"`。完整任务包包含 Work Item、用途类型与对应参考、行为/输入边界、素材与基线路径、允许修改范围、当前候选/时间轴/SHA、确认依据、允许推进步骤、验收标准、测试等级与命令、禁止操作及并行提醒。首次只推进灰盒交付；确认后通过 `followup_task` 复用代理写提示词；收到视频后交接真实文件继续制作。

同一工作项的连续修正优先复用代理；范围实质变化或工作项完成后结束该生命周期。位图生成/编辑仍交给图片生成代理，动画执行代理提供时间轴、帧槽位和素材约束并集成结果。指定工具或模型不可用时报告限制，不静默换模型。委派不扩大文件、视觉自动验证或外部操作授权。

## 抽帧工具与参考路由

抽帧前检查 `ffmpeg`、`ffprobe` 与项目 `sharp` 依赖可用，读取[按区域抽帧](references/region-planning.md#按区域抽帧)了解当前参数、等比缩放、背景处理与锚点。先查看实际工具帮助：

```powershell
node <skill-dir>/scripts/video-to-atlas.mjs --help
```

当前工具每次处理一个区域（省略区域则为整画布），覆盖完整输入时间段；`--fps` 同时控制抽样与播放，没有时间剪辑或独立逐帧时长参数。时间问题先按共用时间轴整理来源，不只改报告中的帧率。

| 当前阶段 | 按需读取 |
| --- | --- |
| 用途判断与类型制作 | 上方对应的一份分类参考；涉及独立特效或 UI 位图时再读取其规则 |
| 游戏时间、分组、阶段及修正 | [action-timing.md](references/action-timing.md) |
| 效果图尺寸推理、合批与空间裁剪 | [region-planning.md](references/region-planning.md) |
| 灰盒确认、提示词组合、来源/修图证据与资源提交 | [workflow-integration.md](references/workflow-integration.md) |

全局阶段仍由[唯一控制面](../phaser4-game-workflow-control/SKILL.md)管理：V2 规划与灰盒确认，V3 接收视频、制作与人工审阅，V5 依据报告的 preload、anims 和 origin 接入 Phaser 并验证运行态。
