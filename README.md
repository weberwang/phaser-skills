# Phaser 4 游戏协作 Skills

面向 Phaser 4、TypeScript、Vite 与 Capacitor 的移动端 2D 游戏虚拟团队工作流。覆盖从立项、垂直切片、正式制作、测试性能到小游戏、iOS、Google Play 提审准备的完整周期。

## 安装到项目

需要 Node.js 22.20 或更高版本，以满足 skills CLI 的运行要求。

在目标游戏项目的根目录执行以下命令。CLI 会识别 Codex 并在安装前显示目标位置；存在同名 skill 时，按交互提示确认覆盖。

~~~powershell
npx -y github:weberwang/phaser-skills
~~~

安装前可列出远端内容而不写入文件：

~~~powershell
npx -y skills@1.5.19 add weberwang/phaser-skills -l --full-depth
~~~

请在执行前审阅远端 skill 内容。安装后的 agent 具有项目文件访问与执行权限。

## 从本仓库安装

克隆本仓库后，可用脚本安装到指定项目。省略路径时，脚本将当前工作目录视为目标项目。

~~~powershell
node .\scripts\install-project-skills.mjs E:\Projects\my-phaser-game
~~~

脚本固定使用已验证的 skills@1.5.19，并通过 --copy 将内容复制到目标项目，避免安装结果依赖本仓库路径。

## 工作流

以 $phaser4-game-orchestrator 作为入口。它会协调以下角色：

- $grilling：仅在证据无法消除且确需人工取舍时介入；低风险相关项可合并确认，高影响或冲突项逐项拷问。
- $phaser4-game-production：制作策划、范围、参考功能契约、验收与变更控制。
- $phaser4-game-architecture：Phaser 4、Vite、Capacitor 与渠道适配边界。
- $phaser4-gameplay-development：玩法、场景、交互、游戏状态和参考功能还原。
- $phaser4-game-balance：数值、难度、经济与验证。
- $phaser4-game-asset-integration：建立全局视觉基线，按参考功能契约从代码低保真、防黑边背景、高保真效果图和框选单图推进到正式结构化 Phaser 场景。
- $phaser4-game-audio：音频体验、授权、格式与接入。
- $phaser4-game-qa-performance：功能、设备、性能与发布候选验证。
- $phaser4-game-release：小游戏、iOS、Google Play 的构建、提审与合规。

另提供一个不受总控调度的手动任务：

- $phaser4-game-image-optimization：手动盘点、压缩并验证运行时图片资源；只接受显式调用，不参与常规质量门调度。

总控按任务影响选择工作通道：

- 快速通道：局部、低风险、可回退的已批准任务，明确验收后直接实现和验证；不维护流程文档，只有人工明确要求时才使用 worktree。
- 标准通道：新模块、跨模块或影响架构、存档、数值、资源、性能的任务，只调度受影响角色。
- 发布通道：影响渠道、隐私、商业能力、资源权属或候选包的任务，使用 G0 至 G3 完整质量门。

图片资源优化是独立的手动附加任务。只有用户显式调用 `$phaser4-game-image-optimization` 时才执行；总控、A1 至 A6、G0 至 G3、构建、测试和发布流程均不得自动触发，也不得把它加入构建脚本、Git 钩子或 CI。任务会先建立体积基线，在独立目录生成压缩候选，完成画质、Phaser 加载、测试与生产构建验证后才替换原文件，并报告逐文件及总体积收益。

任务影响扩大时再升级通道。快速通道至少执行 F0 入口与 F1 证据筛选；标准、发布通道的每个候选增量依次通过“F0 入口 → F1 证据 → F2 专业 → F3 综合 → 按需 F4 人工”漏斗。上游先淘汰缺项、失败证据和专业问题，下游只审差异、跨域风险与必须人工取舍的事项。范围、风险接受度、发布指标和发布放行仍由人工决策；技术缺陷、缺证和未完成项不得转交人工。

Worktree 不是默认能力。只有人工明确要求且存在多个并发写入者时，每个写入者才使用独立 worktree；其他情况直接使用当前工作区。

游戏实现不是可省略的角色调用，而是贯穿 G1/G2 的闭环。参考截图、录屏、运行项目或源代码还原任务必须先冻结逐状态功能契约和视觉基线，再按“功能与结构低保真 → 高保真效果图 → 效果图专业审阅 → 全量单图框选 → 单图生成与验收 → 功能与结构化装配”执行。每个 A 阶段走审核漏斗，但不再默认等同于一次人工审批：新的行为/信息结构、视觉方向、不可逆批量生产成本、预算/授权风险和明确要求的人工终验才进入 F4。功能通过不能替代视觉通过，视觉接近也不能替代功能复现。

进入 G1 的 A1 前，先检查并按缺失项初始化 `assets,qa` 交付物。A1 至 A5 的视觉资源和登记由美术接入负责，A6 的正式场景/预制体代码装配及低保真实现清理由玩法开发独占执行。`docs/control-plane.md` 由总控串行写入，其他角色只提交状态包。

无交互满幅背景在高保真阶段优先生成并通过适用漏斗层，再通过统一适配器应用到每个可见场景。竖屏背景按高度等比缩放并水平裁切/延展，横屏背景按宽度等比缩放并垂直裁切/延展；背景不得承载交互或玩法信息，目标最窄/最宽视口、方向/尺寸变化及场景过渡均不得出现黑边、透明缝或闪烁。

UI 在 A1 冻结精准布局契约：每个组件声明父级坐标系、参照物、参照与自身停靠点、水平/垂直距离、尺寸策略、横向或纵向排列、安全区、方向/断点和误差阈值。正式实现通过统一布局入口计算并在视口、方向、安全区、状态或内容变化后重排；不得以无参照语义的孤立屏幕坐标逐屏手调。A6 在基准、最窄、最宽视口和代表性安全区输出逐组件期望/实测边界、中心与间距，超过阈值或出现累计漂移即不通过。

新建模块、模块首次实现或改变职责、公开契约、状态所有权、依赖方向时，先形成候选模块图并完成 F0 至 F3，再由总控强制执行 $grilling 完成 F4。只有人工批准并在 TDD 标为“已批准待实现”的模块才能搭建正式骨架或编写生产代码；要求修改时从最早受影响层重新筛选，已批准模块内部不改变边界的低风险实现无需重复确认。

启动本地开发、预览或测试服务前，先按项目根目录、服务类型、模式、端口、监听进程和健康状态查重。已有健康实例时直接复用；页面暂未就绪、验证工具切换或单次请求失败时先诊断原服务，不得重复启动。端口冲突时不得擅自停止其他任务或用户进程。

## 项目交接物

总控 skill 的初始化脚本默认生成项目配置、GDD、全局视觉设计、TDD 和控制面；全局视觉设计在 G0 冻结方向，在 G1 随垂直切片补齐可执行规则：

~~~powershell
python .\.agents\skills\phaser4-game-orchestrator\scripts\initialize_project_docs.py --project-root .
~~~

进入对应阶段后，再按需创建数值、资源、测试、渠道或发布交付物：

~~~powershell
python .\.agents\skills\phaser4-game-orchestrator\scripts\initialize_project_docs.py --project-root . --include balance,assets,qa
~~~

脚本默认拒绝覆盖本次选择的已有交接物；只有人工明确要求时才使用 --force。

## Worktree 工作区隔离

Worktree 不属于质量门、角色交接或阶段交付物，也不维护额外的收敛计划；未获人工明确授权时禁止使用。

- 已明确授权的多个并发写入者：每个写入者独占一个 worktree 和分支，并明确文件或模块归属。
- 完成任务：按普通 Git 流程检查、提交和集成；不自动合并、删除 worktree 或删除分支。

## 更新

在目标项目根目录执行：

~~~powershell
npx --yes skills@1.5.19 update --project --yes
~~~

更新后重新检查项目中的 .agents/skills/ 内容和 docs/ 交接物，再继续任何受影响的工作。
